## 핵심 내용
이 문서는 복잡한 클래스 계층 구조에 대한 내용을 다룹니다. 클래스 상속, 다형성, 그리고 객체 지향 프로그래밍의 설계 원칙에 대한 이해를 돕습니다. 복잡한 계층 구조를 효과적으로 설계하고 관리하는 방법을 제시합니다.

## 상세 핵심 내용
이 문서는 복잡한 클래스 계층 구조를 설계하고 관리하는 데 필요한 개념들을 설명합니다. 클래스 상속을 통한 코드 재사용과 확장성을 높이는 방법을 제시하며, 다형성을 활용하여 유연하고 유지보수가 용이한 코드를 작성하는 방법을 다룹니다. 객체 지향 프로그래밍의 SOLID 원칙과 같은 설계 원칙을 적용하여 견고하고 확장 가능한 시스템을 구축하는 방법을 안내합니다. 특히, 복잡한 계층 구조에서 발생할 수 있는 문제점과 이를 해결하기 위한 디자인 패턴의 활용법을 설명합니다. 또한, 클래스 계층 구조를 설계할 때 고려해야 할 사항들과 효율적인 관리 방법을 제시합니다.

## 상세 정보
### 클래스 상속과 다형성
*   클래스 상속을 통해 코드 재사용 및 기능 확장 가능
*   다형성을 활용하여 유연하고 유지보수가 용이한 코드 구현
*   상속 관계에서의 접근 제어 (public, protected, private)
*   다형성의 구현: 오버라이딩, 인터페이스

### 객체 지향 설계 원칙
*   SOLID 원칙 준수
    *   단일 책임 원칙 (Single Responsibility Principle)
    *   개방-폐쇄 원칙 (Open-Closed Principle)
    *   리스코프 치환 원칙 (Liskov Substitution Principle)
    *   인터페이스 분리 원칙 (Interface Segregation Principle)
    *   의존성 역전 원칙 (Dependency Inversion Principle)
*   객체 지향 설계 원칙을 통한 시스템의 유연성 및 유지보수성 확보

### 복잡한 클래스 계층 구조 관리

*   클래스 간의 의존성 관리
*   디자인 패턴 활용 (예: 팩토리, 추상 팩토리)
*   코드 중복 제거 및 재사용성 향상

### 디자인 패턴

### 1.2.4_Complex_class_hierarchies

1.2.4
Complex class hierarchies
One way to avoid writing the same code twice in OOP involves class inheritance. Indeed,
when every requirement of the system is known up front, you design your class hier-
archy is such a way that classes with common behavior derive from a base class.
 Figure 1.15 shows an example of this pattern that focuses on the part of our class
diagram that deals with members and librarians. Both Librarians and Members need
the ability to log in, and they inherit this ability from the User class.
So far, so good, but when new requirements are introduced after the system is imple-
mented, it's a completely different story. Fast forward to Monday, March 29th, at 11:00 AM,
where two days are left before the deadline (Wednesday at midnight).
