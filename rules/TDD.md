# 테스트 파일 작성
-  mock 데이터나 객체 말고 모두 실제 데이터와 구현된 모듈 사용을 원칙으로 함
    - 필요한 실제 데이터가 없을 경우 개발자에게 필요한 실제 데이터를 요청
    - 실제 데이터 사용 위해 처리 단계가 필요할 경우, 그 처리 단계부터 테스트를 진행
- 테스트 코드 작성 시 테스트 클래스 위에 주석으로 구현 파일명(구현 결과가 담길 파일명), 테스트 유형(solitary unit, social unit, integration) 표시
- 테스트 클래스 독스트링로 요구사항 명시하고 테스트 메서드의 요구사항과 입출력도 명확히 표현해줘
- 테스트 파일 저장은 현재 프로젝트의 tests 폴더 구조 로직에 맞게 저장.
    - solitary unit test는 의존성이 존재하지 않는 테스트
    - social unit test는 시스템 내부 요소에 대한 의존성이 존재하는 테스트
    - integration test는 외부 의존성이 존재하는 테스트
