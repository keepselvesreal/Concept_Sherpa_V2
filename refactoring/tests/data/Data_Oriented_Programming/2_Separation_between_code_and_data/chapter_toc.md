## Core 내용
DOP(Data-Oriented Programming)는 코드와 데이터를 명확하게 분리하여 시스템의 복잡성을 줄이고 유연성을 높이는 프로그래밍 패러다임입니다.

## 상세 핵심 내용
이 문서는 '27 lev1 2 Separation between code and data'라는 제목으로, 코드와 데이터 분리를 핵심으로 하는 DOP 시스템에 대해 다룹니다. DOP는 객체 지향 프로그래밍(OOP)의 데이터 캡슐화 방식을 지양하고, 데이터는 멤버만 갖는 데이터 엔티티로 표현하며, 코드는 상태가 없는(stateless) 함수로 모듈화하여 시스템의 이해도를 높이고 변화에 유연하게 대처할 수 있도록 합니다. 본 문서에서는 DOP 시스템의 구성 요소 (데이터 엔티티, 코드 모듈)와 각 요소의 특징, 그리고 DOP 시스템이 OOP 시스템에 비해 가지는 장점 (이해 용이성, 유연성)을 설명합니다. 또한, 실제 라이브러리 관리 시스템을 예시로 들어 DOP의 개념을 구체적으로 설명하며, 요구 사항 변경에 대한 DOP 시스템의 적응성을 보여줍니다.

## 상세 정보 내용
본 문서는 DOP 시스템의 핵심 원리를 설명하고, 시스템 설계 및 구현 시 고려해야 할 사항들을 제시합니다. 구체적으로, 데이터 엔티티 식별 및 그룹화 방법, 코드 모듈의 특징 (상태 없음, 데이터 인자), OOP와의 차이점, DOP 시스템의 유연성을 높이는 방법 등을 다룹니다. 또한, 라이브러리 관리 시스템 예시를 통해 실제 적용 사례를 제시하고, 시스템 이해도를 높이기 위한 모듈 다이어그램의 간결함과 유연한 코드 확장에 대해 설명합니다.

## 주요 화제

*   DOP 시스템의 설계 및 구현 (데이터 엔티티 식별/그룹화, 코드 모듈 설계)

## Core 내용
DOP 시스템의 두 가지 핵심 구성 요소: 데이터 엔티티와 코드 모듈. 코드와 데이터의 명확한 분리를 통해 시스템의 복잡성을 줄이고 유연성을 확보하는 것이 DOP의 핵심 원리입니다.

## 상세 핵심 내용
DOP는 코드와 데이터를 분리하여 시스템의 복잡성을 줄이는 프로그래밍 패러다임입니다. 데이터는 데이터 엔티티로 표현되며, 코드는 상태를 갖지 않는 함수(코드 모듈)로 모듈화됩니다. 이는 OOP에서 데이터 캡슐화를 지양하고 시스템의 이해도와 유연성을 높이는 것을 목표로 합니다. 본 노드는 DOP 시스템의 구성 요소와 핵심 원리를 간략하게 소개합니다.

## 상세 정보 내용
DOP 시스템은 코드와 데이터 분리 원칙을 따르며, 데이터 엔티티 식별, 코드 모듈 설계, OOP와의 차이점, 그리고 DOP 시스템의 장점을 포함합니다. 또한, DOP의 언어 독립성과 적용 가능성을 언급하고, 이어서 다른 노드에서 다룰 내용에 대한 간략한 소개를 제공합니다.

## 주요 화제
*   데이터 지향 프로그래밍 (DOP)의 개념
*   DOP의 핵심 원칙 (코드와 데이터 분리)
*   DOP의 장점 (시스템 복잡성 감소, 유연성 증가)
*   DOP의 적용 가능성 (언어 독립성)

## 부차 화제
*   Library Management System의 문제점 (복잡성, 유연성 부족)
*   객체 지향 프로그래밍의 단점 (데이터 캡슐화)
*   함수형 프로그래밍과의 연관성
*   프로그래밍 언어의 선택

데이터 엔티티는 시스템 내의 정보 표현을 담당하며, DOP 시스템 설계의 초기 단계에서 중요한 역할을 합니다. 구체적으로, 요구사항에서 데이터 엔티티를 식별하고, 관련 엔티티들을 그룹화하여 시스템 구조를 파악합니다. 이는 라이브러리 관리 시스템 예시를 통해 구체화되며, 데이터 엔티티 다이어그램을 통해 시각적으로 표현될 수 있습니다.

## 상세 정보 내용
본 노드는 데이터 엔티티 식별 방법(명사/명사구), 그룹화 방법(중첩 목록, 마인드 맵), 데이터 엔티티 다이어그램 활용법 등 데이터 엔티티 설계와 관련된 실질적인 정보를 제공합니다. OOP의 캡슐화와 대조되는 데이터 표현 방식, 데이터 엔티티 간 관계 설정 등에 대한 추가적인 정보도 포함합니다.

## 주요 화제
*   데이터 엔티티의 정의와 중요성
*   데이터 엔티티를 식별하는 방법
*   데이터 엔티티를 그룹화하는 방법

## 30_lev2_2.3_Code_modules_info.md

## Core 내용
DOP에서 코드 모듈은 상태를 갖지 않는 함수들의 집합으로, 데이터 엔티티를 인자로 받아 처리합니다. 이는 데이터와 코드의 명확한 분리를 통해 시스템의 유연성을 높이는 핵심적인 요소입니다.

## 상세 핵심 내용
코드 모듈은 DOP에서 데이터 처리 로직을 담당하며, OOP의 클래스와 유사하지만 상태를 갖지 않는다는 중요한 차이점을 가집니다. 모듈 내의 함수들은 데이터를 명시적인 인자로 받아서 처리하며, 이는 데이터의 변경이 모듈에 미치는 영향을 최소화합니다. 이러한 설계는 DOP 시스템의 유연성을 높이는 데 기여합니다. 라이브러리 관리 시스템 예시를 통해 코드 모듈의 설계 및 동작 방식을 설명합니다.

## 상세 정보 내용
본 노드는 코드 모듈의 정의, 특징(상태 없음, 명시적 데이터 인자), OOP와의 차이점, 고수준 모듈과 데이터 엔티티의 관계 등 코드 모듈 설계와 관련된 상세 정보를 제공합니다. 함수형 프로그래밍과의 연관성, 모듈 구조(클래스, 패키지, 네임스페이스)에 대한 추가적인 내용도 포함합니다.

## 주요 화제
*   DOP에서의 코드 모듈 정의
*   모듈의 특징 (상태 없음, 명시적 데이터 인자)
*   DOP와 OOP의 차이점
*   고수준 모듈과 데이터 엔티티의 관계
*   Library Management System의 모듈 설계 예시

## 부차 화제

*   모듈과 클래스, 패키지, 네임스페이스의 관계

## Core 내용

## 상세 핵심 내용
DOP 시스템은 데이터와 코드의 분리를 통해 시스템의 이해도를 높입니다. 데이터 엔티티를 이해할 때는 코드의 세부 사항을 고려할 필요가 없고, 코드 모듈을 이해할 때는 데이터 엔티티의 세부 사항을 고려할 필요가 없습니다. DOP 모듈 다이어그램은 클래스 다이어그램보다 단순하며, 이는 모듈 간의 제약 때문이다. DOP 모듈 간의 관계는 사용 관계이며, 연관, 구성, 상속은 없습니다.

## 상세 정보 내용
DOP 시스템의 이해 용이성은 데이터 엔티티와 코드 모듈의 역할 분담, 모듈 간의 단순한 관계, 그리고 모듈 다이어그램의 간결함에서 기인합니다. 본 노드는 OOP 시스템과의 비교를 통해 DOP 시스템의 장점을 부각하며, 폴리모피즘 구현 방식과 같은 추가적인 정보를 제공합니다.
