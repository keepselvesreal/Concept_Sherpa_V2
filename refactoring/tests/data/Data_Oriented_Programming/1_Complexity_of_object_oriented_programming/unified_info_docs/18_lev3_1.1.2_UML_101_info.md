## 핵심 내용
UML 101은 객체 지향 프로그래밍(OOP)에서 사용되는 클래스 다이어그램의 다양한 관계를 설명합니다. 이 문서에서는 UML 다이어그램의 주요 관계인 composition, association, inheritance, usage를 구분하고, 각 관계의 특징과 예시를 제시합니다. 다이어그램 요소들을 통해 객체들 간의 상호 작용과 생명 주기를 이해할 수 있도록 돕습니다.

## 상세 핵심 내용
이 문서는 UML 다이어그램의 구성 요소와 관계 유형에 대해 설명합니다. composition은 한 객체가 소멸될 때 다른 객체도 함께 소멸되는 관계를 나타내며, association은 객체들이 독립적인 생명 주기를 가지는 관계입니다. inheritance는 일반화된 클래스와 특수화된 클래스 사이의 관계를 보여주며, usage는 한 클래스가 다른 클래스의 메서드를 호출하는 관계를 나타냅니다. composition은 plain diamond로, association은 empty diamond로, inheritance는 빈 삼각형으로, usage는 dashed arrow로 표현됩니다. 이러한 관계들은 객체 간의 상호 작용과 종속성을 이해하는 데 중요합니다.

## 상세 정보
*   **UML 다이어그램**: Library Management System의 클래스 다이어그램 예시
*   **관계 유형**:
    *   composition: 한 객체가 소멸되면 다른 객체도 소멸 (one-to-one, one-to-many)
    *   association: 객체들이 독립적인 생명 주기 (many-to-many)
    *   inheritance: 클래스 상속 (Member -> User)
    *   usage: 한 클래스가 다른 클래스의 메서드 호출 (Librarian::blockMember -> Member::block)
*   **표기법**:
    *   composition: plain diamond (one-to-one, one-to-many)
    *   association: empty diamond (many-to-many)
    *   inheritance: plain arrow with empty triangle
    *   usage: dashed arrows
*   **예시**:
    *   Library - Catalog (composition)
    *   Library - Member (composition)
    *   Book - Author (association)
    *   Librarian::blockMember - Member::block (usage)

In a composition relation, when one object dies, the other one also dies. While

In the class diagram, there are two kinds of composition symbolized by an arrow with
a plain diamond at one edge and an optional star at the other edge. Figure 1.2 shows
the relation between:
A Library that owns a Catalog—A one-to-one composition. If a Library object

A Library that owns many Members—A one-to-many composition. If a Library
object dies, then all its Member objects die with it.
TIP
A composition relation is represented by a plain diamond at one edge and an
