# 15_lev1_1_Complexity_of_object_oriented_programming_info.md
<구성 노드 반영 완료>

## Core 내용
객체 지향 프로그래밍(OOP)은 설계, 구현, 유지보수 단계에서 복잡성을 야기하며, 이는 클래스 간의 관계, 데이터 가변성, 데이터 직렬화, 클래스 계층 구조 등 여러 요인에 기인한다. 본 문서는 OOP의 복잡성을 심층적으로 분석하고, 각 문제점에 대한 구체적인 예시와 해결 방안을 제시한다. 특히, OOP의 대안으로 데이터 지향 프로그래밍(DOP)을 소개하며, DOP가 어떻게 OOP의 단점을 보완하고 시스템의 단순성을 확보하는지를 설명한다. OOP 설계의 중요성을 강조하며, UML 다이어그램을 활용한 설계 방법론과 구현 단계에 대한 정보도 함께 제공한다.

## 상세 핵심 내용
본 문서는 객체 지향 프로그래밍(OOP)의 다양한 측면에서 발생하는 복잡성을 심층적으로 분석한다. 먼저, OOP 설계 단계에서 UML 다이어그램을 활용하는 방법, 클래스 간의 관계(composition, association, inheritance, usage)를 이해하고 표현하는 방법을 다룬다. 라이브러리 관리 시스템을 예시로, 클래스 다이어그램의 각 구성 요소를 설명하고, 코드 작성 전 설계를 상세히 기록하는 것의 중요성을 강조한다.

이어서, OOP의 복잡성을 야기하는 주요 원인들을 구체적으로 살펴본다. 클래스 간의 과도한 관계, 객체 멤버의 가변성으로 인한 예측 불가능한 코드 동작, JSON 직렬화/역직렬화의 어려움, 복잡한 클래스 계층 구조(상속) 등을 예시와 함께 제시한다. 이러한 문제점들을 해결하기 위한 대안으로 데이터 지향 프로그래밍(DOP)을 소개한다. DOP는 데이터 불변성을 통해 안정성을 확보하고, 코드와 데이터의 분리를 통해 시스템 이해도를 높이며, 직렬화 과정을 단순화하는 등 OOP의 한계를 극복하는 방법을 제시한다. 마지막으로, OOP와 DOP의 비교를 통해 OOP의 문제점을 더욱 명확히 하고, DOP의 장점과 적용 가능성을 강조한다.

## 상세 정보 내용
본 문서는 객체 지향 프로그래밍(OOP)의 설계, 구현 단계에서 발생하는 복잡성과 이를 해결하기 위한 데이터 지향 프로그래밍(DOP)의 접근 방식을 상세히 설명한다.

**1. OOP 설계 및 구현:**
*   **OOP 설계:** UML 다이어그램을 활용한 설계 방법론 (composition, association, inheritance, usage 등)
*   **라이브러리 관리 시스템 예시:** 클래스 구조, 클래스 간의 관계 분석 (Library, User, Member, Librarian, Catalog, Book 등)
*   **설계의 중요성:** 코드 작성 전 상세 설계 기록의 중요성 강조

**2. OOP의 복잡성 원인:**
*   **클래스 간의 과도한 관계:** Member 클래스 예시 (데이터와 코드의 혼합)
*   **예측 불가능한 코드 동작:** 데이터 가변성 문제 (다중 스레드 환경), isBlocked 상태 변화
*   **복잡한 데이터 직렬화:** JSON 직렬화 및 역직렬화의 어려움 (코드 중복, 데이터 접근 제약)
*   **복잡한 클래스 계층 구조:** 상속, 다중 상속 ("다이아몬드 문제"), VIP 멤버 추가의 어려움

**3. DOP 소개 및 OOP와의 비교:**
*   **DOP의 특징:** 데이터 불변성, 코드와 데이터의 분리, 직렬화 단순화
*   **OOP vs DOP:** 각 접근 방식의 장단점 비교, DOP를 통한 OOP의 문제 해결

**4. 기타 정보:**
*   프로젝트 관리 (데드라인, 고객 관계)
*   알바트로스 컨설팅 프로젝트 예시
*   디자인 패턴의 역할 (복잡성 완화)
