## 핵심 내용
이 문서는 UML 다이어그램의 기본 개념들을 설명하며, 특히 클래스 다이어그램을 중심으로 다양한 관계(composition, association, inheritance, usage)를 소개한다. 객체 지향 프로그래밍(OOP)의 복잡성을 이해하고, UML 다이어그램을 통해 시스템의 구조를 시각적으로 표현하는 방법을 제시한다.

## 상세 핵심 내용
문서는 UML 다이어그램의 종류와 각 관계의 의미를 설명한다. composition은 객체가 다른 객체를 소유하며, 소유 객체가 사라지면 함께 사라지는 관계를 의미한다. association은 객체가 독립적인 생명주기를 가지며 서로 연관된 관계를 나타낸다. inheritance는 상속 관계를 의미하며, 사용 관계는 한 클래스가 다른 클래스의 메서드를 호출하는 경우를 나타낸다. 또한, 다이어그램에서 각 관계를 나타내는 기호(다이아몬드, 화살표 등)를 설명하고, 다양한 예시를 통해 이해를 돕는다.

## 상세 정보
*   **문서 제목:** 18 lev3 1.1.2 UML 101
*   **챕터:** 1.1.2 UML 101, 1.1 OOP design: Classic or classical?, 1.1.3 Explaining each piece of the class diagram
*   **주요 개념:**
    *   UML 다이어그램 (클래스 다이어그램)
    *   객체 지향 프로그래밍 (OOP)
    *   Composition (소유 관계): 한 객체가 다른 객체를 소유하며, 소유 객체가 사라지면 함께 사라짐.
    *   Association (연관 관계): 객체들이 독립적인 생명주기를 가지며 서로 연관됨.
    *   Inheritance (상속 관계): 한 클래스가 다른 클래스를 상속받음.
    *   Usage (사용 관계): 한 클래스가 다른 클래스의 메서드를 호출함.
*   **관계 및 기호:**
    *   Composition: plain diamond (one-to-one or one-to-many)
    *   Association: empty diamond at both edges (many-to-many)
    *   Inheritance: plain arrow with an empty triangle
    *   Usage: dashed arrow
*   **예시:**
    *   Library와 Catalog: one-to-one composition
    *   Library와 Member: one-to-many composition
    *   Book과 Author: many-to-many association
    *   Librarian::blockMember() 호출 Member::block() : usage
    *   Member와 User: inheritance

What’s the difference between composition and association?
 NOTE
Don’t worry if you’re not familiar with OOP jargon. We’re going to leave it
aside in the next chapter.
Theo
It’s all about whether the objects can live without each other. With composi-
tion, when one object dies, the other one dies too. While in an association rela-
tion, each object has an independent life.
TIP
In a composition relation, when one object dies, the other one also dies. While
in an association relation, each object has an independent life cycle.
In the class diagram, there are two kinds of composition symbolized by an arrow with
a plain diamond at one edge and an optional star at the other edge. Figure 1.2 shows
the relation between:
A Library that owns a Catalog—A one-to-one composition. If a Library object
dies, then its Catalog object dies with it.
A Library that owns many Members—A one-to-many composition. If a Library
object dies, then all its Member objects die with it.
TIP
A composition relation is represented by a plain diamond at one edge and an
optional star at the other edge.
Dave
Do you have association relations in your diagram?
Theo
Take a look at the arrow between Book and Author. It has an empty diamond
and a star at both edges, so it’s a many-to-many association relation.
A book can be written by multiple authors, and an author can write multiple books.
Moreover, Book and Author objects can live independently. The relation between
books and authors is a many-to-many association (figure 1.3).
