이 문서는 UML(Unified Modeling Language) 클래스 다이어그램의 기본 개념을 소개합니다. 주요 내용은 객체 지향 프로그래밍에서 사용되는 다양한 화살표 유형(Composition, Association, Inheritance, Usage)과 각 유형의 의미, 그리고 다이어그램에서 이들이 어떻게 표현되는지에 대한 설명입니다. 예를 들어, Composition은 객체의 생명 주기가 함께하며, Association은 독립적인 생명 주기를 가집니다.

## 상세 핵심 내용
이 문서는 UML(Unified Modeling Language) 다이어그램의 기본 개념을 소개합니다. UML은 객체 지향 프로그래밍에서 시스템을 시각적으로 표현하는 데 사용되며, 클래스 다이어그램은 그중 하나입니다. 클래스 다이어그램은 클래스 간의 관계를 나타내며, 여기에는 composition, association, inheritance, usage의 네 가지 주요 관계가 있습니다. Composition은 객체의 생명주기가 종속적인 관계를 나타내며, association은 독립적인 관계를, inheritance는 상속 관계를, usage는 클래스 간의 메서드 호출 관계를 표현합니다. 각 관계는 특정 모양의 화살표로 표현되며, 다이어그램을 통해 시스템의 구조와 동작을 이해하는 데 도움을 줍니다.

## 주요 화제
*   **UML (Unified Modeling Language) 소개**: UML 다이어그램의 기본적인 개념과 용어 설명
*   **UML 다이어그램의 종류**: 클래스 다이어그램을 예시로 하여 UML의 여러 요소 설명
*   **UML 다이어그램 요소**:
    *   **Composition (구성)**: 객체 간의 강한 관계, 한 객체가 소멸되면 다른 객체도 소멸됨
    *   **Association (연관)**: 객체 간의 독립적인 관계, 객체의 생명 주기가 서로 독립적임
    *   **Inheritance (상속)**: 클래스 간의 상속 관계
    *   **Usage (사용)**: 한 클래스가 다른 클래스의 메서드를 사용하는 관계
*   **OOP (Object-Oriented Programming) 디자인 원리**: 객체 지향 프로그래밍 디자인의 핵심 개념 소개
*   **Library Management System (도서관 관리 시스템) 예시**: 클래스 다이어그램을 통해 구체적인 예시 제시

## 부차 화제
다음은 문서에서 주요 주제 외에 언급된 부차적인 주제들입니다:

*   **OOP (객체 지향 프로그래밍) 용어:**
    *   상속, 컴포지션, 연관, 사용 관계를 나타내는 다양한 화살표 유형 (예: 일반 다이아몬드, 빈 다이아몬드, 점선)
    *   슈퍼클래스
    *   클래스 다이어그램
*   **OOP 디자인의 특징:**
    *   Composition과 association의 차이점
    *   한 객체가 다른 객체에 의존하는 경우 (composition)와 독립적인 경우 (association)의 생명 주기
    *   one-to-one, one-to-many, many-to-many 관계의 예시
*   **UML 다이어그램 관련:**
    *   다이어그램의 구성 요소 (클래스, 속성, 메서드)
*   **프로그래밍 관련 팁:**
    *   OOP 용어에 익숙하지 않은 독자를 위한 설명
*   **예시를 위한 문맥:**
    *   Library Management System (도서관 관리 시스템)
    *   Klafim's Global Library Management System

In a composition relation, when one object dies, the other one also dies. While
in an association relation, each object has an independent life cycle.
In the class diagram, there are two kinds of composition symbolized by an arrow with
a plain diamond at one edge and an optional star at the other edge. Figure 1.2 shows
the relation between:
A Library that owns a Catalog—A one-to-one composition. If a Library object
dies, then its Catalog object dies with it.
A Library that owns many Members—A one-to-many composition. If a Library
object dies, then all its Member objects die with it.
TIP
A composition relation is represented by a plain diamond at one edge and an
