## 핵심 내용

이 문서는 객체 지향 프로그래밍(OOP)에서 객체 멤버의 가변성으로 인해 발생하는 예측 불가능한 코드 동작을 설명합니다. 특히, 멀티 스레드 환경에서는 객체의 상태가 변경될 수 있어 두 번 호출하는 로그의 결과가 달라질 수 있습니다. 데이터 불변성이 이러한 문제를 해결하고 DOP(데이터 지향 프로그래밍) 개발자에게 안정감을 제공함을 강조합니다.

## 상세 핵심 내용

이 문서는 예측 불가능한 코드 동작에 대해 설명합니다. 객체 지향 프로그래밍(OOP)에서 객체 멤버는 변경 가능하기 때문에, 다중 스레드 환경에서 두 번의 `console.log` 호출 사이에 객체의 상태가 변경될 수 있어 예측 불가능한 결과를 초래할 수 있습니다. 이는 원시 값(primitive value)과 달리 객체 멤버는 변경 가능하기 때문입니다. 이러한 문제를 해결하기 위해 OOP는 뮤텍스와 같은 동시성 안전 메커니즘을 사용하지만, 성능 저하나 데드락(deadlock)의 위험을 초래합니다. 반면, DOP(Data-Oriented Programming)는 모든 데이터를 불변 값으로 처리하여, 개발자가 예측 가능한 코드를 작성하고 애플리케이션 개발에 집중할 수 있도록 합니다. 즉, 데이터의 불변성은 DOP 개발자의 마음의 평화를 가져다줍니다.

## 주요 화제

문서의 핵심 주제들은 다음과 같습니다:

*   **예측 불가능한 코드 동작:** 멀티 스레딩 환경 또는 비동기 코드(JavaScript)에서 객체 멤버에 접근할 때 발생하는 예측 불가능한 동작.
*   **객체 지향 프로그래밍(OOP)의 문제점:** 객체 멤버의 가변성(mutable)으로 인한 예측 불가능한 동작 발생.
*   **원시 타입과 객체 멤버의 차이:** 원시 타입은 불변성이지만, 객체 멤버는 가변성을 가질 수 있음.
*   **해결책:** 동시성 안전 메커니즘(뮤텍스 등)을 사용하여 보호하지만, 성능 저하 및 교착 상태 위험이 있음.
*   **데이터 불변성의 중요성:** DOP(Data-Oriented Programming)는 모든 데이터를 불변 값으로 취급하여 개발자의 안정성을 높임.
*   **불변성이 주는 이점:** DOP 개발자의 정신적 안정과 애플리케이션 개발에 집중할 수 있는 뇌세포 확보.

## 부차 화제

문서에서 언급된 부차적인 주제들은 다음과 같습니다:

*   **단일 스레드 vs. 멀티 스레드 환경에서의 코드 동작:** 멀티 스레드 환경에서 객체 상태 변경으로 인해 코드의 예측 불가능성이 발생할 수 있음.
*   **비동기 코드에서의 예측 불가능성:** 자바스크립트와 같이 단일 스레드 환경에서도 비동기 코드를 통해 데이터가 수정될 경우 예측 불가능성이 발생할 수 있음.
*   **OOP (객체 지향 프로그래밍)의 문제점:** 객체 멤버의 가변성으로 인한 예측 불가능한 동작, 그리고 이로 인한 동시성 안전 메커니즘 도입의 필요성(성능 저하 및 데드락 위험).
*   **DOP (Data-oriented programming)의 장점:** DOP에서의 데이터 불변성(primitive type 및 collection type 모두)이 개발자에게 안정성을 제공하고, 애플리케이션 개발에 집중할 수 있게 해줌.
*   **무테스(mutexes)를 사용한 동시성 안전 메커니즘:** OOP에서 예측 불가능성을 해결하기 위한 방법 중 하나, 하지만 성능 저하 및 데드락 위험과 같은 문제점이 발생.

You might be a bit tired after the system-level analysis that we presented in the previ-

class Member {
  isBlocked;
  displayBlockedStatusTwice() {
    var isBlocked = this.isBlocked;
    console.log(isBlocked);
    console.log(isBlocked);
  }
}
member.displayBlockedStatusTwice();

"Of course, it displayed true again," you say. And you are right!
 Now, take a look at a slightly different pseudocode as shown in listing 1.2. Here we

displayed on the second console.log call?

class Member {
  isBlocked;
  displayBlockedStatusTwice() {
    console.log(this.isBlocked);
    console.log(this.isBlocked);
  }
}
member.displayBlockedStatusTwice();

multi-threaded environment, it's unpredictable. Indeed, in a multi-threaded environ-

the state of the object (e.g., a librarian unblocked the member). In fact, with a slight
modification, the same kind of code unpredictability could occur even in a single-

Complexity of object-oriented programming
This unpredictable behavior of the second listing is one of the annoying conse-
quences of OOP. Unlike primitive types, which are usually immutable, object mem-
bers are mutable. One way to solve this problem in OOP is to protect sensitive code
with concurrency safety mechanisms like mutexes, but that introduces issues like a
performance hit and a risk of deadlocks.
 We will see later in the book that DOP treats every piece of data in the same way:
both primitive types and collection types are immutable values. This value treatment for
all citizens brings serenity to DOP developers' minds, and more brain cells are avail-
able to handle the interesting pieces of the applications they build.

TIP
Data immutability brings serenity to DOP developers' minds.
