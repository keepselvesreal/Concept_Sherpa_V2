7.5 Details about data validation failures: **7.5 유효성 검사 실패 시 상세 정보 분석 및 활용**

이 챕터는 JSON Schema validation 실패 시, 실패 이유에 대한 상세 정보를 얻는 방법과 그 유용성을 다룹니다. 부모 노드의 7 Basic data validation 내용과 연결하여, 오류 처리 및 사용자 경험 개선의 중요성을 강조합니다.

**1. 오류 정보의 구조와 해석 (부모 노드 내용 반영):**

*   **오류 정보의 형태:** Ajv (JavaScript validator)를 예시로, validation 실패 시 오류 정보는 배열 형태로 반환됩니다. 각 배열 요소는 오류에 대한 상세 정보를 담은 객체입니다.
*   **객체 내부 구조:** 각 오류 객체는 다음과 같은 속성을 가질 수 있습니다.
    *   `instancePath`: 오류가 발생한 데이터 내의 위치.
    *   `schemaPath`: 스키마 내에서 오류가 발생한 부분의 위치.
    *   `keyword`: 발생한 오류의 유형 (예: "required", "type").
    *   `params`: 오류 유형에 따른 추가적인 정보.
    *   `message`: 오류에 대한 설명 (인간 친화적인 텍스트).
*   **오류 정보의 난해함:** 원시적인 오류 정보는 이해하기 어려울 수 있습니다.

**2. 오류 정보를 활용하는 방법 (부모 노드 내용 반영):**

*   **오류 정보의 가독성 향상:** Ajv는 `errorsText` 유틸리티 함수를 제공하여 오류 정보를 사람이 읽기 쉬운 형태로 변환합니다.
*   **다중 오류 처리 (allErrors 옵션):** `allErrors: true` 옵션을 통해 모든 오류를 감지하고, 한 번에 처리합니다.
*   **실제 사용 사례:** 시스템 경계 (boundaries)에서 데이터 유효성 검사를 수행하여, 오류 발생 시 사용자에게 명확한 정보를 제공합니다.

## 주요 화제
- **데이터 유효성 검사 실패 시 상세 정보 접근:** JSON Schema 유효성 검사 실패 시, 실패 이유에 대한 상세 정보를 얻을 수 있다는 점을 설명합니다. 필수 필드 누락, 잘못된 타입 등의 구체적인 오류 정보를 확인할 수 있습니다.
- **Ajv 라이브러리의 오류 정보 구조:** JavaScript의 Ajv 라이브러리를 예시로 들어, 유효성 검사 실패 시 오류 정보가 어떻게 저장되고 접근되는지 설명합니다. 오류 정보는 배열 형태로 저장되며, 각 오류는 `instancePath`, `schemaPath`, `keyword`, `params`, `message` 등의 속성을 가집니다.
- **Ajv의 오류 정보를 이해하기 쉬운 형태로 변환:** Ajv 라이브러리가 제공하는 `errorsText` 유틸리티 함수를 사용하여 오류 배열을 사람이 읽기 쉬운 형식으로 변환하는 방법을 제시합니다.
- **Ajv에서 다중 오류 감지 활성화:** Ajv가 기본적으로 첫 번째 오류만 감지하지만, `allErrors: true` 옵션을 사용하여 여러 개의 오류를 감지하도록 설정하는 방법을 설명합니다. 이를 통해 데이터의 여러 유효성 검사 실패를 한 번에 확인할 수 있습니다.
- **JSON Schema Cheat Sheet 소개:** JSON Schema의 기본 개념을 요약한 치트 시트를 통해 `type`, `items`, `properties`, `required`, `enum`, `additionalProperties` 등의 주요 키워드를 간략하게 설명합니다.
- **JSON Schema 유효 데이터 예시:** JSON Schema의 유효성 검사를 통과하는 데이터의 예시를 제시하여, 스키마와 데이터 간의 관계를 이해하도록 돕습니다.
