Complexity of object-oriented programming
This unpredictable behavior of the second listing is one of the annoying conse-
quences of OOP. Unlike primitive types, which are usually immutable, object mem-
bers are mutable. One way to solve this problem in OOP is to protect sensitive code
with concurrency safety mechanisms like mutexes, but that introduces issues like a
performance hit and a risk of deadlocks.
 We will see later in the book that DOP treats every piece of data in the same way:
both primitive types and collection types are immutable values. This value treatment for
all citizens brings serenity to DOP developers' minds, and more brain cells are avail-
able to handle the interesting pieces of the applications they build.
TIP
Data immutability brings serenity to DOP developers' minds.

## 핵심 내용
객체지향 프로그래밍(OOP)에서 객체 멤버의 가변성으로 인해 발생하는 예측 불가능한 코드 동작을 설명한다. 특히, 멀티 스레드 환경에서 객체의 상태가 변경될 수 있어 동일한 코드가 다른 결과를 낼 수 있음을 지적하고, 데이터 불변성이 이러한 문제를 해결하고 DOP 개발자에게 안정감을 제공한다고 강조한다.

## 상세 핵심 내용
OOP에서 객체 멤버는 가변적이기 때문에, 멀티 스레드 환경에서 코드의 예측 불가능한 동작이 발생할 수 있다.  두 번의 console.log 호출 사이에 객체의 상태가 변경될 가능성이 있으며, 이는 concurrency safety mechanisms (뮤텍스 등)을 통해 해결할 수 있지만 성능 저하나 데드락 위험을 초래할 수 있다. 반면, DOP에서는 모든 데이터를 불변 값으로 취급하여 이러한 문제를 방지하고 개발자의 인지 부담을 줄인다.  데이터의 가변성은 코드의 예측 불가능성을 야기하며, 데이터 불변성은 DOP 개발자에게 안정감을 제공한다.

## 상세 정보
*   OOP에서 객체 멤버의 가변성으로 인해 코드 동작이 예측 불가능해질 수 있다.
*   싱글 스레드 환경에서는 예측 가능한 결과가 나오지만, 멀티 스레드 환경에서는 context switch로 인해 객체의 상태가 변경되어 다른 결과가 나올 수 있다.
*   자바스크립트와 같은 싱글 스레드 환경에서도 비동기 코드에 의해 데이터가 변경될 경우 예측 불가능한 동작이 발생할 수 있다.
*   primitive 타입은 일반적으로 immutable하지만, 객체 멤버는 mutable하다.
*   이러한 문제를 해결하기 위해 뮤텍스와 같은 concurrency safety mechanisms을 사용할 수 있지만, 성능 저하나 데드락 위험이 발생할 수 있다.
*   DOP에서는 모든 데이터를 immutable 값으로 취급하여 코드의 예측 가능성을 높이고 개발자의 부담을 줄인다.
*   데이터 불변성은 DOP 개발자에게 안정감을 제공한다.
