## 핵심 내용
이 문서는 Klafim 글로벌 라이브러리 관리 시스템 프로토타입의 객체 지향 설계를 설명합니다. 개발자 Theo는 시스템을 코딩하기 전에 UML 클래스 다이어그램을 사용하여 주요 클래스(예: Library, Book, Member, Librarian)와 그들 간의 관계를 정의했습니다. 이 설계는 초보적인 수준이지만, OOP 시스템의 복잡성을 보여주고 코딩을 시작하기에 충분한 정보를 제공합니다.

## 상세 핵심 내용
이 문서는 객체 지향 프로그래밍(OOP) 설계 단계에 대한 내용을 담고 있습니다. 개발자 테오가 Klafim 프로토타입을 구현하기 위해 UML 클래스 다이어그램을 이용하여 시스템을 설계하는 과정을 보여줍니다. 시스템은 도서관 회원, 사서, 책, 도서 대출, 책 목록, 작가 등의 주요 클래스로 구성됩니다. 설계 과정에서 테오는 사용자의 요구사항을 파악하고, 각 클래스 간의 관계를 정의하며, 2시간 후 첫 번째 설계를 완성합니다. 이 설계는 초보적인 수준이지만, 실제 OOP 시스템의 복잡성을 이해하는 데 도움이 됩니다. 테오는 주니어 개발자 데이브에게 설계를 보여주며, 객체의 상태 변화 문제에 대한 대화를 나눕니다. 마지막으로, 이 설계는 코딩 시작을 위한 기반을 제공하며, 전반적인 시스템의 구조를 이해하는 데 중요한 역할을 합니다.

## 1.1.1 The Design Phase - 상세 정보 정리

**1. 개요:**

*   **제목:** 1.1.1 The design phase
*   **목표:** Klafim 프로토타입을 구현할 시스템의 객체 지향 설계 (OOP design)
*   **주요 내용:**
    *   설계 단계에서의 UML 클래스 다이어그램 작성
    *   시스템의 주요 클래스 식별 및 관계 정의
    *   초보 개발자를 위한 간단한 설계 (디자인 패턴 미사용)
    *   설계 과정에서의 대화 및 문제점 공유

**2. 시스템 요구사항 (Requirements):**

*   **사용자:**
    *   도서관 회원 (Members)
    *   사서 (Librarians)
*   **기능:**
    *   **공통:**
        *   이메일 및 비밀번호를 이용한 로그인
        *   제목 또는 저자를 이용한 도서 검색
    *   **회원 (Members):**
        *   도서 대출
    *   **사서 (Librarians):**
        *   회원 차단 및 해제 (도서 반납 지연 시)
        *   회원에게 대출된 도서 목록 확인
*   **기타:**
    *   도서는 여러 권의 복사본 (copies)을 가질 수 있음
    *   도서는 특정 도서관 (physical library)에 소속됨

**3. 주요 클래스 (Main Classes):**

*   **Library (도서관):** 시스템의 핵심 부분
*   **Book (도서):** 책
*   **BookItem (도서 항목):** 책의 각 복사본
*   **BookLending (도서 대출):** 도서 대출 시 생성되는 객체
*   **Member (회원):** 도서관 회원
*   **Librarian (사서):** 도서관 사서
*   **User (사용자):** Librarian과 Member의 기본 클래스 (Base class)
*   **Catalog (목록):** 도서 목록을 포함
*   **Author (저자):** 책의 저자

**4. 설계 (Design) 관련 정보:**

*   **UML 클래스 다이어그램:** 시스템의 클래스와 관계를 시각적으로 표현
*   **설계의 목적:**
    *   개발자 (Theo)가 코딩을 시작할 수 있도록 충분한 정보를 제공
    *   책의 저자가 OOP 시스템의 복잡성을 설명할 수 있도록 예시 제공
*   **설계의 특징:**
    *   초보적인 설계 (Naive design): 숙련된 OOP 개발자가 사용하는 디자인 패턴을 사용하지 않음
    *   모든 시스템 기능을 포괄하지 않음

**5. 등장 인물 및 대화 내용:**

*   **Theo (개발자):** Klafim 시스템 설계를 진행
*   **Dave (주니어 개발자):** Theo에게 설계에 대한 질문을 하고, 객체 상태 변화 문제에 대한 어려움을 겪음
*   **대화 내용:**
    *   Theo가 시스템 설계를 완료하고 Dave에게 보여주며, 설계에 대한 의견을 나눔
    *   Dave는 객체 지향 설계에 대한 지식을 쌓기 위해 노력하며, 객체 상태 변화 문제에 대한 어려움을 토로

**6. 기타 정보:**

*   페이지 33, 34에 걸쳐 내용이 구성됨

### 1.1.1 The design phase

1.1.1
The design phase
Before rushing to his laptop to code the system, Theo grabs a sheet of paper, much big-
ger than a napkin, and starts to draw a UML class diagram of the system that will imple-
ment the Klafim prototype. Theo is an object-oriented programmer. For him, there is no
question—every business entity is represented by an object, and every object is made
from a class.
Theo spends some time thinking about the organization of the system. He identifies the
main classes for the Klafim Global Library Management System.
The requirements for the Klafim prototype
There are two kinds of users: library members and librarians.
Users log in to the system via email and password.
Members can borrow books.
Members and librarians can search books by title or by author.
Librarians can block and unblock members (e.g., when they are late in return-
ing a book).
Librarians can list the books currently lent to a member.
There can be several copies of a book.
A book belongs to a physical library.
