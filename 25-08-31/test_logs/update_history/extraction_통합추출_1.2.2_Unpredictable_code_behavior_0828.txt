Complexity of object-oriented programming
This unpredictable behavior of the second listing is one of the annoying conse-
quences of OOP. Unlike primitive types, which are usually immutable, object mem-
bers are mutable. One way to solve this problem in OOP is to protect sensitive code
with concurrency safety mechanisms like mutexes, but that introduces issues like a
performance hit and a risk of deadlocks.
 We will see later in the book that DOP treats every piece of data in the same way:
both primitive types and collection types are immutable values. This value treatment for
all citizens brings serenity to DOP developers' minds, and more brain cells are avail-
able to handle the interesting pieces of the applications they build.
TIP
Data immutability brings serenity to DOP developers' minds.

## 핵심 내용
이 문서는 객체 지향 프로그래밍(OOP)에서 발생하는 예측 불가능한 코드 동작에 대해 설명한다. 특히, 데이터의 가변성으로 인해 멀티 스레드 환경에서 객체 멤버에 접근할 때 발생하는 문제점을 지적하고, 데이터 불변성을 지향하는 DOP(Data-Oriented Programming)가 이러한 문제를 해결하는 데 도움이 된다고 주장한다.

## 상세 핵심 내용
OOP에서는 객체 멤버가 가변적이기 때문에, 멀티 스레드 환경에서 동일한 객체 멤버에 연속적으로 접근할 때 예기치 않은 결과가 발생할 수 있다. 이는 스레드 간의 컨텍스트 스위치로 인해 객체의 상태가 변경될 수 있기 때문이다. 이러한 문제를 해결하기 위해 뮤텍스와 같은 동시성 안전 메커니즘을 사용할 수 있지만, 성능 저하와 데드락 발생 위험이 따른다. 반면, DOP는 모든 데이터를 불변 값으로 취급하여 개발자에게 안정성을 제공하고 복잡한 문제 해결에 집중할 수 있도록 돕는다. 따라서 데이터 불변성은 DOP 개발자에게 중요한 이점을 제공한다.

## 상세 정보
*   **예측 불가능한 코드 동작 (Unpredictable code behavior):** OOP에서 객체 멤버의 가변성으로 인해 발생할 수 있는 문제점을 다룬다.
*   **코드 예시 1 (Listing 1.1):** 지역 변수에 Boolean 값을 할당하여 두 번 출력하는 경우, 예측 가능한 결과를 얻을 수 있다.
*   **코드 예시 2 (Listing 1.2):** 객체 멤버에 직접 접근하여 두 번 출력하는 경우, 멀티 스레드 환경에서 예측 불가능한 결과를 얻을 수 있다.
*   **멀티 스레드 환경의 문제점:** 스레드 간 컨텍스트 스위치로 인해 객체의 상태가 변경되어 예측 불가능한 결과가 발생할 수 있다.
*   **동시성 안전 메커니즘:** 뮤텍스 등의 메커니즘을 사용하여 동시성 문제를 해결할 수 있지만, 성능 저하 및 데드락 위험이 있다.
*   **DOP (Data-Oriented Programming):** 모든 데이터를 불변 값으로 취급하여 OOP의 가변성 문제를 해결하고 개발자에게 안정성을 제공한다.
*   **데이터 불변성의 중요성:** 데이터 불변성은 DOP 개발자에게 안정성을 제공하고 복잡한 문제 해결에 집중할 수 있도록 돕는다.
