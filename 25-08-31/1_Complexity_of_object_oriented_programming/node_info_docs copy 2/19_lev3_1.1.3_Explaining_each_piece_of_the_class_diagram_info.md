## 핵심 내용

이 문서는 도서관 시스템의 클래스 다이어그램 구성 요소들을 설명합니다. `Library` 클래스는 시스템의 루트 클래스이며, `Member`, `Librarian`, `Catalog` 객체를 소유합니다. `Librarian`과 `Member` 클래스는 `User` 클래스에서 파생되며, `Catalog` 클래스는 책을 관리하고, `Book` 클래스는 책의 정보를, `BookItem` 클래스는 책의 사본을 나타냅니다.

## 상세 핵심 내용

이 문서는 도서관 시스템의 클래스 다이어그램을 설명하며, 핵심 클래스들의 역할과 관계를 정의합니다. `Library` 클래스는 시스템의 루트 클래스로, `Member`, `Librarian`, `Catalog` 객체를 소유하며, 실질적인 행위는 이들에게 위임합니다. `User` 클래스는 `Member`와 `Librarian` 클래스의 기반이 되며, 기본적인 사용자 정보를 관리하고 로그인 기능을 제공합니다. `Member` 클래스는 도서 대출, 반납, 계정 차단/해제 기능을 가지며, `BookLending` 객체를 소유하고, `BookItem`을 사용하여 도서를 대출합니다. `Librarian` 클래스는 회원의 차단/해제, 대출 기록 조회, 도서 추가 기능을 제공하며, `Member`, `BookItem`, `BookLending`을 사용합니다. `Catalog` 클래스는 도서 검색 및 추가를 담당하며, `Book` 객체를 소유하고 `Librarian`을 활용하여 도서를 추가합니다. 마지막으로, `Book` 클래스는 도서의 기본적인 정보와 저자 정보를 관리하며, `BookItem` 객체를 소유하고, `BookItem`은 도서의 개별 복사본을 나타내며, 각 대출 기록을 `BookLending` 객체로 관리합니다.

## 주요 화제

다음은 문서의 주요 화제들을 불렛 포인트로 정리한 내용입니다.

*   **클래스 다이어그램 설명**: 문서의 주요 목적은 클래스 다이어그램의 각 요소들을 설명하는 것입니다.
*   **Library 클래스**: Library 클래스는 라이브러리 시스템의 루트 클래스이며, 다른 객체들을 소유하고 위임하는 역할을 합니다.
*   **User 클래스**: User 클래스는 라이브러리 사용자를 나타내며, id, email, password 속성을 가지고 login 기능을 제공합니다.
*   **Member 클래스**: Member 클래스는 User 클래스를 상속받아 라이브러리 회원을 나타내며, 도서 대출(checkout), 반납(returnBook), 차단(block), 차단 해제(unblock) 기능을 제공합니다. BookLending 객체를 소유하고 BookItem을 사용하여 대출을 구현합니다.
*   **Librarian 클래스**: Librarian 클래스는 User 클래스를 상속받아 사서를 나타내며, 회원 차단/해제, 회원 대출 목록 조회, 도서 아이템 추가 기능을 제공합니다. Member, BookItem, BookLending을 사용하여 기능을 구현합니다.
*   **Catalog 클래스**: Catalog 클래스는 도서 관리를 담당하며, 도서 검색(search), 도서 아이템 추가(addBookItem) 기능을 제공합니다. Librarian을 사용하여 addBookItem을 구현하고 Book 객체를 소유합니다.
*   **Book 클래스**: Book 클래스는 도서의 기본 정보를 나타내며, id, title 속성을 가지고 여러 Author 객체와 연관되며 여러 BookItem 객체를 소유합니다.
*   **BookItem 클래스**: BookItem 클래스는 도서 복사본을 나타내며, id, libId 속성을 가지고 BookLending 객체를 소유하며, 도서 대출(checkout) 기능을 제공합니다.
*   **객체 지향 프로그래밍(OOP)**: 문서 전체적으로 객체 지향 프로그래밍의 개념과 클래스 간의 관계를 설명하고 있습니다.

## 부차 화제

이 문서의 주요 주제는 클래스 다이어그램의 각 부분을 설명하는 것이지만, 다음과 같은 부차적인 주제들이 언급됩니다.

*   **UML (Unified Modeling Language):** 클래스 다이어그램을 이해하기 위한 기본적인 지식.
*   **객체 지향 프로그래밍 (OOP):** 라이브러리 시스템이 OOP 원칙에 따라 설계되었음을 암시하며, 클래스와 객체의 관계, 상속, 캡슐화 등의 개념이 언급됩니다.
*   **라이브러리 시스템:** 문서 전체의 맥락을 제공하며, 라이브러리 시스템의 구성 요소와 각 클래스의 역할을 설명합니다.
*   **데이터 모델링:** 각 클래스가 어떤 데이터를 소유하고 관리하는지에 대한 설명. (예: Library 클래스는 Member, Librarian, Catalog 객체를 소유)
*   **코드/행동 모델링:** 각 클래스가 어떤 행동(메서드)을 수행할 수 있는지에 대한 설명. (예: Member 클래스는 checkout, returnBook 등을 수행)
*   **클래스 간의 관계:** 상속 (User, Librarian, Member), 소유 (Library, Member, Librarian, Catalog, Book, BookItem)와 사용 관계 (Catalog - Librarian, Librarian - Member, Librarian - BookItem, Librarian - BookLending)가 설명됩니다.
*   **보안 (암호화):** User 클래스의 password 필드에 대한 언급에서 보안 및 암호화의 중요성이 간략하게 언급됩니다.
*   **책 대출/반납 프로세스:** Member 클래스의 checkout, returnBook 메서드와 BookLending 객체를 통해 유추할 수 있습니다.

LIBRARIAN, MEMBER, AND USER CLASSES
Librarian and Member both derive from User. Figure 1.7 shows this relation.
The User class represents a user of the library:
In terms of data members, it sticks to the bare minimum: it has an id, email,
and password (with no security and encryption for now).
In terms of code, it can log in via login.
The Member class represents a member of the library:
It inherits from User.
In terms of data members, it has nothing more than User.
In terms of code, it can
– Check out a book via checkout.
– Return a book via returnBook.
– Block itself via block.
– Unblock itself via unblock.
– Answer if it is blocked via isBlocked.
It owns multiple BookLending objects.
It uses BookItem in order to implement checkout.

The Librarian class represents a librarian:
It derives from User.
In terms of data members, it has nothing more than User.
In terms of code, it can
– Block and unblock a Member.
– List the member's book lendings via getBookLendings.
– Add book items to the library via addBookItem.

It uses BookItem to implement checkout.
It uses BookLending to implement getBookLendings. 
THE CATALOG CLASS
The Catalog class is responsible for the management of the books. Figure 1.8 shows
the relation among the Catalog, Librarian, and Book classes. In terms of code, a
Catalog object can
Search books via search.
Add book items to the library via addBookItem.
A Catalog object uses Librarian in order to implement addBookItem. In terms of
data, a Catalog owns multiple Book objects. 
THE BOOK CLASS
Figure 1.9 presents the Book class. In terms of data, a Book object
Should have as its bare minimum an id and a title.
Is associated with multiple Author objects (a book might have multiple authors).
Owns multiple BookItem objects, one for each copy of the book.

THE BOOKITEM CLASS
