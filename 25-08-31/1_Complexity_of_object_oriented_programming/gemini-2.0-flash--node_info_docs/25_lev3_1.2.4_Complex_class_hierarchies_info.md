## 핵심 내용

OOP에서 클래스 상속을 통해 코드 재사용성을 높일 수 있지만, 시스템 요구사항 변경에 따라 복잡한 클래스 계층 구조가 발생하고 코드 수정이 어려워질 수 있다. 특히 다중 상속은 "Deadly Diamonds of Death" 문제를 야기하여 시스템을 더욱 복잡하게 만들 수 있으므로, OOP에서는 상속보다 컴포지션을 선호하는 것이 좋다.

## 상세 핵심 내용

이 문서는 객체 지향 프로그래밍(OOP)에서 클래스 상속의 복잡성과 문제점을 보여준다. 초기 시스템 설계 시에는 클래스 상속이 코드 재사용에 유용하지만, 시스템 구현 후 새로운 요구사항이 추가될 때 유연성이 떨어진다는 점을 지적한다. 특히 VIP 멤버와 Super 멤버 기능 추가 요구사항이 발생하면서 기존 클래스 계층 구조를 수정해야 했고, 다중 상속으로 인한 다이아몬드 문제가 발생하여 시스템이 복잡해지고 개발 기한을 맞추지 못하게 되었다. 이 사례는 OOP에서 클래스 상속보다는 컴포지션(composition)을 사용하는 것이 더 유연하고 유지보수가 용이한 설계를 만들 수 있음을 강조한다. 급작스러운 요구사항 변경에 대한 설계의 중요성을 시사하며, 유연하지 못한 상속 기반 설계가 얼마나 큰 어려움을 초래할 수 있는지 보여준다. 최종적으로 시스템은 Super 멤버 기능을 제외하고 출시되었으며, 이는 초기 설계의 중요성을 더욱 강조하는 결과로 이어진다.

## 주요 화제

다음은 문서의 주요 화제들입니다:

*   **객체 지향 프로그래밍(OOP)에서의 클래스 상속의 복잡성**: 특히 시스템 요구 사항이 변경될 때 클래스 상속이 가져올 수 있는 문제점을 다룹니다.

*   **클래스 계층 구조 설계**: 초기 요구 사항에 맞춰 설계된 클래스 계층 구조가 새로운 요구 사항에 얼마나 취약한지 보여줍니다.

*   **VIP 멤버 기능 추가의 어려움**: 기존 코드(Librarian 클래스의 addBookItem 메서드)를 재사용하기 어려운 상황을 설명하며, OOP에서 코드가 클래스에 잠겨 있다는 점을 강조합니다.

*   **다중 상속과 다이아몬드 문제**: VIPMember 클래스가 Member와 UserWithBookItemRight 클래스를 상속받아 발생하는 다이아몬드 문제를 지적합니다.

*   **Super 멤버 기능 추가의 복잡성**: Super 멤버를 추가하면서 시스템의 복잡성이 증가하고, 다이아몬드 문제가 더 심화되는 상황을 보여줍니다.

*   **합성(Composition) vs 상속(Inheritance)**: 클래스 상속 대신 합성을 사용하는 것이 더 나은 설계 방법일 수 있음을 제시합니다.

*   **요구 사항 변경과 개발 일정**: 갑작스러운 요구 사항 변경이 개발 일정에 미치는 영향과 개발자의 어려움을 보여줍니다.

*   **실패한 프로젝트와 교훈**: 복잡한 클래스 계층 구조로 인해 프로젝트가 기한 내에 완료되지 못하고, 결국 기능 추가가 연기되는 상황을 통해 교훈을 얻습니다.

### 1.2.4_Complex_class_hierarchies

1.2.4
Complex class hierarchies
One way to avoid writing the same code twice in OOP involves class inheritance. Indeed,
when every requirement of the system is known up front, you design your class hier-
archy is such a way that classes with common behavior derive from a base class.
 Figure 1.15 shows an example of this pattern that focuses on the part of our class
diagram that deals with members and librarians. Both Librarians and Members need
the ability to log in, and they inherit this ability from the User class.
So far, so good, but when new requirements are introduced after the system is imple-
mented, it's a completely different story. Fast forward to Monday, March 29th, at 11:00 AM,
where two days are left before the deadline (Wednesday at midnight).
