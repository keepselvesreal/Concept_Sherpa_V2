## 핵심 내용

Theo는 꿈에서 Klafim 도서관 관리 시스템을 REST API로 구현해야 했고, JSON을 사용하여 검색 기능을 만들려 했다. 하지만 OOP 방식으로 JSON 직렬화 및 역직렬화를 구현하는 과정이 복잡하고 반복적인 코드 작성을 요구하여 어려움을 겪었고, 이는 OOP에서 데이터가 클래스 내부에 잠겨 있어 발생하는 문제점임을 보여준다.

## 상세 핵심 내용

이 문서는 OOP(Object-Oriented Programming)에서 JSON 데이터 직렬화/역직렬화의 어려움을 지적하고 있습니다. Theo라는 개발자가 REST API를 구현하는 꿈을 꾸는데, 여기서 /search 엔드포인트 구현 시 JSON 입출력을 처리하기 위해 여러 클래스(SearchController, SearchQuery, SearchResult)를 반복적으로 생성해야 하는 어려움을 겪습니다. 이는 새로운 엔드포인트(/add-book-item)를 추가할 때마다 동일한 과정을 반복해야 하는 비효율성을 초래합니다. OOP에서는 데이터가 클래스 멤버에 고정되어 있어 일반적인 접근이 어렵고, 따라서 데이터 직렬화가 복잡해지는 문제가 있습니다. 결론적으로 OOP에서 JSON 처리는 많은 클래스와 코드를 반복적으로 작성해야 하는 번거로움을 야기하며, 데이터 중심 프로그래밍(DOP)을 통해 이러한 문제를 해결할 수 있음을 암시합니다. OOP 언어들이 reflection이나 코드 장황성을 통해 이 어려움을 완화하려고 하지만, 근본적인 해결책은 아니라는 점도 언급됩니다.

## 주요 화제

다음은 해당 문서의 주요 화제입니다.

*   **데이터 직렬화의 어려움 (Data Serialization Challenges):** OOP 환경에서 JSON을 사용한 데이터 직렬화 및 역직렬화가 복잡하고 반복적인 작업임을 강조합니다.
*   **REST API 설계:** Klafim's Library Management System을 REST API로 제공하고, 특히 `/search` 엔드포인트 구현을 예시로 들어 설명합니다.
*   **OOP의 복잡성 (Complexity of Object-Oriented Programming):** 데이터 직렬화를 위해 여러 클래스(Controller, Query, Result)를 생성해야 하는 OOP의 구조적 복잡성을 지적합니다.
*   **JSON 처리의 반복성 (Repetitive JSON Handling):** 각 엔드포인트마다 JSON 직렬화/역직렬화 코드를 반복적으로 작성해야 하는 문제점을 설명합니다.
*   **OOP에서의 데이터 접근 제한 (Limited Data Access in OOP):** OOP에서는 데이터가 클래스 멤버에 갇혀 있어 일반적인 접근이 어렵다는 점을 지적합니다.
*   **DOP (Data-Oriented Programming) 언급:** DOP가 JSON 직렬화/역직렬화에 대한 일반적인 해결책을 제공할 수 있음을 암시합니다.
*   **JSON과 관련된 OOP의 어려움 완화 노력:** reflection이나 코드의 장황성을 통해 JSON과 관련된 OOP의 어려움을 완화하려는 노력을 언급합니다.

## 부차 화제

이 문서의 부차적인 주제들은 다음과 같습니다:

*   **REST API**: Klafim's Library Management System을 REST API를 통해 접근 가능하게 만드는 것.
*   **OOP (Object-Oriented Programming)의 복잡성**: OOP에서 데이터 직렬화 및 역직렬화의 어려움, 클래스 기반의 rigid한 데이터 구조, generic한 데이터 접근의 부재.
*   **/search 엔드포인트**: JSON 형식의 쿼리를 받아 결과를 JSON 형식으로 반환하는 검색 엔드포인트 구현 예시.
*   **/add-book-item 엔드포인트**: 사서가 책 항목을 추가할 수 있는 엔드포인트 구현의 복잡성.
*   **JSON 직렬화/역직렬화**: OOP에서 JSON 직렬화/역직렬화 처리를 위한 반복적인 클래스 생성 및 코드 작성의 문제점.
*   **데이터 필드 처리**: 데이터 필드 이름과 값을 쉼표로 구분하여 연결하는 방식의 일반적인 데이터 직렬화 과정.
*   **Reflection 및 코드 장황성**: OOP 언어에서 JSON 변환의 어려움을 완화하기 위한 방법으로 언급되는 Reflection의 복잡성 및 코드의 장황성.
*   **DOP (Data-Oriented Programming)**: DOP가 JSON 직렬화/역직렬화를 처리하는 generic한 방식에 대한 간략한 언급.

Complexity of object-oriented programming
 The bad news is that Theo would have to repeat the same process for every end-
point of the system. Each time he encounters a new kind of JSON input or output,
he would have to create a new class and write code. Theo's dream is turning into a
nightmare!
Suddenly, his phone rings, next to where he was resting his head on the desk. As Theo
wakes up, he realizes that Nancy never asked for JSON. It was all a dream . . . a really bad
dream!

TIP
In OOP, data serialization is difficult.

It's quite frustrating that handling JSON serialization and deserialization in OOP
requires the addition of so many classes and writing so much code—again and again!
The frustration grows when you consider that serializing a search query, a book item
query, or any query is quite similar. It comes down to
Going over data fields.
Concatenating the name of the data fields and the value of the data fields, sepa-
rated by a comma.
Why is such a simple thing so hard to achieve in OOP? In OOP, data has to follow a
rigid shape defined in classes, which means that data is locked in members. There is
no simple way to access data generically.

TIP
In OOP, data is locked in classes as members.

We will refine later what we mean by generic access to the data, and we will see how
DOP provides a generic way to handle JSON serialization and deserialization. Until
then, you will have to continue suffering. But at least you are starting to become aware
of this suffering, and you know that it is avoidable.
 NOTE
Most OOP programming languages alleviate a bit of the difficulty involved
in the conversion from and to JSON. It either involves reflection, which is definitely a
complex thing, or code verbosity.
