## 핵심 내용

이 문서는 OOP(객체 지향 프로그래밍)에서 JSON 데이터 직렬화의 어려움을 설명합니다. 예시를 통해, OOP에서 각 엔드포인트마다 JSON 변환을 위한 클래스를 반복적으로 생성하고 코드를 작성해야 하는 복잡성을 보여줍니다. OOP에서는 데이터가 클래스 멤버에 묶여 있어 일반적인 데이터 접근이 어렵기 때문에, 이러한 단순 작업이 어렵게 느껴진다고 지적합니다.

## 상세 핵심 내용

이 문서는 객체 지향 프로그래밍(OOP)에서 JSON 데이터 직렬화의 복잡성을 설명합니다. 
주어진 예시는 REST API를 통해 Klafim의 도서관 관리 시스템에 접근하는 /search 엔드포인트를 구현하는 꿈을 통해 OOP의 문제점을 보여줍니다. 
Theo는 각 엔드포인트마다 JSON 변환을 위한 클래스(Query, Controller, Result)를 반복적으로 생성해야 하는 어려움에 직면합니다. 
OOP에서는 데이터가 클래스 멤버에 묶여 있어 데이터를 일반적인 방식으로 접근하기 어렵기 때문에 JSON 직렬화 및 역직렬화가 어렵습니다. 
이러한 문제는 OOP에서 데이터를 다루는 방식의 제한에서 기인하며, JSON 직렬화와 역직렬화와 같은 간단한 작업도 복잡하게 만듭니다.
향후 DOP(Data-Oriented Programming) 접근 방식을 통해 이 문제를 해결할 수 있음을 암시합니다.
OOP 언어는 반사(reflection)나 코드의 장황함으로 이 문제를 어느 정도 해결하려 하지만, 근본적인 해결책은 되지 못합니다.

## 주요 화제

*   **JSON을 이용한 REST API 구현**: Klafim의 도서관 관리 시스템을 REST API로 만들 때 JSON을 사용해야 하는 상황을 예시로 제시합니다.
*   **/search 엔드포인트 구현**: JSON 형식의 쿼리를 받아 JSON 형식으로 결과를 반환하는 /search 엔드포인트 구현 과정과 관련된 내용이 포함되어 있습니다.
*   **OOP(객체 지향 프로그래밍)에서의 데이터 직렬화 어려움**: OOP에서 JSON 직렬화/역직렬화에 필요한 클래스 추가와 코드 작성의 어려움을 지적합니다.
*   **클래스 기반의 데이터 구조 문제**: OOP에서 데이터가 클래스 멤버로 고정되어 일반적인 데이터 접근이 어려운 문제를 언급합니다.
*   **JSON 직렬화/역직렬화의 반복 작업**: 다른 엔드포인트(예: /add-book-item) 구현 시 JSON 처리 코드를 반복해서 작성해야 하는 문제를 지적합니다.
*   **데이터 직렬화의 단순함과 OOP의 복잡성**: JSON 직렬화가 데이터 필드 순회 및 연결과 같이 간단한 작업임에도 불구하고 OOP에서는 복잡하게 처리해야 하는 이유를 설명합니다.
*   **DOP(Data-Oriented Programming)의 가능성**: DOP가 JSON 직렬화/역직렬화를 일반적인 방식으로 처리하는 방법을 제공할 수 있음을 암시합니다.
*   **OOP의 해결 방법**: Reflection 또는 코드의 중복성으로 OOP에서 JSON 변환의 어려움을 어느 정도 완화할 수 있다는 것을 언급합니다.

Complexity of object-oriented programming
 The bad news is that Theo would have to repeat the same process for every end-
point of the system. Each time he encounters a new kind of JSON input or output,
he would have to create a new class and write code. Theo's dream is turning into a
nightmare!
Suddenly, his phone rings, next to where he was resting his head on the desk. As Theo
wakes up, he realizes that Nancy never asked for JSON. It was all a dream . . . a really bad
dream!

TIP
In OOP, data serialization is difficult.
It's quite frustrating that handling JSON serialization and deserialization in OOP
requires the addition of so many classes and writing so much code—again and again!
The frustration grows when you consider that serializing a search query, a book item
query, or any query is quite similar. It comes down to
Going over data fields.
Concatenating the name of the data fields and the value of the data fields, sepa-
rated by a comma.
Why is such a simple thing so hard to achieve in OOP? In OOP, data has to follow a
rigid shape defined in classes, which means that data is locked in members. There is
no simple way to access data generically.

TIP
In OOP, data is locked in classes as members.
We will refine later what we mean by generic access to the data, and we will see how
DOP provides a generic way to handle JSON serialization and deserialization. Until
then, you will have to continue suffering. But at least you are starting to become aware
of this suffering, and you know that it is avoidable.
 NOTE
Most OOP programming languages alleviate a bit of the difficulty involved
in the conversion from and to JSON. It either involves reflection, which is definitely a
complex thing, or code verbosity.
