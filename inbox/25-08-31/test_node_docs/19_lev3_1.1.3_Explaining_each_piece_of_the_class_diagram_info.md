이 문서는 객체 지향 프로그래밍(OOP)에서의 클래스 다이어그램 구성 요소를 설명합니다. Library 클래스는 시스템의 루트 클래스이며, Member, Librarian, Catalog 객체를 소유합니다. 각 클래스는 특정 역할과 기능을 가지며, Book, BookItem, BookLending 객체와의 관계를 통해 도서관 시스템을 구성합니다.

## 상세 핵심 내용
이 문서는 객체 지향 프로그래밍(OOP) 설계의 클래스 다이어그램을 설명하며, 라이브러리 시스템을 구성하는 다양한 클래스와 그 관계를 자세히 보여줍니다.  Library 클래스는 시스템의 루트로, Member, Librarian, Catalog 객체를 소유합니다.  Librarian과 Member 클래스는 User 클래스를 상속받아 사용자 정보를 관리하며, 각각 멤버의 책 대출, 반납, 차단 등의 기능과 사서의 멤버 관리, 도서 추가 등의 기능을 정의합니다.  Catalog 클래스는 책 검색과 추가를 담당하며 Book 객체를 소유합니다.  Book 클래스는 id와 제목을 가지며 Author 객체와 BookItem 객체를 연결합니다.  BookItem 클래스는 책의 복사본을 나타내며 BookLending 객체를 소유하며 대출 기능을 수행합니다. 각 클래스는 데이터 멤버와 코드(행동)를 가지며, 서로 상호작용하여 라이브러리 시스템을 구현합니다.

## 상세 정보
## 1.1.3 클래스 다이어그램 각 부분 설명

**문서 개요:** 이 문서는 객체 지향 프로그래밍(OOP)의 클래스 다이어그램에 대한 설명 부분입니다. 특히 라이브러리 시스템을 예시로 각 클래스의 역할, 데이터 멤버, 코드(행동)를 상세히 설명합니다.

**1. 주요 클래스:**

*   **Library (라이브러리):**
    *   **역할:** 라이브러리 시스템의 루트 클래스
    *   **데이터 멤버:**
        *   Multiple Member objects (여러 회원 객체)
        *   Multiple Librarian objects (여러 사서 객체)
        *   A single Catalog object (단일 카탈로그 객체)
    *   **코드(행동):**  자체적으로는 아무런 기능을 수행하지 않고, 소유 객체들에게 기능을 위임함.

*   **User (사용자):**
    *   **역할:** 라이브러리 사용자를 나타내는 추상 클래스 (Librarian과 Member의 부모 클래스)
    *   **데이터 멤버:**
        *   id (ID)
        *   email (이메일)
        *   password (비밀번호)
    *   **코드(행동):**
        *   login (로그인)

*   **Member (회원):**
    *   **역할:** 라이브러리 회원을 나타내는 클래스
    *   **상속:** User 클래스 상속
    *   **데이터 멤버:** User의 속성 상속
    *   **코드(행동):**
        *   checkout (도서 대출)
        *   returnBook (도서 반납)
        *   block (계정 차단)
        *   unblock (계정 차단 해제)
        *   isBlocked (차단 여부 확인)
        *   BookLending 객체 소유
        *   BookItem 객체를 사용하여 checkout 기능 구현

*   **Librarian (사서):**
    *   **역할:** 사서를 나타내는 클래스
    *   **상속:** User 클래스 상속
    *   **데이터 멤버:** User의 속성 상속
    *   **코드(행동):**
        *   blockMember (회원 차단)
        *   unblockMember (회원 차단 해제)
        *   getBookLendings (회원의 도서 대출 목록 가져오기)
        *   addBookItem (도서 추가)
        *   Member 객체를 사용하여 blockMember, unblockMember, getBookLendings 기능 구현
        *   BookItem 객체를 사용하여 checkout 기능 구현
        *   BookLending 객체를 사용하여 getBookLendings 기능 구현

*   **Catalog (카탈로그):**
    *   **역할:** 도서 관리를 담당하는 클래스
    *   **데이터 멤버:**  multiple Book objects (여러 Book 객체 소유)
    *   **코드(행동):**
        *   search (도서 검색)
        *   addBookItem (도서 추가)
        *   Librarian 객체를 사용하여 addBookItem 기능 구현

*   **Book (도서):**
    *   **역할:** 도서를 나타내는 클래스
    *   **데이터 멤버:**
        *   id (ID)
        *   title (제목)
        *   Multiple Author objects (여러 Author 객체와 연관)
        *   Multiple BookItem objects (여러 BookItem 객체 소유)

*   **BookItem (도서 개별 사본):**
    *   **역할:** 도서의 개별 사본을 나타내는 클래스
    *   **데이터 멤버:**
        *   id (ID)
        *   libId (물리적 라이브러리 ID)
        *   Multiple BookLending objects (여러 BookLending 객체 소유)
    *   **코드(행동):**
        *   checkout (대출 가능)

**2. 클래스 간 관계:**

*   User <- Librarian (상속)
*   User <- Member (상속)
*   Library -> Catalog (단일 관계)
*   Library -> Member (여러 관계)
*   Library -> Librarian (여러 관계)
*   Catalog -> Book (여러 관계)
*   Book -> Author (여러 관계)
*   Book -> BookItem (여러 관계)
*   Member -> BookLending (여러 관계)
*   BookItem -> BookLending (여러 관계)
*   Librarian -> Member (사용 관계)
*   Catalog -> Librarian (사용 관계)

**3. 기타 정보:**

*   **용어:** code와 behavior는 동일한 의미로 사용됨.
*   **참고:** 이 문서는 UML 클래스 다이어그램의 각 요소를 설명하며, 라이브러리 시스템을 예시로 사용.

## 주요 화제
*   클래스 다이어그램의 각 요소 설명
*   Library 클래스: 시스템의 루트 클래스, 다른 객체들을 소유 (Member, Librarian, Catalog)
*   User, Librarian, Member 클래스: 상속 관계, User 클래스는 기본 정보 (id, email, password) 포함
*   Member 클래스: User 클래스 상속, 도서 대출/반납, 차단/해제 기능, BookLending 객체 소유, BookItem 사용
*   Librarian 클래스: User 클래스 상속, Member 차단/해제, 대출 기록 확인, 도서 추가 기능, Member, BookItem, BookLending 사용
*   Catalog 클래스: 도서 관리, 검색, 도서 추가 기능, Librarian 사용, Book 객체 소유
*   Book 클래스: id, title 정보, Author 객체와 연관, BookItem 객체 소유
*   BookItem 클래스: 책의 복사본 표현, id, libId 정보, BookLending 객체 소유, checkout 기능

LIBRARIAN, MEMBER, AND USER CLASSES
Librarian and Member both derive from User. Figure 1.7 shows this relation.
The User class represents a user of the library:
In terms of data members, it sticks to the bare minimum: it has an id, email,
and password (with no security and encryption for now).
In terms of code, it can log in via login.
The Member class represents a member of the library:
It inherits from User.
In terms of data members, it has nothing more than User.
In terms of code, it can
– Check out a book via checkout.
– Return a book via returnBook.
– Block itself via block.
– Unblock itself via unblock.
– Answer if it is blocked via isBlocked.
It owns multiple BookLending objects.
It uses BookItem in order to implement checkout.

The Librarian class represents a librarian:
It derives from User.
In terms of data members, it has nothing more than User.
In terms of code, it can
– Block and unblock a Member.
– List the member's book lendings via getBookLendings.
– Add book items to the library via addBookItem.
It uses Member to implement blockMember, unblockMember, and getBook-
Lendings.
It uses BookItem to implement checkout.
It uses BookLending to implement getBookLendings. 
THE CATALOG CLASS
The Catalog class is responsible for the management of the books. Figure 1.8 shows
the relation among the Catalog, Librarian, and Book classes. In terms of code, a
Catalog object can
Search books via search.
Add book items to the library via addBookItem.
A Catalog object uses Librarian in order to implement addBookItem. In terms of
data, a Catalog owns multiple Book objects. 
THE BOOK CLASS
Figure 1.9 presents the Book class. In terms of data, a Book object
Should have as its bare minimum an id and a title.
Is associated with multiple Author objects (a book might have multiple authors).
Owns multiple BookItem objects, one for each copy of the book.

THE BOOKITEM CLASS
The BookItem class represents a book copy, and a book could have many copies. In
terms of data, a BookItem object
Should have as its bare minimum data for members: an id and a libId (for its

Owns multiple BookLending objects, one for each time the book is lent.
In terms of code, a BookItem object can be checked out via checkout.
