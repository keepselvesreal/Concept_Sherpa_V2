## 핵심 내용
이 문서는 UML 다이어그램의 기본 개념을 소개합니다. 특히, 객체 지향 프로그래밍(OOP)에서 사용되는 네 가지 주요 관계 유형인 구성, 연관, 상속 및 사용을 설명합니다. 각 관계 유형을 식별하는 방법을 제시하고, 이를 예시를 통해 설명하며, UML 다이어그램을 이해하는 데 필요한 핵심적인 내용들을 요약합니다.

## 상세 핵심 내용
UML 101 문서는 객체 지향 설계(OOP)의 기본 개념과 UML 다이어그램의 주요 구성 요소를 소개합니다. 이 문서에서는 클래스 다이어그램을 예시로 들어, 구성(composition), 연관(association), 상속(inheritance), 사용(usage)의 네 가지 주요 관계를 설명합니다. 구성 관계는 한 객체가 소멸되면 다른 객체도 함께 소멸되는 경우를 나타내며, 연관 관계는 객체들이 독립적인 생명 주기를 갖는 경우를 의미합니다. 상속은 일반적인 속성을 물려받는 관계를, 사용 관계는 한 클래스가 다른 클래스의 메서드를 호출하는 경우를 나타냅니다. 다이어그램에서 다양한 화살표와 기호를 통해 이러한 관계를 시각적으로 표현하여, 객체 간의 상호 작용과 시스템 구조를 파악할 수 있도록 돕습니다.

    *   **메서드 (Methods):** 각 클래스의 동작 (예: `Librarian` 클래스의 `blockMember()`, `getBookLendingsOfMember()`)
    *   **관계 (Relationships):** 클래스 간의 연결 (연관 관계, 상속, 사용 관계, 포함 관계)

*   **클래스 다이어그램의 목적:** 시스템의 구조를 시각적으로 표현하여 이해도를 높임

### 4. UML 관계 유형 설명

*   **4가지 주요 관계:**
    *   **Composition (포함 관계):**
        *   **정의:** 한 객체가 다른 객체를 소유하며, 소유 객체가 사라지면 소유된 객체도 함께 사라짐.
        *   **표기:** 한쪽 끝에 채워진 다이아몬드(♦)가 있고, 다른 쪽 끝에 별표(\*)가 있을 수 있음 (다수 포함 관계).
        *   **예시:** `Library`가 `Catalog`를 소유 (one-to-one composition), `Library`가 여러 `Member`를 소유 (one-to-many composition)
        *   **그림 1.2:** 포함 관계 예시 설명 (Library - Catalog, Library - Member)
    *   **Association (연관 관계):**
        *   **정의:** 객체들이 서로 독립적으로 존재하며, 서로의 생명 주기에 영향을 미치지 않음.
        *   **표기:** 양쪽 끝에 빈 다이아몬드(◊)가 있고, 각 끝에 별표(\*)가 있을 수 있음 (다대다 연관).
        *   **예시:** `Book`과 `Author` (한 책은 여러 저자를 가질 수 있고, 한 저자는 여러 책을 쓸 수 있음).
        *   **그림 1.3:** 다대다 연관 관계 예시 설명 (Book - Author)
    *   **Usage (사용 관계):**
        *   **정의:** 한 클래스가 다른 클래스의 메서드를 호출.
        *   **표기:** 점선 화살표(--- >)
        *   **예시:** `Librarian`의 `blockMember()` 메서드가 `Member`의 `block()` 메서드를 호출.
        *   **그림 1.4:** 사용 관계 예시 설명 (Librarian - Member)
    *   **Inheritance (상속 관계):**
        *   **정의:** 한 클래스가 다른 클래스의 속성과 메서드를 상속받음.
        *   **표기:** 빈 삼각형(△)이 있는 실선 화살표
        *   **예시:** `Member` 클래스가 `User` 클래스를 상속.
        *   **그림 1.5:** 상속 관계 예시 설명 (Member - User)

### 5.  핵심 팁 (TIP)

*   **Composition:** 한 객체가 사라지면, 포함된 객체도 사라진다. (plain diamond)
*   **Association:** 객체들은 독립적인 생명 주기를 가진다. (empty diamond)
*   **Usage:** 점선 화살표로 표시 (dashed arrow)
*   **Inheritance:** 빈 삼각형이 있는 실선 화살표로 표시 (plain arrow with an empty triangle)
