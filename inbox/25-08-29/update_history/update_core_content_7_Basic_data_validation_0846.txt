구성노드1(7.1 Data validation in DOP): DOP에서 데이터 유효성 검사는 시스템 경계에서 가장 중요하며, 클라이언트, 데이터베이스, 웹 서비스 간의 데이터 교환에서 유효성 검사를 수행합니다. 시스템 경계에서 유효한 데이터를 보장하면 내부 데이터 유효성 검사의 필요성을 줄여 오류를 방지하고 시스템의 안정성을 높일 수 있습니다.
구성노드2(7.2 JSON Schema in a nutshell): JSON Schema는 데이터를 표현하는 방식과 분리하여 데이터의 유효성을 검증하기 위한 스키마를 정의하는 언어입니다. JSON Schema는 데이터 타입, 필수 필드, 허용된 값 목록 등 다양한 유효성 검사 규칙을 표현할 수 있으며, 다양한 프로그래밍 언어에서 사용할 수 있는 유효성 검사 라이브러리를 제공합니다.
구성노드3(7.3 Schema flexibility and strictness): JSON Schema는 기본적으로 맵 필드가 선택 사항이며, `required` 배열을 통해 필수 필드를 지정합니다. `additionalProperties`를 false로 설정하면 스키마에 정의되지 않은 필드를 허용하지 않아 응답의 엄격성을 높일 수 있습니다. 일반적으로 응답은 엄격하게, 요청은 유연하게 처리하는 것이 좋습니다.
구성노드4(7.4 Schema composition): Schema Composition은 JSON Schema를 조합하여 복잡한 데이터 유효성 검사를 수행하는 기술입니다. `allOf` (AND), `anyOf` (OR), `oneOf` 와 같은 키워드를 사용하여 여러 스키마를 결합, 필드의 필수 여부와 같은 다양한 조건을 표현할 수 있습니다. 이를 통해 클래스를 사용하는 것보다 더 유연하고 강력한 데이터 유효성 검사가 가능해집니다.
구성노드5(7.5 Details about data validation failures): 데이터 유효성 검사 실패 시, 실패 이유에 대한 상세 정보를 얻을 수 있으며, 누락된 필수 필드 이름이나 예상과 다른 데이터 유형 등의 구체적인 오류 내용을 파악할 수 있다. Ajv와 같은 라이브러리는 오류를 배열 형태로 제공하며, `allErrors: true` 옵션을 사용하여 여러 오류를 한 번에 감지할 수 있다.
