## 7.4 Schema Composition 상세 정보 분석 및 새로운 내용

이 챕터에서는 JSON Schema를 이용한 데이터 유효성 검증, 특히 스키마 구성(Schema Composition)이라는 고급 기술을 소개합니다. 다음은 본문의 핵심 내용에서 파생된 새로운 상세 정보와 추가 내용입니다.

**1. Open Library Books API 응답 분석:**

*   **실제 API 응답 예시:** `Watchmen` 책의 JSON 응답 예시를 통해 실제 API에서 반환되는 데이터 구조를 보여줍니다. 이 예시는 `publishers`, `number_of_pages`, `weight`, `physical_format`, `subjects`, `isbn_13`, `title`, `isbn_10`, `publish_date`, `physical_dimensions` 등 다양한 필드를 포함하고 있습니다.
*   **`isbn_10`과 `isbn_13`의 문제점:** `isbn_10`과 `isbn_13` 필드는 둘 다 필수적인 것은 아니지만, 적어도 하나는 존재해야 합니다. 이 문제점은 JSON Schema의 기본 기능만으로는 해결하기 어렵다는 것을 보여줍니다.
*   **`isbn_10`과 `isbn_13`의 규칙:** 책의 출판 연도에 따라 `isbn_10` 또는 `isbn_13`이 사용됩니다. 2007년 이전에 출판된 책은 `isbn_10`을, 2007년 이후에 출판된 책은 `isbn_13`을, 두 버전 모두 있는 경우도 있습니다.

**2. 스키마 구성 (Schema Composition)의 개념:**

*   **AND, OR, NOT 연산과의 비유:** 스키마 구성은 논리 연산(AND, OR, NOT)과 유사한 방식으로 스키마를 결합하는 방법입니다. 이를 통해 복잡한 데이터 유효성 검증 규칙을 표현할 수 있습니다.
*   **`allOf`, `anyOf`, `oneOf`:** JSON Schema에서는 다음과 같은 키워드를 사용하여 스키마 구성을 구현합니다.
    *   `allOf`: 모든 하위 스키마를 충족해야 합니다 (AND).
    *   `anyOf`: 최소한 하나의 하위 스키마를 충족해야 합니다 (OR).
    *   `oneOf`: 정확히 하나의 하위 스키마를 충족해야 합니다.
*   **예시: `Open Library` API 응답 스키마 구성:**
    *   `basicBookInfoSchema`: `title` 필드만 필수인 기본 정보 스키마입니다.
    *   `mandatoryIsbn13`: `isbn_13` 필드가 필수인 스키마입니다.
    *   `mandatoryIsbn10`: `isbn_10` 필드가 필수인 스키마입니다.
    *   `bookInfoSchema`: `basicBookInfoSchema`와 `mandatoryIsbn13` 또는 `mandatoryIsbn10` 중 하나를 충족해야 합니다. (`basicBookInfoSchema AND (mandatoryIsbn13 OR mandatoryIsbn10)`)

**3. 스키마 구성의 장점:**

*   **표현력 향상:** 스키마 구성을 통해 클래스로 데이터를 표현할 때보다 더 복잡하고 유연한 데이터 유효성 검증 규칙을 표현할 수 있습니다.
*   **유지보수성 향상:** 여러 개의 작은 스키마를 조합하여 복잡한 스키마를 구성함으로써, 각 스키마의 재사용성을 높이고 유지보수를 용이하게 합니다.

**4. 추가 정보:**

*   **`validate()` 함수:** Listing 7.19에서 `validate()` 함수가 사용되었지만, 이 함수의 구현이나 사용 방법에 대한 구체적인 정보는 제공되지 않습니다. (책의 앞부분에 이미 정의되어 있거나, 외부 라이브러리를 사용한다고 유추 가능)
*   **데이터 유효성 검증 실패 시 문제점:** 유효성 검증 실패 시, 문제점을 명확하게 알 수 없다는 점이 지적됩니다. (자세한 내용은 12장에서 다룰 예정)

**5. 코드 예시 분석:**

*   **`basicBookInfoSchema`:** 기본 정보 스키마는 다양한 필드의 `type`을 정의하지만, `required` 필드는 `title`만 포함합니다.
*   **`mandatoryIsbn13` 및 `mandatoryIsbn10`:** `isbn_13` 또는 `isbn_10` 필드만을 필수 요소로 지정하는 간단한 스키마입니다.
*   **`bookInfoSchema`:**  `allOf`와 `anyOf`를 사용하여 세 개의 스키마를 조합합니다.

**6. 추가적인 고려 사항:**

*   **API 문서의 중요성:** Open Library Books API와 같은 외부 API를 사용할 때는 API 문서를 참조하여 응답 데이터의 구조와 규칙을 정확히 파악해야 합니다.
*   **스키마 검증 라이브러리:** JSON Schema를 실제 구현하고 검증하기 위해서는 관련 라이브러리를 사용해야 합니다 (예: ajv, jsonschema).
*   **예외 처리:** 데이터 유효성 검증 실패 시, 사용자에게 적절한 오류 메시지를 표시하고, 데이터 처리 흐름을 제어하는 예외 처리 메커니즘을 구현해야 합니다.
