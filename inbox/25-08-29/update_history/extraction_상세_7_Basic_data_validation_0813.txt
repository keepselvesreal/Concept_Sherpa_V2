At first glance, it may seem that embracing DOP means accessing data without validat-
ing it and engaging in wishful thinking, where data is always valid. In fact, data valida-
tion is not only possible but recommended when we follow data-oriented principles.
This chapter illustrates how to validate data when data is represented with
generic data structures. It focuses on data validation occurring at the boundaries of
the system, while in part 3, we will deal with validating data as it flows through the
system. This chapter is a deep dive into the fourth principle of DOP.
PRINCIPLE #4 Separate data schema from data representation.

## 7 Basic Data Validation - 추가 상세 정보 및 새로운 내용 정리

다음은 7 Basic data validation 내용을 바탕으로, 기존 내용을 보완하고 새로운 상세 정보, 예시, 구현 방법을 추가하여 정리한 내용입니다.

**1. 시스템 경계 (System Boundaries)의 중요성 강조 및 구체적인 예시 추가:**

*   **핵심:** 시스템 경계에서 데이터 유효성 검사의 중요성을 재차 강조하며, 잘못된 데이터가 시스템 내부로 유입되는 것을 막는 데 초점을 맞춥니다. 시스템 경계는 데이터가 시스템 외부와 상호작용하는 지점으로 정의됩니다.
*   **구체적인 예시:**
    *   웹 서버의 경우, 클라이언트 요청 (예: 웹 브라우저, API 호출)과 서버 응답, 데이터베이스, 외부 웹 서비스 (예: 결제 시스템, 다른 API) 간의 데이터 교환 지점이 시스템 경계에 해당합니다.
    *   모바일 앱의 경우, API 서버와의 통신, 로컬 데이터베이스 접근, 사용자의 입력 (예: 폼 데이터)이 시스템 경계가 될 수 있습니다.
*   **추가 정보:** 시스템 경계에서 유효성 검사를 철저히 하면, 시스템 내부의 데이터 무결성을 크게 향상시킬 수 있습니다.

**2. JSON Schema 상세 설명 및 추가 기능 소개:**

*   **핵심:** JSON Schema를 사용하여 데이터 구조를 정의하고, 데이터 유효성 검사를 수행하는 방법을 자세히 설명합니다. JSON Schema의 기본 구조, 데이터 타입 정의, 속성(properties), 필수 필드(required), 열거형(enum) 등을 예시와 함께 보여줍니다.
*   **상세 설명:**
    *   **데이터 타입:** `string`, `number`, `integer`, `boolean`, `array`, `object` 등 JSON Schema에서 지원하는 다양한 데이터 타입을 소개합니다.
    *   **속성 (properties):** 객체의 각 필드에 대한 스키마를 정의하는 데 사용됩니다. 각 속성은 타입(type)과 추가적인 검증 규칙 (예: `enum`, `minimum`, `maximum`, `minLength`, `maxLength`, `pattern` 등)을 가질 수 있습니다.
    *   **필수 필드 (required):** 객체 내에서 반드시 존재해야 하는 필드를 지정합니다.
    *   **열거형 (enum):** 허용되는 값의 목록을 지정하여 특정 필드가 가질 수 있는 값을 제한합니다.
    *   **추가 속성 (additionalProperties):** 스키마에 정의되지 않은 추가적인 필드를 허용할지 여부를 설정합니다. `false`로 설정하면 스키마에 정의된 필드만 허용됩니다.
*   **추가 정보:** JSON Schema는 데이터 유효성 검사를 위한 강력한 도구이며, 다양한 제약 조건을 표현할 수 있습니다. 예를 들어, 숫자의 범위를 제한하거나, 문자열이 특정 정규 표현식과 일치하는지 확인할 수 있습니다.

**3. JSON Schema의 유연성 및 엄격함 (Flexibility and Strictness) 심층 분석:**

*   **핵심:** JSON Schema의 유연성과 엄격함 사이의 균형을 강조하고, 상황에 따라 적절한 설정을 사용하는 방법을 설명합니다. 특히, `additionalProperties` 속성을 사용하여 추가적인 필드 허용 여부를 제어하는 방법을 자세히 다룹니다.
*   **상세 설명:**
    *   **요청 (Request) vs. 응답 (Response):** 일반적으로, 클라이언트 요청에는 `additionalProperties`를 `true`로 설정하여 유연하게 받아들이고, 서버 응답에는 `additionalProperties`를 `false`로 설정하여 엄격하게 검증하는 것이 좋습니다.
    *   **이유:** 서버는 응답 데이터를 완벽하게 제어할 수 있지만, 클라이언트의 요청은 예측하기 어려울 수 있습니다. 유연한 요청 처리는 클라이언트의 오류를 허용하고, 사용성을 향상시킬 수 있습니다. 엄격한 응답 검증은 서버가 보내는 데이터의 일관성을 보장합니다.
*   **구체적인 예시:**
    *   **요청:** 검색 요청에서 사용자가 불필요한 필드를 포함하더라도 서버는 이를 무시하고 검색을 수행할 수 있습니다.
    *   **응답:** 검색 결과 응답에서 정의되지 않은 필드가 포함되면, 클라이언트는 예기치 않은 동작을 하거나, 오류가 발생할 수 있습니다.

**4. JSON Schema 컴포지션 (Composition) - 스키마 조합 및 활용:**

*   **핵심:** JSON Schema의 강력한 기능 중 하나인 스키마 컴포지션을 소개합니다. `allOf`, `anyOf`, `oneOf` 키워드를 사용하여 복잡한 데이터 구조를 정의하는 방법을 설명합니다.
*   **상세 설명:**
    *   `allOf`: 모든 하위 스키마를 만족해야 합니다 (AND).
    *   `anyOf`: 최소한 하나의 하위 스키마를 만족해야 합니다 (OR).
    *   `oneOf`: 정확히 하나의 하위 스키마를 만족해야 합니다 (XOR).
*   **구체적인 예시:**
    *   **API 응답:** `isbn_10` 또는 `isbn_13` 중 적어도 하나는 반드시 존재해야 하는 경우, `anyOf`를 사용하여 이를 표현할 수 있습니다.
    *   **복잡한 데이터 구조:** 여러 스키마를 조합하여 더 복잡한 데이터 구조를 정의할 수 있습니다.
*   **추가 정보:** 스키마 컴포지션은 코드의 재사용성을 높이고, 데이터 구조의 변경에 유연하게 대응할 수 있도록 돕습니다.

**5. 데이터 유효성 검사 실패 시 상세 정보 획득:**

*   **핵심:** 데이터 유효성 검사 실패 시, 오류의 상세 정보를 얻는 방법을 설명합니다. 오류 메시지, 실패한 필드 이름, 예상된 데이터 타입 등을 포함하여, 문제 해결에 필요한 정보를 제공합니다.
*   **상세 설명:**
    *   **오류 정보 (Error Information):** JSON Schema 검사 라이브러리는 일반적으로 오류 목록을 제공합니다. 각 오류는 실패한 필드의 위치, 기대하는 데이터 타입, 오류 메시지 등을 포함합니다.
    *   **라이브러리별 구현 차이:** 각 JSON Schema 검사 라이브러리는 오류 정보 접근 방식이 다를 수 있습니다. 예를 들어, JavaScript의 Ajv 라이브러리는 `ajv.errors` 속성을 통해 오류 정보를 제공합니다.
    *   **오류 메시지 변환:** Ajv와 같은 라이브러리는 오류 정보를 사람이 읽기 쉬운 형식으로 변환하는 유틸리티 함수 (예: `ajv.errorsText()`)를 제공합니다.
*   **구체적인 예시:**
    *   **필수 필드 누락:** "title" 필드가 누락된 경우, "data must have required property 'title'"와 같은 오류 메시지를 얻을 수 있습니다.
    *   **데이터 타입 불일치:** "title" 필드가 문자열이 아닌 숫자인 경우, "data/title must be string"과 같은 오류 메시지를 얻을 수 있습니다.
*   **추가 정보:** 상세한 오류 정보는 디버깅을 용이하게 하고, 사용자에게 더 친절한 오류 메시지를 제공하는 데 도움이 됩니다.

**6. Ajv를 사용한 JSON Schema 검사 예시 (JavaScript):**

*   **핵심:** JavaScript 환경에서 가장 널리 사용되는 JSON Schema 검사 라이브러리인 Ajv를 사용하여 데이터 유효성 검사를 수행하는 구체적인 예시를 제공합니다.
*   **구현 방법:**
    1.  **Ajv 설치:** `npm install ajv` 명령어를 사용하여 Ajv를 설치합니다.
    2.  **스키마 정의:** JSON Schema를 사용하여 데이터 구조를 정의합니다.
    3.  **검사 인스턴스 생성:** `new Ajv()`를 사용하여 Ajv 인스턴스를 생성합니다. `allErrors: true` 옵션을 사용하여 모든 오류를 수집할 수 있습니다.
    4.  **유효성 검사:** `ajv.validate(schema, data)` 함수를 사용하여 데이터를 검사합니다.
    5.  **오류 처리:** `ajv.errors` 속성을 통해 오류 정보를 확인하고, `ajv.errorsText(ajv.errors)` 함수를 사용하여 사람이 읽기 쉬운 형식으로 변환합니다.
*   **구체적인 코드 예시:**
    ```javascript
    const Ajv = require('ajv');
    const ajv = new Ajv({ allErrors: true }); // allErrors 옵션으로 모든 오류 수집

    const searchBooksRequestSchema = {
      "type": "object",
      "properties": {
        "title": { "type": "string" },
        "fields": {
          "type": "array",
          "items": { "type": "string" }
        }
      },
      "required": ["title", "fields"]
    };

    const validSearchBooksRequest = {
      "title": "habit",
      "fields": ["title", "weight", "number_of_pages"]
    };

    const invalidSearchBooksRequest = {
      "myTitle": "habit", // title 필드 오류
      "fields": [1, 2]    // fields 배열 요소 타입 오류
    };

    const validate = ajv.compile(searchBooksRequestSchema); // 스키마 컴파일
    const validResult = validate(validSearchBooksRequest);
    const invalidResult = validate(invalidSearchBooksRequest);

    if (!validResult) {
      console.log("유효성 검사 실패 (유효한 요청):", ajv.errorsText(validate.errors));
    } else {
      console.log("유효성 검사 성공 (유효한 요청)");
    }

    if (!invalidResult) {
      console.log("유효성 검사 실패 (유효하지 않은 요청):", ajv.errorsText(validate.errors));
    } else {
      console.log("유효성 검사 성공 (유효하지 않은 요청)");
    }
    ```

**8. 7.5. Details about data validation failures 예시 보강:**

*   **오류 메시지 예시 추가:**
    *   `"data must have required property 'title'"` (필수 필드 누락)
    *   `"data/fields/0 must be string"` (배열 요소 타입 불일치)
    *   `"data must match exactly one schema in oneOf"` (oneOf 조건 불만족)
    *   `"data must NOT have additional properties"` (additionalProperties = false, 추가 프로퍼티 존재)
    *   `"data/title must match pattern \"^[a-zA-Z0-9\\s]+$\""` (정규식 불일치)

**9. JSON Schema cheat sheet 및 유효한 데이터 예시 보강:**

*   **Cheat Sheet 추가 정보:**
    *   `"minimum": 숫자`, `"maximum": 숫자` (최솟값, 최댓값)
    *   `"minLength": 숫자`, `"maxLength": 숫자` (최소 길이, 최대 길이)
    *   `"pattern": 정규식` (정규식 일치)
    *   `"format": "date-time"`, `"format": "email"` 등 (특정 형식 검사)
    *   `"default": 값` (기본값 설정)
    *   `"nullable": true` (null 값 허용)
*   **유효한 데이터 예시 보강:**
    *   다양한 데이터 타입 및 제약 조건을 만족하는 예시 추가. (예: 숫자 범위, 문자열 길이 제한, 정규 표현식 일치 등)
    *   스키마 컴포지션을 활용한 유효한 데이터 예시.

**10. 데이터 유효성 검사의 장점 요약:**

*   **데이터 무결성 보장:** 잘못된 데이터가 시스템 내부로 유입되는 것을 방지하여 데이터의 정확성과 일관성을 유지합니다.
*   **오류 감소 및 디버깅 용이성:** 잘못된 데이터로 인한 오류 발생을 줄이고, 오류 발생 시 원인을 빠르게 파악할 수 있도록 도와줍니다.
*   **보안 강화:** 악의적인 데이터 입력으로부터 시스템을 보호합니다 (예: SQL injection, XSS 공격 방지).
*   **코드 품질 향상:** 데이터 유효성 검사는 코드의 가독성과 유지보수성을 향상시키고, 코드의 복잡성을 줄입니다.
*   **API 안정성 확보:** API를 사용하는 클라이언트 및 외부 서비스와의 데이터 교환에서 안정성을 보장합니다.
