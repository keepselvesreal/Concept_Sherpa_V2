## 🏗️ 아키텍처 변경사항

### AIProvider 인터페이스 개선
```python
# 기존 메서드 (제거)
async def query(self, prompt, additional_data)
async def query_with_native_session(self, prompt, session_info, additional_data)

# 새로운 메서드 (추가)
async def query_single_request(self, prompt, additional_data)          # 일회성 쿼리
async def query_with_persistent_session(self, prompt, session_info, additional_data)  # 세션 유지
```

### ContentDocumentService 완전 재구성
```python
# 기존 메서드들 (모두 제거)
async def detect_section_content(self, ...)  # 기존 복잡한 구현
async def _analyze_sections_with_session(self, ...)
async def _extract_content_with_session(self, ...)
# ... 기타 모든 기존 메서드들

# 새로운 메서드들 (새로 구현)
async def detect_section_content(self, ...)   # 단순화된 일회성 분석 + fallback 로직
async def extract_section_content(self, ...)  # 단순화된 멀티턴 추출 + fallback 로직
def _parse_json_response(self, ...)           # 지원 메서드
def _save_content_json(self, ...)             # 지원 메서드  
def _save_section_files(self, ...)            # 지원 메서드
```

### IntegratedNodeGenerationStage 메서드 변경
```python
# 메서드명 변경
extract_content_nodes() → generate_content_documents()

# 처리 로직 변경
기존: 복잡한 분석 → content.json 저장
새로운: detect_section_content() + extract_section_content() → content.json + sections/ 폴더 + unified_info_docs/ 폴더
```

## 🎛️ 핵심 기능 변경

### 1. 섹션 내용 분석 (detect_section_content)
- **입력**: 장 전체 내용 + 섹션 목록
- **처리**: 일회성 AI 쿼리로 모든 섹션의 has_content 판단
- **출력**: has_content 필드가 추가된 섹션 목록
- **저장**: content.json (id, title, level, has_content 필드만)

### 2. 섹션 내용 추출 (extract_section_content)  
- **입력**: has_content=true인 섹션들 + 장 전체 내용
- **처리**: 멀티턴 세션으로 각 섹션별 내용 추출
- **출력**: 섹션별 마크다운 내용 목록
- **저장**: sections/{섹션제목}.md 파일들

### 3. 문서 통합 (integrate_documents)
- **입력**: node_info_docs + sections 폴더
- **처리**: 섹션 제목으로 매칭하여 노드 문서와 섹션 내용 통합
- **출력**: unified_info_docs 폴더에 통합된 최종 문서들

## 🔧 구현시 주요 고려사항

### 에러 처리 전략
- **detect_section_content 실패**: Fallback으로 모든 섹션을 has_content=false 설정
- **extract_section_content 실패**: Fallback으로 빈 추출 결과 반환
- **JSON 파싱 실패**: Fallback 모드로 안전한 기본값 제공
- **세션 연결 끊김**: 새로운 세션으로 전체 작업 재시작

### 파일 저장 규칙
- **content.json**: 지정된 4개 필드만 포함 (id, title, level, has_content)
- **sections 파일**: normalize_title() 적용한 안전한 파일명 사용
- **폴더 구조**: sections, unified_info_docs 폴더 없으면 자동 생성

### 로깅 패턴
- **단계별 진행**: 각 주요 단계마다 시작/완료 로그
- **성능 정보**: 처리 시간, 섹션 수, 생성 파일 수 등
- **에러 상세**: 실패 시 구체적인 원인과 위치 정보
