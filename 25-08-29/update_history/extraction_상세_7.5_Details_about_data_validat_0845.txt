## 7.5 Details about data validation failures - 추가 정보 정리

이 문서의 주요 내용은 JSON Schema validation 실패 시, 실패 이유에 대한 상세 정보를 얻는 방법과 그 유용성에 대한 것입니다. 다음은 이 내용에서 다루지 않았던, 추가적으로 주목할 만한 세부 정보, 예시, 구현 방법입니다.

**1. 오류 정보의 구조와 해석:**

*   **오류 정보의 형태:** Ajv (JavaScript validator)를 예시로, validation 실패 시 오류 정보는 배열 형태로 반환됩니다. 각 배열 요소는 오류에 대한 상세 정보를 담은 객체입니다.
*   **객체 내부 구조:** 각 오류 객체는 다음과 같은 속성을 가질 수 있습니다.
    *   `instancePath`: 오류가 발생한 데이터 내의 위치 (예: ""는 root, "/fields/0"은 fields 배열의 첫 번째 요소).
    *   `schemaPath`: 스키마 내에서 오류가 발생한 부분의 위치.
    *   `keyword`: 발생한 오류의 유형 (예: "required", "type").
    *   `params`: 오류 유형에 따른 추가적인 정보 (예: `missingProperty` - 누락된 필드의 이름).
    *   `message`: 오류에 대한 설명 (인간 친화적인 텍스트).
*   **오류 정보의 난해함:** 원시적인 오류 정보는 이해하기 어려울 수 있습니다.

**2. 오류 정보를 활용하는 방법:**

*   **오류 정보의 가독성 향상:** Ajv는 `errorsText` 유틸리티 함수를 제공하여 오류 정보를 사람이 읽기 쉬운 형태로 변환합니다.
*   **다중 오류 처리 (allErrors 옵션):** 기본적으로 Ajv는 첫 번째 오류만 감지하지만, `allErrors: true` 옵션을 Ajv 생성자에 전달하면 모든 오류를 감지할 수 있습니다. 이 옵션은 여러 오류를 동시에 처리해야 하는 경우에 유용합니다.
*   **실제 사용 사례:** 시스템 경계(boundaries)에서 데이터 유효성 검사를 수행하여, 웹 서버로의 변환과 같은 시나리오에서 유용함을 강조합니다.

**3. 코드 예시 및 구체적인 내용:**

*   **Listing 7.20:** `invalidSearchBooksRequest` 객체에서 `myTitle` 필드가 `title`로, `fields` 배열의 요소가 문자열이 아닌 경우 오류가 발생합니다.
*   **Listing 7.21:** Ajv에서 반환되는 오류 객체의 상세 구조를 보여줍니다.
*   **Listing 7.22:** `errorsText` 함수를 사용하여 오류를 사람이 읽을 수 있는 형태로 변환하는 예시입니다.
*   **Listing 7.23:** `allErrors: true` 옵션을 사용하여 여러 오류를 한 번에 감지하는 예시입니다. `invalidSearchBooksRequest` 객체는 `title` 필드가 누락되고, `fields` 배열에 숫자 타입의 요소가 포함되어 3개의 오류가 발생합니다.

**4. 새로운 내용과 추가 정보:**

*   **Ajv 이외의 다른 Validator Library:** 다른 validator library들은 각자 오류 정보를 노출하는 방식이 다를 수 있다는 점을 간접적으로 시사합니다. (예: Java의 `javax.validation` framework나 Python의 `jsonschema` 등) 각 라이브러리의 문서와 API를 참조하여 오류 처리 방법을 파악해야 합니다.
*   **오류 처리 전략:**
    *   **프론트엔드에서의 유효성 검사:** 사용자가 입력한 데이터의 유효성을 검사하여 사용자 경험을 향상시키고, 서버에 불필요한 요청을 줄일 수 있습니다.
    *   **백엔드에서의 유효성 검사:** 데이터베이스에 저장되기 전에 데이터의 유효성을 검사하여 데이터 무결성을 유지하고, 악의적인 데이터를 방지할 수 있습니다.
    *   **오류 메시지 커스터마이징:** validator가 제공하는 기본 오류 메시지 외에, 애플리케이션의 요구사항에 맞춰 사용자 정의 오류 메시지를 제공할 수 있습니다. (예: 국제화, 상세한 설명 추가)
*   **성능 고려 사항:** `allErrors: true` 옵션을 사용하면 여러 오류를 감지할 수 있지만, 유효성 검사 시간이 증가할 수 있습니다. 성능이 중요한 경우에는, 필요한 경우에만 사용하거나, 오류 발생 시 특정 시점까지만 검사하는 등의 최적화를 고려해야 합니다.
*   **JSON Schema Cheat Sheet의 활용:** JSON Schema cheat sheet는 JSON Schema를 처음 접하는 사람들에게 유용한 가이드가 될 수 있으며, 자주 사용되는 schema 구조와 패턴을 빠르게 파악하는 데 도움을 줍니다.
*   **유효한 데이터의 중요성:** Listing 7.25와 같이 유효한 데이터 예시는, 데이터가 예상대로 구조화되었는지 확인하고, 유효성 검사 규칙이 올바르게 작동하는지 테스트하는 데 도움이 됩니다.
*   **테스트:** 데이터 유효성 검사는 소프트웨어의 안정성을 높이는 데 중요한 역할을 합니다. 유효성 검사 로직을 테스트하여 예상대로 작동하는지 확인해야 합니다.
