## 7.5 Details about data validation failures

이 섹션은 JSON Schema 유효성 검사 실패 시 얻을 수 있는 상세 정보와 관련된 내용을 다룹니다.

### 데이터 유효성 검사 실패의 중요성

*   JSON Schema 유효성 검사는 단순한 이진 검사(유효/무효)를 넘어 실패 이유에 대한 상세 정보를 제공합니다.
*   예를 들어, 필수 필드가 누락된 경우 누락된 필드의 이름을, 데이터 유형이 예상과 다른 경우 해당 정보를 얻을 수 있습니다.

### 데이터 유효성 검사 실패 정보 접근 방법

*   각 데이터 검사기 라이브러리(예: Ajv)는 유효성 검사 실패에 대한 정보를 노출하는 자체 방식을 가지고 있습니다.
*   Ajv의 경우, 마지막 데이터 유효성 검사에서 발생한 오류가 validator 인스턴스 내의 배열로 저장됩니다.

### 단일 실패의 경우

*   **예시:** "title" 필드 대신 "myTitle"을 사용하는 검색 도서 요청.
*   **Ajv에서의 오류 정보:** `ajv.errors` 배열에 저장됩니다.
*   **오류 정보의 형식 (Listing 7.21):**
    ```json
    [
      {
        "instancePath": "",
        "schemaPath": "#/required",
        "keyword": "required",
        "params": {
          "missingProperty":"title"
        },
        "message": "must have required property 'title'"
      }
    ]
    ```
    *   `instancePath`: 오류가 발생한 데이터 내의 경로.
    *   `schemaPath`: 오류와 관련된 스키마의 경로.
    *   `keyword`: 오류를 발생시킨 JSON Schema 키워드.
    *   `params`: 오류와 관련된 추가 정보 (예: 누락된 속성).
    *   `message`: 오류에 대한 설명.
*   **Ajv의 `errorsText` 유틸리티 함수:** 오류 배열을 사람이 읽을 수 있는 형식으로 변환합니다.

### 다중 실패의 경우

*   **Ajv의 기본 동작:** 첫 번째 유효성 검사 오류만 감지합니다 (성능상의 이유).
*   **다중 오류 감지 활성화:** `Ajv` 생성자에 `allErrors: true` 옵션을 전달해야 합니다.
*   **예시 (Listing 7.23):**
    ```javascript
    var ajv = new Ajv({allErrors: true});
    ```
    *   `invalidSearchBooksRequest`가 "title" 필드를 누락하고, "fields" 배열에 문자열 대신 숫자를 포함하는 경우, 세 개의 오류가 반환됩니다.
    *   `errorsText`를 사용하면 "data must have required property 'title', data/fields/0 must be string, data/fields/1 must be string"과 같은 사람이 읽을 수 있는 형식으로 오류를 확인할 수 있습니다.

### 요약

*   데이터 유효성 검사 실패 시 상세 정보를 활용하면 시스템의 경계를 개선하고 오류를 보다 효과적으로 처리할 수 있습니다.
*   JSON Schema의 사용은 웹 서버를 구축하고, 라이브러리 관리 시스템을 구축하는데 유용합니다.
