## 7.5 Details about data validation failures 상세 내용 정리

### 데이터 유효성 검사 실패의 중요성

*   기존에는 JSON Schema 유효성 검사를 단순히 '유효' 또는 '무효'로 처리했지만, 실제로는 유효하지 않은 데이터에 대한 자세한 정보를 얻을 수 있다.
*   예를 들어, 필수 필드가 누락된 경우 해당 필드의 이름을 알 수 있으며, 데이터 유형이 예상과 다를 경우 해당 정보도 얻을 수 있다.

### 오류 정보 접근 방법 (JavaScript Ajv 예시)

*   각 데이터 유효성 검사 라이브러리는 유효성 검사 실패에 대한 세부 정보를 노출하는 방식이 다르다.
*   Ajv (JavaScript 라이브러리)의 경우, 마지막 데이터 유효성 검사에서 발생한 오류가 validator 인스턴스 내의 배열 `ajv.errors`에 저장된다.
*   `ajv.errors` 배열의 각 요소는 오류에 대한 자세한 정보를 담고 있는 객체이다.

### `ajv.errors` 배열의 내용 이해

*   `ajv.errors` 배열 내의 각 오류 객체는 다음과 같은 속성을 가질 수 있다.
    *   `instancePath`: 오류가 발생한 데이터 내의 위치 (예: `""`, `"/fields/0"`)
    *   `schemaPath`: 오류를 발생시킨 스키마의 경로 (예: `"#required"`)
    *   `keyword`: 발생한 오류의 키워드 (예: `"required"`)
    *   `params`: 오류에 대한 추가 파라미터 (예: `{"missingProperty":"title"}`)
    *   `message`: 오류에 대한 설명 (예: `"must have required property 'title'"`)
*   `ajv.errorsText(ajv.errors)` 유틸리티 함수를 사용하여 `ajv.errors` 배열의 내용을 사람이 읽기 쉬운 형식으로 변환할 수 있다.

### 다중 오류 검출

*   기본적으로 Ajv는 첫 번째 유효성 검사 실패만 감지한다.
*   `allErrors: true` 옵션을 Ajv 생성자에 전달하면 여러 유효성 검사 실패를 모두 감지할 수 있다.
*   이렇게 하면 데이터 내에서 여러 문제가 동시에 발견된 경우 모든 오류를 한 번에 확인할 수 있다.

### 예시: 다중 오류 검출 (Listing 7.23)

*   `myTitle` 필드가 `title` 대신 사용되고, `fields` 배열에 문자열 대신 숫자가 포함된 경우 세 가지 오류가 반환된다.
*   결과 예시:
    *   "data must have required property 'title'"
    *   "data/fields/0 must be string"
    *   "data/fields/1 must be string"
