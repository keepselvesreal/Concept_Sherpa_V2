## 7.1 Data Validation in DOP: 상세 분석

### 도입부: DOP에서의 데이터 검증의 중요성

*   **문제 제기:** OOP(객체 지향 프로그래밍)에서 데이터 검증이 보장되는 것과 달리, DOP(데이터 지향 프로그래밍)에서는 필드 이름 및 타입의 작은 실수로 인해 데이터 일관성 문제가 발생할 수 있다는 점이 제기됩니다.
*   **해결책 제시:** DOP에서도 데이터 검증이 가능하며, 시스템 경계에서 데이터를 검증하는 것이 중요합니다.

### DOP에서의 데이터 검증 원리

*   **DOP의 특징:** DOP는 데이터 스키마와 데이터 표현이 분리되어 있습니다. 이는 데이터 검증을 수행하는 데 있어서 중요한 기반이 됩니다.
*   **데이터 검증의 초점:** DOP에서 가장 중요한 데이터 검증은 시스템 경계를 넘나드는 데이터에 집중합니다.

### 시스템 경계의 정의 및 예시

*   **시스템 경계:** 시스템이 데이터를 교환하는 영역을 의미합니다.
*   **예시 (웹 서버):**
    *   클라이언트 경계 (웹 브라우저 등)
    *   데이터베이스 경계
    *   웹 서비스 경계

### 데이터 검증의 종류 및 중요성

*   **두 가지 종류의 데이터 검증:**
    *   **경계에서의 검증:** 시스템의 입출력 데이터를 검증합니다. (Guardian, Production 환경)
    *   **내부에서의 검증:** 코드 개발의 용이성을 위해 내부 데이터를 검증합니다. (Dev 환경)
*   **경계에서의 검증의 중요성:** 시스템의 경계에서 데이터가 유효한지 확인하면, 시스템 내부에서 예상치 못한 데이터가 발생할 확률을 줄일 수 있습니다.
*   **내부 검증의 목적:** 코드베이스가 커짐에 따라 개발 편의성을 높입니다.

### 데이터 검증의 목적

*   **경계에서의 검증 목적:**
    *   유효하지 않은 데이터의 시스템 유입 및 유출 방지.
    *   유효하지 않은 데이터를 발견했을 때, 유용한 오류 메시지 제공.

### 데이터 검증 요약 표 (Table 7.1)

| 종류                     | 목적                                     | 환경   |
| :----------------------- | :---------------------------------------- | :----- |
| 경계에서의 데이터 검증 | 시스템 입출력 데이터의 유효성 검증          | Production |
| 내부에서의 데이터 검증  | 개발 편의성                                 | Dev      |
