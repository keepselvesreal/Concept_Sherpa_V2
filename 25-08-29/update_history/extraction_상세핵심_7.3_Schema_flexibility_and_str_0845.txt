## 7.3 Schema flexibility and strictness 상세 정리

본 내용은 JSON Schema를 사용하여 데이터 유효성 검사를 수행할 때의 유연성과 엄격성에 대해 다룹니다. 특히, JSON Schema에서의 필드 필수 여부, 추가 속성 허용 여부, 그리고 데이터 유효성 검사 시의 모범 사례를 중심으로 설명합니다.

### 필수 필드와 선택 필드

*   **기본 동작:** JSON Schema에서 객체 내 필드는 기본적으로 선택적(Optional)입니다. 즉, 스키마에 정의되지 않은 필드가 존재해도 유효성 검사 오류를 발생시키지 않습니다.
*   **필수 필드 지정:** 필드를 필수 필드로 지정하려면 `required` 배열에 해당 필드 이름을 포함해야 합니다.

    *   예시:
        ```json
        {
          "type": "object",
          "required": ["title", "available"],
          "properties": {
            "title": {"type": "string"},
            "available": {"type": "boolean"},
            "subtitle": {"type": "string"}
          }
        }
        ```

    *   위 예시에서 `title`과 `available` 필드는 필수이며, `subtitle` 필드는 선택적입니다.

### 스키마 재사용 및 구성 가능성

*   **스키마의 유연성:** JSON Schema는 단순한 맵(Map, 객체)으로 구성되어 있어, 변수에 할당하거나 다른 스키마에 포함시키는 방식으로 쉽게 재사용하고 구성할 수 있습니다.
*   **스키마 분리:** 복잡한 스키마를 별도의 스키마로 분리하여 관리함으로써 가독성을 높이고 유지 보수를 용이하게 할 수 있습니다.

    *   예시: `bookInfoSchema`와 `searchBooksResponseSchema`

### 추가 속성 허용 여부 (additionalProperties)

*   **기본 동작:** JSON Schema는 기본적으로 스키마에 정의되지 않은 추가 속성을 허용합니다.
*   **추가 속성 금지:** 추가 속성을 금지하려면 `additionalProperties` 속성을 `false`로 설정합니다.

    *   예시:
        ```json
        {
          "type": "object",
          "required": ["title", "isbn", "available"],
          "additionalProperties": false,
          "properties": {
            "title": {"type": "string"},
            "isbn": {"type": "string"},
            "available": {"type": "boolean"}
          }
        }
        ```

    *   위 예시에서는 `title`, `isbn`, `available` 필드 외에 다른 필드가 있으면 유효성 검사에서 오류가 발생합니다.

### 데이터 유효성 검사 모범 사례

*   **외부 데이터 유효성 검사:** 외부 데이터 소스(예: 데이터베이스)로부터 받은 데이터는 반드시 유효성 검사를 수행해야 합니다.
*   **송신 데이터의 엄격성:** 서버에서 클라이언트로 전송하는 데이터(응답)는 가능한 엄격하게 검사하여 예상치 못한 데이터가 전송되는 것을 방지합니다. `additionalProperties: false` 설정을 권장합니다.
*   **수신 데이터의 유연성:** 클라이언트로부터 받은 데이터(요청)는 가능한 유연하게 처리하여 예상치 못한 필드가 존재하더라도 처리를 시도합니다.

    *   "Be conservative in what you send, be liberal in what you accept." (Jon Postel의 Robustness Principle)
*   **요청/응답 간의 차이:** 요청 스키마는 유연하게, 응답 스키마는 엄격하게 구성하는 것이 일반적인 방법입니다.
