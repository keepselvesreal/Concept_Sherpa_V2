## 7.5 Details about data validation failures - 추가 상세 정보 및 새로운 내용 정리

다음은 "7.5 Details about data validation failures" 내용을 분석하여 기존 핵심 내용에서 다루지 않은 추가적인 세부 사항, 예시, 구체적인 구현 방법 등을 정리한 내용입니다.

**1. 데이터 유효성 검사 실패 시 상세 정보 제공:**

*   **개념:** 데이터가 유효성 검사에 실패했을 때, 단순히 "유효하지 않음"만 알려주는 것이 아니라, **실패 이유에 대한 구체적인 정보**를 제공합니다.
*   **구체적인 정보 예시:**
    *   누락된 필수 필드의 이름
    *   예상된 타입과 다른 데이터 타입
*   **의미:** 개발자가 데이터 유효성 검사 실패의 원인을 쉽게 파악하고 문제를 해결할 수 있도록 돕습니다.

**2. 데이터 유효성 검사 실패 정보 접근 방법 (Ajv 라이브러리 기준):**

*   **실패 정보 저장 위치:** Ajv 라이브러리에서는 마지막 유효성 검사에서 발생한 에러 정보를 `validator.errors` 배열에 저장합니다.
*   **배열 형태의 이유:** 여러 개의 유효성 검사 실패가 동시에 발생할 수 있기 때문입니다.
*   **개별 에러 정보의 구조:**
    *   `instancePath`: 에러가 발생한 데이터 내의 위치 (예: ""는 최상위 레벨, "/fields/0"은 "fields" 배열의 첫 번째 요소).
    *   `schemaPath`: 에러와 관련된 스키마 내의 위치.
    *   `keyword`: 발생한 에러의 종류 (예: "required", "type").
    *   `params`: 에러에 대한 추가 정보 (예: 누락된 속성의 이름).
    *   `message`: 에러에 대한 설명.

**3. 에러 메시지 가독성 개선:**

*   **문제점:** `validator.errors` 배열에 저장된 에러 정보는 개발자가 이해하기 어려울 수 있습니다.
*   **해결 방법:** Ajv는 `errorsText()` 유틸리티 함수를 제공하여 `validator.errors` 배열을 **사람이 읽기 쉬운 형식**으로 변환합니다.
*   **예시:** `ajv.errorsText(ajv.errors);`

**4. 여러 개의 유효성 검사 실패 감지:**

*   **기본 동작:** Ajv는 기본적으로 첫 번째 유효성 검사 실패만 감지합니다.
*   **이유 (추정):** 성능상의 이유로, 첫 번째 에러 발생 시 검사를 중단합니다.
*   **여러 에러 감지 설정:** `Ajv` 생성자에 `allErrors: true` 옵션을 전달합니다.
    *   `var ajv = new Ajv({allErrors: true});`
*   **결과:** 여러 개의 유효성 검사 실패가 발생한 경우, 모든 에러 정보를 `validator.errors` 배열에 저장합니다.
