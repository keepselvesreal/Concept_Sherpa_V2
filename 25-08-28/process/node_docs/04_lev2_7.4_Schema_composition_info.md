## 7.4 Schema Composition: 심층 분석

이 섹션은 JSON Schema를 사용하여 외부 API 응답 데이터를 검증하는 방법에 초점을 맞추고 있으며, 특히 스키마 구성(Schema Composition)이라는 강력한 기능을 소개합니다.

### 7.4.1 문제 제기: 외부 API 데이터 검증의 필요성

*   **상황:** Theo는 Open Library Books API에서 제공하는 책 정보를 통합하는 작업을 맡았습니다. 외부 API에서 반환되는 JSON 데이터를 검증해야 할 필요성을 느낍니다.
*   **문제:** API 응답 데이터의 복잡성, 특히 `isbn_10`과 `isbn_13` 필드의 존재 유무에 따라 데이터 유효성을 정확하게 검증하는 것이 어렵습니다.
*   **예시:** "Watchmen" 책의 API 응답에는 `isbn_10`과 `isbn_13`이 모두 포함되어 있습니다. 책의 출판 시기에 따라 두 필드 중 하나만 존재하거나 둘 다 존재할 수 있습니다.

### 7.4.2 초안 스키마와 한계

*   **초기 접근:** Theo는 Open Library Books API 응답의 JSON Schema를 작성합니다. 이 스키마는 `title` 필드를 필수 요소로 지정하고, 다른 필드의 데이터 유형을 정의합니다.
*   **문제점:** 초기 스키마는 `isbn_10`과 `isbn_13` 필드 중 적어도 하나가 존재해야 한다는 제약 조건을 표현하지 못합니다. 두 필드 모두 선택 사항으로 간주됩니다.

### 7.4.3 스키마 구성(Schema Composition) 소개

*   **개념:** 스키마 구성은 여러 개의 스키마를 결합하여 복잡한 유효성 검사 규칙을 정의하는 방법입니다. 논리 연산자 AND, OR, NOT과 유사하게 작동합니다.
*   **핵심 키워드:**
    *   `allOf`: 모든 스키마에 부합해야 함 (AND)
    *   `anyOf`: 스키마 중 하나 이상에 부합해야 함 (OR)
    *   `oneOf`: 정확히 하나의 스키마에 부합해야 함 (OR, 배타적)
*   **적용:** `basicBookInfoSchema AND (mandatoryIsbn13 OR mandatoryIsbn10)`와 같은 방식으로 스키마를 결합하여 복잡한 유효성 검사 조건을 표현합니다.

### 7.4.4 스키마 구성 예시: Open Library Books API 응답 검증

1.  **개별 스키마 정의:**
    *   `basicBookInfoSchema`: `title`이 필수인 기본적인 책 정보 스키마.
    *   `mandatoryIsbn13`: `isbn_13`이 필수인 스키마.
    *   `mandatoryIsbn10`: `isbn_10`이 필수인 스키마.
2.  **스키마 조합:**
    *   `bookInfoSchema`: `basicBookInfoSchema`와 `(mandatoryIsbn13 OR mandatoryIsbn10)`을 `allOf`와 `anyOf`를 사용하여 결합합니다. 즉, 책 정보는 제목을 가져야 하고, ISBN13 또는 ISBN10을 적어도 하나는 가져야 합니다.
3.  **유효성 검사:**
    *   `bookInfoSchema`를 사용하여 API 응답 데이터를 검증합니다.
    *   유효한 응답("Watchmen" 정보 포함)은 `true`를 반환합니다.

### 7.4.5 스키마 구성의 장점

*   **유연성:** 복잡한 데이터 유효성 검사 규칙을 표현할 수 있습니다.
*   **재사용성:** 개별 스키마를 재사용하여 다른 스키마를 구성할 수 있습니다.
*   **표현력:** 클래스로 데이터를 표현하는 것보다 더 많은 유효성 검사 조건을 정의할 수 있습니다.

### 7.4.6 추가 고려 사항

*   **오류 메시지:** 데이터가 유효하지 않은 경우, 정확히 무엇이 잘못되었는지 알기 어렵다는 단점이 있습니다 (이 부분은 더 개선되어야 함).
*   **심화 학습:** 더 발전된 데이터 유효성 검사에 대한 내용은 12장에서 다룹니다.

## 7.4 Schema composition 분석 및 상세 정보

이 챕터는 JSON Schema를 사용하여 외부 웹 서비스(Open Library Books API)에서 반환된 데이터를 검증하는 방법을 설명하며, 특히 **Schema composition(스키마 조합)** 이라는 강력한 기능을 소개합니다. 다음은 챕터의 핵심 내용에서 도출된 추가적인 상세 정보와 새로운 내용입니다.

**1. Open Library Books API 및 데이터 검증 필요성:**

*   **구체적인 API 예시:** Open Library Books API는 책에 대한 상세 정보를 제공하는 서비스입니다. 예시로, "Watchmen" 책에 대한 API 응답 JSON 데이터를 보여줍니다. 이 응답 데이터는 출판사, 페이지 수, 무게, 형식, 주제, ISBN, 제목, 출판일, 물리적 크기 등의 정보를 포함합니다.
*   **데이터 유효성 검증의 필요성:** 외부 API에서 제공되는 데이터는 신뢰할 수 없으므로, 데이터의 구조와 유형을 검증하여 오류를 방지하고, 애플리케이션의 안정성을 확보해야 합니다.
*   **ISBN (International Standard Book Number) 필드의 특수성:** ISBN-10과 ISBN-13은 모두 책의 고유 식별자이지만, 책의 출판 연도에 따라 둘 중 하나 또는 둘 모두 존재할 수 있습니다. 2007년 이후 출판된 책은 ISBN-13을, 그 이전 책은 ISBN-10을 주로 사용합니다. "Watchmen"은 원래 1986년에 출판되었지만 2007년 이후에도 출판되었기 때문에 두 ISBN 모두를 가지고 있습니다.

**2. Schema composition의 개념과 구현:**

*   **Schema composition의 정의:** JSON Schema composition은 여러 스키마를 조합하여 더 복잡한 유효성 검사 규칙을 정의하는 기능입니다. 이는 AND, OR, NOT과 유사한 논리적 조건을 사용하여 스키마를 결합하는 방식으로 작동합니다.
*   **`allOf`, `anyOf`, `oneOf` 키워드:**
    *   `allOf`: 모든 스키마를 만족해야 합니다 (AND).
    *   `anyOf`: 최소한 하나의 스키마를 만족해야 합니다 (OR).
    *   `oneOf`: 정확히 하나의 스키마를 만족해야 합니다 (XOR, 배타적 OR). 이 챕터에서는 `oneOf`에 대한 간략한 언급이 있지만, 자세한 내용은 12장에서 다룬다고 언급합니다.
*   **구체적인 예시 (Open Library Books API response 스키마):**
    1.  `basicBookInfoSchema`: 필수 필드 "title"을 포함한 기본 정보 스키마.
    2.  `mandatoryIsbn13`: 필수 필드 "isbn\_13"을 갖는 스키마.
    3.  `mandatoryIsbn10`: 필수 필드 "isbn\_10"을 갖는 스키마.
    4.  `bookInfoSchema`: `basicBookInfoSchema` AND (`mandatoryIsbn13` OR `mandatoryIsbn10`)와 같이 조합된 스키마. 이 스키마는 "title"은 필수이며, "isbn\_13" 또는 "isbn\_10" 중 하나는 반드시 존재해야 함을 나타냅니다.
*   **코드 예시 (Listing 7.18, 7.19):**  스키마를 JSON 형식으로 정의하고, 유효성 검사 함수를 사용하여 데이터를 검증하는 예시 코드를 제공합니다.

**3. Schema composition의 장점과 추가적인 고려 사항:**

*   **표현력 향상:** Schema composition은 클래스로 데이터를 표현할 때보다 더 복잡한 데이터 유효성 검사 조건을 표현할 수 있도록 합니다.
*   **에러 메시지 부재:** 데이터가 유효하지 않을 때, JSON Schema만으로는 구체적인 에러 정보를 얻기 어렵다는 단점이 있습니다. (이 부분은 추후 개선될 수 있음)
*   **더 발전된 데이터 유효성 검사:** 12장에서 더 진보된 데이터 유효성 검사 기법을 다룰 것이라고 언급하며, 스키마 조합은 데이터 검증의 시작일 뿐임을 강조합니다.

**요약:**

이 챕터는 JSON Schema의 스키마 조합 기능을 사용하여 외부 API 응답 데이터를 검증하는 방법을 설명합니다. ISBN 필드와 같은 복잡한 조건의 유효성을 검사하는 데 `allOf`, `anyOf`, `oneOf`와 같은 키워드를 활용하는 방법을 보여줍니다.  또한, 데이터 유효성 검사의 중요성을 강조하며, 추후 더 발전된 검사 기법에 대한 예고도 포함하고 있습니다.


## 주요 화제
- **외부 웹 서비스 데이터 검증의 필요성**: 외부 웹 서비스 (예: Open Library Books API)에서 제공하는 데이터의 유효성을 검증해야 할 필요성을 제기하고, 그 이유를 설명합니다.
- **JSON Schema를 이용한 데이터 검증**: 외부 API 응답 (JSON 형태)의 구조를 정의하고 유효성을 검증하기 위해 JSON Schema를 사용하는 방법을 소개합니다.
- **Schema composition (스키마 조합)의 개념**: JSON Schema를 사용하여 여러 스키마를 조합하는 방법을 설명합니다. "allOf" (AND), "anyOf" (OR) 연산자를 사용하여 더 복잡한 데이터 유효성 검증 조건을 정의할 수 있음을 보여줍니다.
- **ISBN 필드의 유효성 검증 문제**: isbn_10과 isbn_13 필드가 항상 둘 다 존재하지 않고, 둘 중 하나 또는 둘 다 존재할 수 있는 경우의 유효성 검증 문제를 제시하고, 스키마 조합을 통해 이 문제를 해결하는 방법을 보여줍니다.
- **스키마 조합의 활용**: 기본 정보 스키마와 ISBN 필드 관련 스키마를 조합하여, ISBN 필드의 유효성 검증 조건을 구현하는 구체적인 예시를 제공합니다.
- **JSON Schema의 고급 기능**: "oneOf"와 같은 JSON Schema의 추가 기능에 대한 간략한 소개와, JSON Schema를 이용한 데이터 유효성 검증의 표현력에 대한 언급이 있습니다.
- **데이터 유효성 검증의 한계와 향후 과제**: 데이터가 유효하지 않을 때 어떤 문제가 발생했는지 명확하게 파악하기 어려운 점을 언급하고, 더 발전된 데이터 유효성 검증의 필요성을 제기합니다.
