## 핵심 내용
JSON Schema는 JSON 데이터의 구조와 유효성을 정의하는 언어입니다. 객체, 배열, 문자열 등 데이터 유형과 필수/선택 필드, 허용된 값(enum) 등을 지정하여 데이터 유효성 검사를 수행합니다. JSON Schema는 다양한 프로그래밍 언어에서 사용 가능하며, 데이터가 스키마를 준수하는지 검사하는 유효성 검사 라이브러리가 존재합니다.


## 상세 핵심 내용
### JSON Schema in a nutshell - 개요

"JSON Schema in a nutshell"은 데이터 유효성 검사를 위한 JSON Schema 언어에 대한 간략한 소개를 제공합니다. 이 챕터에서는 JSON Schema를 사용하여 데이터의 구조와 유효성을 정의하고, 데이터를 검증하는 방법을 설명합니다.

### 데이터 유효성 검사 및 JSON Schema의 중요성

*   **데이터 표현과 스키마의 분리:** 데이터 표현(실제 데이터)과 데이터 스키마(데이터 구조 정의)를 분리하는 것이 중요합니다. 이를 통해 데이터의 유효성을 독립적으로 검증할 수 있습니다.
*   **JSON Schema의 역할:** JSON Schema는 JSON 형식의 데이터에 대한 스키마를 정의하는 언어입니다. 데이터의 타입, 필수 필드, 허용 값 등을 명시하여 데이터의 구조와 유효성을 검사할 수 있습니다.
*   **DOP (Data-Oriented Programming)에서의 중요성:** 데이터 유효성 검사는 DOP에서 중요한 개념입니다. 데이터가 스키마를 준수하는지 검증하여 데이터 무결성을 유지하고 애플리케이션의 안정성을 확보할 수 있습니다.

### JSON Schema 기본 구조

*   **`type` 필드:** 데이터 타입을 지정합니다. 예: `"object"`, `"string"`, `"array"`
*   **`properties` 필드:** 객체(object) 타입의 경우, 각 필드의 스키마를 정의합니다.
*   **`items` 필드:** 배열(array) 타입의 경우, 배열 요소의 스키마를 정의합니다.
*   **`enum` 필드:** 특정 값들만 허용하도록 제한합니다 (열거형).
*   **`required` 필드:** 객체 타입에서 필수 필드를 지정합니다. 값은 필수 필드 이름의 배열입니다.

### JSON Schema 예제: 검색 요청 스키마

책 검색 요청의 스키마를 정의하는 예제를 통해 JSON Schema의 사용법을 설명합니다.

1.  **기본 스키마:** `"type": "object"`, `"properties": {...}`
2.  **필드 타입 지정:** `"title": {"type": "string"}, "fields": {"type": "array"}`
3.  **배열 요소 타입 지정:**  `"fields": {"type": "array", "items": {"type": "string"}}`
4.  **허용 값 제한 (enum):** `{"fields": {"type": "array", "items": {"enum": [...]}}}`
5.  **필수 필드 지정 (required):** `"required": ["title", "fields"]`

### 데이터 유효성 검사 방법

*   **유효성 검사 라이브러리:** JSON Schema를 검증하는 라이브러리를 사용합니다. JavaScript, Java, C#, Python, Ruby 등 다양한 언어에서 사용할 수 있습니다.
*   **validate 함수:** 라이브러리는 일반적으로 스키마와 데이터를 입력으로 받아 유효성 검사 결과를 반환하는 `validate` 함수를 제공합니다.  (true: 유효, false: 무효)

### JSON Schema의 장점

*   **언어 독립성:** 다양한 프로그래밍 언어에서 사용할 수 있습니다.
*   **표현력:** 클래스로 표현하기 어려운 복잡한 유효성 검사 조건을 정의할 수 있습니다 (예: 숫자 범위, 정규 표현식).

### 추가 정보

*   **고급 유효성 검사:** 숫자 범위 검사, 정규 표현식과 같은 고급 유효성 검사 기능이 있습니다.
*   **유효성 검사 실패 정보:** 유효성 검사 실패 시, 구체적인 오류 정보를 얻을 수 있습니다.
*   **스키마 복잡성:** JSON Schema는 클래스 정의보다 더 많은 정보를 제공하며 유연합니다.

## 7.2 JSON Schema in a nutshell - 추가 상세 정보 및 새로운 내용 정리

이 내용은 "7.2 JSON Schema in a nutshell"의 내용을 기반으로 JSON Schema에 대한 이해를 더욱 깊게 하기 위해, 기존 텍스트에서 다루지 않은 추가적인 세부 사항과 새로운 내용을 식별하여 정리합니다.

**1. JSON Schema의 개념:**

*   **데이터 스키마와 데이터 표현의 분리:** JSON Schema는 데이터의 구조(스키마)를 데이터 자체(표현)와 분리하여 정의합니다. 이로 인해 데이터 검증(validation)을 언제든 독립적으로 수행할 수 있습니다. (TIP: DOP에서 데이터 스키마는 데이터 표현과 분리됩니다.)
*   **JSON Schema의 기본 구조:**
    *   `type`: 데이터 타입을 정의합니다. (예: "object", "string", "array")
    *   `properties`: 객체(object) 내 필드의 스키마를 정의합니다.
    *   `items`: 배열(array)의 각 요소의 스키마를 정의합니다.
    *   `enum`: 열거형(enumeration) 값을 정의합니다. 특정 값들 중 하나를 허용합니다.
    *   `required`: 객체 내 필수 필드를 정의합니다.

**2. JSON Schema의 활용 예시 - Book Search Request 스키마:**

*   **요청 구조:** 검색 요청은 "title" (string)과 "fields" (array of strings) 두 필드로 구성됩니다.
*   **스키마 구성 단계:**
    1.  **기본 구조 (object):** `{"type": "object", "properties": {...}}`
    2.  **title 필드 (string):** `"title": {"type": "string"}`
    3.  **fields 필드 (array of string):**
        *   `"fields": {"type": "array", "items": {"type": "string"}}`
        *   **열거형(enum)을 사용한 값 제한:** `"fields": {"type": "array", "items": {"enum": ["publishers", "number_of_pages", "weight", "physical_format", "subjects", "publish_date", "physical_dimensions"]}}`
    4.  **필수 필드 (required):** `"required": ["title", "fields"]`
*   **완성된 스키마:**
    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {
            "enum": [
              "publishers",
              "number_of_pages",
              "weight",
              "physical_format",
              "subjects",
              "publish_date",
              "physical_dimensions"
            ]
          }
        }
      },
      "required": ["title", "fields"]
    }
    ```

**3. 데이터 검증 (Data Validation):**

*   **검증의 의미:** 스키마에 따라 데이터가 유효한지 확인하는 과정입니다.
*   **검증 라이브러리:** 다양한 프로그래밍 언어에서 JSON Schema 검증 라이브러리를 사용할 수 있습니다.
    *   JavaScript: Ajv (https://github.com/ajv-validator/ajv)
    *   Java: Snow (https://github.com/ssilverman/snowy-json)
    *   C#: JSON.net Schema (https://www.newtonsoft.com/jsonschema)
    *   Python: jschon (https://github.com/marksparkza/jschon)
    *   Ruby: JSONSchemer (https://github.com/davishmcclurg/json_schemer)

**4. JSON Schema의 장점:**

*   **언어 독립성:** 여러 프로그래밍 언어에서 사용할 수 있는 검증 도구를 제공합니다.
*   **표현력:** 클래스 기반의 데이터 표현보다 더 복잡한 검증 조건을 표현할 수 있습니다. (예: 숫자 범위, 정규 표현식)

**5. 추가적인 궁금증과 해결:**

*   **유효성 검사 실패 시 상세 정보:**  검증 실패의 원인을 자세히 알 수 있는 기능을 제공하는 라이브러리가 있습니다. (예: Ajv는 에러 메시지를 제공합니다.)
*   **복잡한 응답 스키마:** 검색 결과와 같이 여러 필드가 있고, 일부 필드가 선택적인 복잡한 응답의 유효성 검사도 가능합니다.
*   **고급 검증:** 숫자 범위 제한, 정규 표현식과 같은 고급 검증 기능도 JSON Schema에서 제공합니다. (챕터 12에서 다룸)

**6. 추가 정보:**

*   JSON Schema 공식 웹사이트: https://json-schema.org/
*   이 책에서 사용하는 JSON Schema 버전: 2020-12
*   JSON Schema는 데이터 유효성 검사를 위한 강력하고 유연한 도구입니다.

## 주요 화제
- **JSON Schema 소개와 필요성**: 데이터 유효성 검증을 위해 JSON Schema를 사용하는 이유와 데이터 표현과 스키마의 분리 개념을 설명합니다.

- **JSON Schema 기본 구조 (object, properties, type, array, items)**: JSON Schema의 기본적인 구조(object, properties, type, array, items)와 각 요소의 역할 및 사용법을 설명합니다. object는 맵(map)을 나타내고, properties는 객체 내 필드의 스키마를 정의하며, type은 데이터 타입을 지정하고, array와 items는 배열 타입과 배열 요소의 스키마를 정의하는 데 사용됩니다.

- **JSON Schema enum 키워드**: 열거형(enum)을 사용하여 허용된 값의 목록을 정의하는 방법을 설명합니다.

- **JSON Schema required 키워드**: 필수 필드를 지정하는 방법(required)을 설명합니다.

- **JSON Schema를 이용한 데이터 유효성 검증**:  JSON Schema를 사용하여 데이터의 유효성을 검사하는 방법을 보여주고, 유효성 검증 라이브러리 사용에 대한 간략한 소개와 예시를 제공합니다.

- **JSON Schema의 장점**: JSON Schema가 언어 독립적이고, 클래스 기반 데이터 표현보다 더 강력한 유효성 검증 조건을 표현할 수 있다는 점을 강조합니다.

- **JSON Schema의 고급 기능 (간략한 언급)**: JSON Schema의 고급 기능, 예를 들어 숫자 범위 검증, 정규 표현식 일치 검증과 상세 오류 정보 획득 및 서버 응답 유효성 검증에 대한 간략한 언급이 있습니다.


## 부차 화제
- JSON Schema의 역할: JSON Schema가 데이터 표현과 별개로 데이터의 스키마를 정의하는 데 사용됨을 설명합니다. 데이터 유효성 검사(validation)를 위해 사용되며, 데이터 표현과 분리되어 독립적으로 존재합니다.
- JSON Schema의 기본 구조: "object" 타입, "properties" 필드와 "type" 필드를 사용하여 스키마의 기본 골격을 구성하는 방법을 설명합니다.  "properties"는 객체 내 필드의 스키마를 정의하고, "type"은 데이터 타입을 지정합니다.
- JSON Schema의 배열 처리: 배열 내 요소의 데이터 타입(items)을 지정하는 방법을 보여줍니다.
- JSON Schema의 열거형(enumeration) 지원: "enum" 키워드를 사용하여 허용되는 값의 목록을 정의하는 방법을 설명합니다.
- JSON Schema의 필수 필드 지정: "required" 필드를 사용하여 객체 내 필수 필드를 지정하는 방법을 설명합니다.
- JSON Schema를 이용한 데이터 유효성 검사: 데이터 유효성 검사의 개념과 JSON Schema validator 라이브러리를 사용하는 방법을 간략히 설명합니다. 데이터가 스키마를 준수하는지 확인하는 과정이며, validator가 true/false 값을 반환합니다.
- JSON Schema의 언어 독립성: JSON Schema가 다양한 프로그래밍 언어에서 사용될 수 있다는 점과, 그 이유를 설명합니다.
- JSON Schema의 표현력: JSON Schema가 클래스를 사용한 데이터 표현보다 더 복잡한 유효성 검사 조건을 표현할 수 있다는 점을 강조합니다.
- JSON Schema의 고급 기능: 숫자 범위, 정규 표현식 매칭과 같은 고급 유효성 검사 기능에 대한 간략한 언급과, 더 자세한 내용은 추후 챕터에서 다룬다는 점을 안내합니다.
- 데이터 유효성 검사 실패 시 정보 획득: 유효성 검사 실패 시, 왜 실패했는지에 대한 자세한 정보를 얻는 방법에 대한 언급을 합니다.
- 서버 응답의 유효성 검사: 서버에서 클라이언트로 보내는 응답의 유효성 검사 필요성을 언급하고, 검색 결과와 같은 복잡한 데이터 구조의 유효성 검사를 예시로 제시합니다.
