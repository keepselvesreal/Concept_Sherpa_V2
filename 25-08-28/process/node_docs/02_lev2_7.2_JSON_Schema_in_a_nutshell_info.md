## 핵심 내용
JSON Schema는 DOP에서 데이터 유효성 검사를 위한 강력한 도구로, 데이터 표현 방식과 분리된 스키마를 정의합니다. JSON Schema는 데이터 타입, 필수 필드, 허용된 값 등 다양한 규칙을 정의하여 데이터의 유효성을 검증하며, 다양한 프로그래밍 언어에서 활용 가능한 유효성 검사 라이브러리를 지원합니다. 이는 부모 노드에서 언급된 데이터 스키마와 표현의 분리를 실현하는 핵심 기술입니다.

## 7.2 JSON Schema in a nutshell: JSON Schema를 활용한 데이터 유효성 검사

### 핵심 내용 및 JSON Schema 소개
*   **핵심:** JSON Schema를 활용한 데이터 유효성 검사 방법 (부모 노드 핵심 내용 반영).
*   **데이터 유효성 검사 중요성 (재강조):** 데이터 무결성 유지, 시스템 오류 방지, 상세 오류 정보 제공 (7.5절 연계).
*   **JSON Schema 개요 (부모 노드 요약):** 데이터 구조 및 유효성 정의 언어, 데이터 표현과 분리, 언어 독립성 (다양한 언어 지원).

### 도서 검색 요청 스키마 정의 (단계별 상세화, 예시 보강)
1.  **요청 타입 정의:** JSON 객체 ("type": "object") (부모 노드 예시 재확인).
2.  **속성 정의 (상세):** "properties" 사용, 각 필드의 스키마 정의 (부모 노드 예시, 7.3절 연결).
    *   **title:** "string" 타입.
    *   **fields:** "array" 타입.
        *   **items:** 배열 요소 타입 지정 ("string").
        *   **enum:** 허용된 값 목록 지정 (예시: "publishers", "number\_of\_pages"). (부모 노드 예시 재확인).
3.  **필수 필드 정의:** "required" 배열 (예: ["title", "fields"]). (부모 노드 예시 재확인).

### JSON Schema를 이용한 데이터 유효성 검사 (라이브러리 및 에러 처리 강조)
*   **유효성 검사 라이브러리:** Ajv (예시), Snow, JSON.net Schema 등 다양한 언어 지원 (부모 노드 예시 재확인).
*   **검사 결과:** `true`/`false` 반환, 실패 시 상세 오류 정보 (7.5절 연결).
*   **실패 정보 활용:** 시스템 경계에서 유효하지 않은 데이터의 유입을 막고, 오류 메시지를 사용자 친화적으로 제공 (7.1절, 7.5절 연계).

### JSON Schema의 장점 (요약 및 추가)
*   **언어 독립성:** 다양한 언어 지원 (부모 노드 재확인).
*   **표현력:** 클래스 기반보다 복잡한 조건 표현 가능 (범위, 정규식 등).
*   **유연성:** 데이터 표현과 스키마 분리 (부모 노드 재확인).
*   **추가 강조:** 스키마의 재사용과 조합 용이성 (7.4절 연결).

## 상세 정보
7.2 JSON Schema in a nutshell: **7.2 JSON Schema: 기본 개념 및 활용**

이 챕터는 JSON Schema의 기본 개념과 사용법을 소개합니다. 부모 노드에서 설명된 7 Basic data validation 내용과 연계하여, JSON Schema가 데이터 유효성 검증에 어떻게 활용되는지 구체적으로 설명합니다.

**1. JSON Schema의 역할과 중요성 (부모 노드 반영):**

*   **데이터 유효성 검사:** JSON Schema는 데이터 표현과 데이터 스키마를 분리하여, 데이터가 스키마에 정의된 규칙을 준수하는지 검사합니다.
*   **DOP(Data Oriented Programming)에서의 중요성:** DOP에서 데이터의 정확성을 보장하는 데 중요한 역할을 합니다.
*   **언어 독립성:** 다양한 프로그래밍 언어에서 사용할 수 있는 유효성 검사 라이브러리가 존재합니다. (부모 노드 'JSON Schema의 특징' 참고)
*   **검증 실패 시:** Ajv와 같은 Validator Library는 오류 정보를 상세하게 제공하여 문제 해결을 돕습니다. (부모 노드의 '데이터 검증 실패 정보' 참고)

**2. JSON Schema의 기본 구조 (부모 노드 반영):**

*   **최상위 구조:** JSON 객체이며, `type` 과 `properties` 필드를 갖습니다.
    *   `type`: 데이터의 유형을 정의합니다 (예: "object", "string", "array").
    *   `properties`: 객체 내 필드의 스키마를 정의합니다.
*   **객체(object) 타입 스키마:**
    *   `type`: "object"
    *   `properties`: 객체의 각 필드에 대한 스키마 정의
*   **배열(array) 타입 스키마:**
    *   `type`: "array"
    *   `items`: 배열의 각 요소에 대한 스키마 정의
*   **ENUM 사용:** "enum" 키워드를 사용하여 허용되는 값의 목록을 지정합니다. (예: `{"enum": ["value1", "value2"]}`).
*   **필수(required) 필드 지정:** "required" 필드를 사용하여 필수 필드를 정의합니다. (예: `{"required": ["field1", "field2"]}`).

**3. JSON Schema를 사용한 검색 요청 스키마 예시 (부모 노드 예시 활용):**

*   **검색 요청 데이터:**
```json
{
"title": "habit",
"fields": ["title", "weight", "number_of_pages"]
}
```
*   **검색 요청 스키마:**
```json
var searchBooksRequestSchema = {
"type": "object",
"properties": {
"title": {"type": "string"},
"fields": {
"type": "array",
"items": {
"enum": [
"publishers",
"number_of_pages",
"weight",
"physical_format",
"subjects",
"publish_date",
"physical_dimensions"
]
}
}
},
"required": ["title", "fields"]
};
```

**4. JSON Schema 유효성 검사 (부모 노드 내용과 연결):**

*   **유효성 검사 라이브러리:** 다양한 프로그래밍 언어에서 JSON Schema 유효성 검사 라이브러리를 사용할 수 있습니다. (예: Ajv (JavaScript), Snow (Java), JSON.net Schema (C#), jschon (Python), JSONSchemer (Ruby))
*   **validate 함수:**  일반적으로 유효성 검사 라이브러리는 스키마와 데이터를 입력으로 받아 유효성 검사 결과를 반환하는 `validate` 함수를 제공합니다. (유효하면 `true`, 유효하지 않으면 `false`)
*   **유효하지 않은 경우:** 오류 발생 시, Ajv와 같은 라이브러리를 통해 상세한 오류 정보를 얻을 수 있습니다. (부모 노드의 '데이터 검증 실패 정보' 참고)

**5. JSON Schema의 장점 (부모 노드 내용 포함):**

*   **언어 독립성:** 여러 프로그래밍 언어에서 사용 가능.
*   **표현력:** 클래스 기반의 데이터 정의보다 훨씬 더 복잡한 유효성 검사 조건을 표현할 수 있습니다 (예: 숫자 범위, 정규 표현식).
*   **유연성:** 스키마는 객체처럼 조작하고, 스키마를 재사용하여 모듈화를 통해 가독성을 향상시킬 수 있습니다. (부모 노드의 'JSON Schema의 유연성 및 엄격성' 참고)

**6. 추가적인 내용 (부모 노드 내용 참조):**

*   **스키마 구성(schema composition):** 여러 스키마를 조합하여 유효성 검사 규칙을 정의할 수 있습니다. (7.4절에서 자세히 다룰 예정)
*   **고급 유효성 검사:** 숫자 범위, 정규 표현식 등을 사용한 유효성 검사를 12장에서 다룰 예정입니다.
*   **응답 유효성 검사:** 서버 응답의 유효성을 검사하는 방법, 즉 "보내는 것은 엄격하게, 받는 것은 유연하게" 원칙을 적용하는 방법에 대한 간략한 언급이 있었습니다.
*   **오류 정보:** 유효성 검사 실패 시 오류에 대한 상세 정보를 얻는 방법, Ajv와 같은 라이브러리의 활용 (7.5절)

**7. 새로운 내용 (부모 노드 내용을 기반으로 함):**

*   **JSON Schema는 데이터 구조를 정의하고 검증하는 데 사용되며, DOP에서 데이터의 정확성을 보장하는 핵심 요소입니다.**
*   **API 요청 및 응답의 형식을 정의하고, 데이터 유효성을 검사하는 전반적인 과정을 설명하며, 실제 예시를 통해 활용 방안을 제시합니다.**
*   **JSON Schema를 사용하여 API 요청과 응답의 형식을 정의하고, 데이터 유효성을 검사하는 전반적인 과정을 설명합니다. 다양한 언어에서 사용 가능한 JSON Schema 유효성 검사 라이브러리의 목록을 제시하여 실제 구현에 대한 가이드라인을 제공합니다.** ( 부모 노드의 'JSON Schema 유효성 검사' 부분 참고)

- **배열 요소 타입 정의 (items):** 배열 내 요소의 타입을 정의하는 "items" 속성을 사용하는 방법을 설명합니다.

- **필수 필드 지정 (required):** "required" 속성을 사용하여 필수 필드를 지정하는 방법을 설명합니다.
- **JSON Schema를 이용한 유효성 검사:**  데이터 유효성 검사의 개념과 JSON Schema를 사용하여 데이터를 검증하는 방법, 검증 라이브러리의 사용 예시를 보여줍니다.
- **유효성 검사의 결과와 실패 시의 처리:** 유효성 검사 결과 (true/false)를 보여주고, 더 자세한 오류 정보를 얻는 방법과 고급 검증 (범위, 정규식)에 대한 간략한 언급을 합니다.
