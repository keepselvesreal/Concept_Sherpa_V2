## 핵심 내용
JSON Schema는 JSON 데이터의 구조와 유효성을 정의하는 언어입니다. 객체, 속성, 자료형, 배열, 열거형, 필수 필드 등을 사용하여 데이터의 형식을 명세하고, 다양한 프로그래밍 언어에서 사용할 수 있는 유효성 검사 라이브러리를 통해 데이터가 스키마에 부합하는지 검사할 수 있습니다.

## 7.2 JSON Schema in a nutshell 상세 정리

### 1. 소개 및 배경

*   **목표:** 웹 서버 구축을 위한 데이터 유효성 검사 및 데이터 스키마 정의.
*   **문제 상황:** 메모리 기반의 라이브러리 관리 시스템을 웹 서버로 확장해야 함.
*   **해결책:** JSON Schema를 사용하여 클라이언트 요청의 데이터 구조를 정의하고 유효성을 검사.
*   **DOP (Data-Oriented Programming) 관점:** 데이터 표현과 데이터 스키마를 분리하여 독립적으로 관리.

### 2. JSON Schema 기본 개념

*   **정의:** JSON 데이터의 구조와 유효성을 정의하는 스키마 언어.
*   **데이터 타입:** 객체(object), 문자열(string), 배열(array) 등 다양한 데이터 타입을 지원.
*   **핵심 속성:** `type`, `properties`, `items`, `enum`, `required`.

### 3. 검색 요청 스키마 예시

*   **요청 구조:** `title`(문자열), `fields`(문자열 배열)
*   **기본 스키마 (Listing 7.2):**
    ```json
    {
      "type": "object",
      "properties": {...}
    }
    ```
*   **필드 타입 정의 (Listing 7.3):**
    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {"type": "array"}
      }
    }
    ```
*   **배열 요소 타입 정의 (Listing 7.4):**
    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {"type": "string"}
        }
      }
    }
    ```
*   **enum을 이용한 허용된 필드 값 정의 (Listing 7.5):**
    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {
            "enum": [
              "publishers",
              "number_of_pages",
              "weight",
              ...
            ]
          }
        }
      }
    }
    ```
*   **필수 필드 지정 (Listing 7.6):**
    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {
            "enum": [
              "publishers",
              "number_of_pages",
              "weight",
              ...
            ]
          }
        }
      },
      "required": ["title", "fields"]
    }
    ```

### 4. 데이터 유효성 검사

*   **검사:** 데이터가 스키마에 정의된 구조와 규칙을 준수하는지 확인.
*   **검사 라이브러리:** 다양한 프로그래밍 언어에서 JSON Schema 유효성 검사 라이브러리 제공 (예: Ajv, Snow, JSON.net Schema, jschon, JSONSchemer).
*   **검사 예시 (Listing 7.8):**
    *   유효한 데이터는 `true` 반환.
    ```javascript
    validate(searchBooksRequestSchema, searchBooksRequest); // → true
    ```
*   **유효하지 않은 데이터 예시 (Listing 7.9):**
    *   유효하지 않은 데이터는 `false` 반환.
    ```javascript
    validate(searchBooksRequestSchema, invalidSearchBooksRequest); // → false
    ```

### 5. JSON Schema의 장점 및 활용

*   **언어 독립성:** 다양한 프로그래밍 언어에서 사용 가능.
*   **표현력:** 클래스 기반의 데이터 표현보다 더 복잡한 유효성 검사 조건 정의 가능. (예: 범위 검사, 정규 표현식 검사, chapter 12 참조)
*   **유효성 검사 실패 시 정보:** 유효성 검사 실패 이유에 대한 상세 정보 획득 가능.

## 7.2 JSON Schema in a nutshell - 추가 정보 및 상세 내용

다음은 "7.2 JSON Schema in a nutshell" 내용을 바탕으로, 기존 내용에서 다루지 않은 추가적인 상세 정보와 새로운 내용을 식별하여 정리한 것입니다.

**1. JSON Schema의 핵심 개념 및 용어:**

*   **Data Schema:** 데이터의 구조와 유효성을 정의하는 규칙의 집합. 데이터 표현(Data Representation)과 분리되어 관리된다. (DOP, Data Oriented Programming의 핵심 개념).
*   **Data Validation:**  데이터가 스키마에 부합하는지 검증하는 과정. 스키마를 사용하여 데이터를 검사하고, 데이터의 유효성을 보장한다.
*   **Object (JSON Schema 타입):** JSON 객체를 나타내는 데이터 타입. `type: "object"`로 정의되며, `properties` 필드를 통해 객체 내 각 필드의 스키마를 정의한다.
*   **Properties:**  JSON 객체 내 필드들의 스키마를 정의하는 맵 (key-value 쌍). 각 key는 필드 이름을, value는 해당 필드의 JSON Schema를 나타낸다.
*   **Type:**  JSON Schema에서 데이터 타입을 지정하는 키워드. 예: "string", "array", "object".
*   **Array (JSON Schema 타입):** 배열을 나타내는 데이터 타입. `type: "array"`로 정의되며, `items` 필드를 통해 배열 요소의 스키마를 정의한다.
*   **Items:**  배열 요소의 스키마를 정의하는 필드. 배열 내 각 요소의 데이터 타입을 지정할 때 사용된다.
*   **Enum:**  허용되는 값의 목록(열거형)을 지정하는 키워드. 특정 필드가 가질 수 있는 값들을 제한할 때 사용된다. `{"enum": [...]}` 형식으로 사용하며, 배열 내에 허용되는 값들을 나열한다.
*   **Required:**  필수 필드를 지정하는 키워드.  `{"required": ["field1", "field2"]}` 형식으로 사용하며, 필수 필드의 이름을 배열로 지정한다.

**2. JSON Schema의 활용:**

*   **데이터 구조 정의:**  JSON Schema를 사용하여 JSON 데이터의 구조(필드, 타입 등)를 명확하게 정의할 수 있다.
*   **데이터 유효성 검사:**  JSON Schema validator 라이브러리를 사용하여 JSON 데이터가 정의된 스키마에 부합하는지 검증할 수 있다.  (예: `validate(searchBooksRequestSchema, searchBooksRequest)`)
*   **데이터 교환 및 통신:**  JSON Schema는 다양한 프로그래밍 언어에서 사용할 수 있으므로,  데이터 교환 및 통신 시 데이터의 유효성을 보장하는 데 유용하다.
*   **API 개발:**  API 요청 및 응답의 스키마를 정의하여 API의 안정성과 일관성을 높일 수 있다.

**3. JSON Schema의 장점:**

*   **언어 독립성:**  JSON Schema는 프로그래밍 언어에 독립적이므로, 다양한 환경에서 사용할 수 있다.
*   **표현력:**  클래스를 사용하여 데이터를 표현하는 것보다 더 복잡하고 다양한 유효성 검사 조건을 표현할 수 있다 (예: 숫자 범위, 정규식).

**4.  예제 및 코드 설명:**

*   **Listing 7.1 (검색 요청 예시):**

    ```json
    {
      "title": "habit",
      "fields": ["title", "weight", "number_of_pages"]
    }
    ```

    검색 요청의 실제 데이터를 나타낸다. "title"과 "fields" 필드를 포함한다.
*   **Listing 7.2 (객체 스키마 기본 골격):**

    ```json
    {
      "type": "object",
      "properties": {...}
    }
    ```

    JSON Schema에서 객체의 기본 구조를 나타낸다.  `type`은 객체임을, `properties`는 객체의 필드 스키마를 정의함을 나타낸다.
*   **Listing 7.3 (검색 요청 스키마 골격):**

    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {"type": "array"}
      }
    }
    ```

    검색 요청의 기본 스키마. "title"은 문자열, "fields"는 배열임을 정의한다.
*   **Listing 7.4 (배열 요소 타입 정보 추가):**

    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {"type": "string"}
        }
      }
    }
    ```

    "fields" 배열의 요소 타입이 문자열임을 명시적으로 지정한다.
*   **Listing 7.5 (열거형 값 사용):**

    ```json
    {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {
            "enum": [
              "publishers",
              "number_of_pages",
              "weight",
              "physical_format",
              "subjects",
              "publish_date",
              "physical_dimensions"
            ]
          }
        }
      }
    }
    ```

    "fields" 배열의 요소가 미리 정의된 값들 중 하나여야 함을 나타낸다.
*   **Listing 7.6 (검색 요청 스키마):**

    ```javascript
    var searchBooksRequestSchema = {
      "type": "object",
      "properties": {
        "title": {"type": "string"},
        "fields": {
          "type": "array",
          "items": {
            "enum": [
              "publishers",
              "number_of_pages",
              "weight",
              "physical_format",
              "subjects",
              "publish_date",
              "physical_dimensions"
            ]
          }
        }
      },
      "required": ["title", "fields"]
    };
    ```

    검색 요청의 완전한 JSON Schema. "title"과 "fields"가 필수 필드임을 명시한다.
*   **Listing 7.7 (유효한 검색 요청 예시):**

    ```json
    {
      "title": "habit",
      "fields": ["title", "weight", "number_of_pages"]
    }
    ```

    정상적인 검색 요청 데이터를 나타낸다.
*   **Listing 7.8 (유효성 검사 예시):**

    ```javascript
    var searchBooksRequestSchema = { ... }; // Listing 7.6과 동일
    var searchBooksRequest = {
      "title": "habit",
      "fields": ["title", "weight", "number_of_pages"]
    };
    validate(searchBooksRequestSchema, searchBooksRequest); // → true
    ```

    유효성 검사 함수를 사용하여 유효한 데이터를 검증하는 예시.
*   **Listing 7.9 (유효하지 않은 검색 요청 예시):**

    ```javascript
    var invalidSearchBooksRequest = {
      "tilte": "habit",
      "fields": ["title", "weight", "number_of_pages"]
    };
    validate(searchBooksRequestSchema, invalidSearchBooksRequest); // → false
    ```

    "title" 필드에 오타가 있는 유효하지 않은 데이터를 검증하는 예시.

**5.  향후 학습 내용에 대한 힌트:**

*   **스키마 조합 (Schema Composition):**  더 복잡한 스키마를 만들기 위해 여러 스키마를 조합하는 방법.
*   **고급 유효성 검사 (Advanced Validation):** 숫자 범위, 정규식 등을 사용하여 더욱 정교한 유효성 검사를 수행하는 방법.  (챕터 12에서 다룸)
*   **유효성 검사 결과 상세 정보:**  유효성 검사 실패 시 오류 이유를 자세히 얻는 방법.

## 주요 화제
- **JSON Schema 소개 및 목적:** JSON Schema가 데이터 유효성 검사(validation)를 위한 스키마 언어임을 설명하고, 데이터 표현과 스키마를 분리하는 DOP (Data-Oriented Programming)의 이점을 언급합니다. JSON Schema의 언어 독립성을 강조합니다.
- **검색 요청 스키마 구축:** 검색 요청 데이터의 스키마를 JSON Schema를 사용하여 구축하는 과정을 보여줍니다. `type`, `properties`, `items`, `enum`, `required` 등의 JSON Schema 키워드를 활용하여 스키마를 정의합니다.
- **JSON Schema를 사용한 데이터 유효성 검사:** 데이터 유효성 검사의 개념과 JSON Schema를 사용한 유효성 검사 방법 (예: `validate` 함수)을 설명합니다. 유효한 요청과 유효하지 않은 요청을 검사하는 예제를 제공합니다.
- **JSON Schema의 장점 및 활용:** JSON Schema가 클래스 멤버를 선언하는 것보다 더 상세한 유효성 검사 조건을 표현할 수 있으며, 다양한 프로그래밍 언어에서 사용될 수 있다는 장점을 강조합니다.
- **고급 유효성 검사 및 추가 기능 (향후 언급):** 숫자 범위, 정규 표현식 일치 등 고급 유효성 검사 기능과 유효성 검사 실패 시의 세부 정보 획득 가능성에 대해 언급하며, 서버 응답 유효성 검사의 중요성을 간략하게 설명합니다.
- **JSON Schema 유효성 검사 라이브러리:** 다양한 프로그래밍 언어(JavaScript, Java, C#, Python, Ruby)에서 사용 가능한 JSON Schema 유효성 검사 라이브러리를 소개합니다.

- **JSON Schema 언어 소개**: JSON Schema 언어에 대한 간략한 소개와 공식 웹사이트(json-schema.org) 언급
- **JSON Schema 기본 구조**:  `type` (데이터 타입)과 `properties` (필드별 스키마 정의)
- **JSON Schema의 `array` 타입과 `items` 속성**: 배열의 요소 타입 정의
- **JSON Schema의 `enum` 키워드**:  허용되는 값의 목록을 정의 (열거형)
- **JSON Schema의 `required` 속성**:  필수 필드 지정
- **JSON Schema 유효성 검사 라이브러리**: JavaScript, Java, C#, Python, Ruby 등 다양한 언어에서 사용 가능한 라이브러리 목록과 URL 제공
- **유효성 검사 결과**:  유효성 검사 결과 (true/false), 실패 시 오류 정보 획득 가능성
- **JSON Schema의 표현력**: 클래스 기반의 데이터 표현보다 강력한 표현력 (언어 독립성, 고급 검사 조건 표현 가능)
- **고급 유효성 검사 예시**: 숫자 범위, 정규 표현식 기반 검사 (챕터 12에서 자세히 다룸)
- **서버 응답 유효성 검사**: 검색 요청뿐만 아니라 서버 응답에 대한 유효성 검사 필요성 언급
