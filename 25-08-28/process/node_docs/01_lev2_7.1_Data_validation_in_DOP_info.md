## 핵심 내용
DOP에서 데이터 유효성 검사는 시스템 경계에서 가장 중요하며, 클라이언트, 데이터베이스, 웹 서비스 간의 데이터 교환에서 유효성 검사를 수행합니다. 시스템 경계에서 유효한 데이터를 보장하면 내부 데이터 유효성 검사의 필요성을 줄여 오류를 방지하고 시스템의 안정성을 높일 수 있습니다.


## 상세 핵심 내용
## 7.1 Data validation in DOP: 상세 분석

### 배경: OOP와 DOP의 데이터 검증 비교

*   **OOP의 장점**: 객체 지향 프로그래밍(OOP)에서는 클래스 인스턴스화 시 멤버 필드의 이름과 타입이 보장되어 데이터의 유효성을 쉽게 관리할 수 있습니다.
*   **DOP의 문제점**: 데이터 지향 프로그래밍(DOP)에서는 필드 이름과 타입에 대한 작은 실수로 인해 데이터 일관성 문제가 발생하기 쉽습니다.

### DOP에서의 데이터 검증 가능성

*   **DOP는 데이터 검증을 강제하지 않지만, 금지하지도 않습니다.** DOP에서는 데이터 스키마가 데이터 표현과 분리되어 있습니다.

### 시스템 경계에서의 데이터 검증 중요성

*   **시스템 경계 정의**: 데이터 교환이 일어나는 지점 (예: 웹 서버와 클라이언트, 웹 서버와 데이터베이스, 웹 서비스)
*   **시스템 경계 예시 (웹 서버):**
    *   **클라이언트 경계:** 웹 브라우저 등
    *   **데이터베이스 경계:** 데이터 저장소
    *   **웹 서비스 경계:** 다른 서비스와의 통신

*   **시스템 경계 데이터 검증의 중요성**: 시스템으로 들어오고 나가는 데이터의 유효성을 확보하면, 시스템 내부에서 예상치 못한 데이터가 발생할 가능성이 줄어듭니다.
*   **TIP**: 시스템 경계에서 데이터가 유효하면, 시스템 내부에서 데이터를 다시 검증할 필요가 없습니다.

### 두 가지 종류의 데이터 검증

*   **경계에서의 검증**: 시스템의 출입 데이터의 유효성을 검사 (가디언, 프로덕션 환경)
    *   **목적**: 시스템으로 들어오고 나가는 데이터의 유효성 확보, 유효하지 않은 데이터 발생 시 정보 오류 표시
*   **내부에서의 검증**: 코드베이스 증가에 따른 개발 편의성을 위해 사용 (개발 환경)
    *   **목적**: 개발 편의성

### 요약

DOP에서 데이터 유효성 검증은 중요하며, 특히 시스템 경계에서 데이터를 검증하는 것이 핵심입니다. 시스템 내부의 데이터 검증은 개발 편의성을 위한 부가적인 기능입니다.


## 상세 정보
## 7.1 Data validation in DOP 분석 및 추가 정보 정리

이 문서에서는 DOP(Data-Oriented Programming)에서의 데이터 유효성 검증에 대한 내용을 다루고 있습니다. OOP(Object-Oriented Programming)와 비교하여 DOP에서 데이터 유효성 검증의 중요성과 방법에 대한 설명을 제공합니다.

**핵심 내용 요약:**

*   **DOP에서의 데이터 유효성 검증의 필요성:** OOP와 달리 DOP에서는 데이터 구조가 유연하기 때문에, 데이터 필드 이름이나 타입에 작은 실수로 인해 데이터 일관성 문제가 발생할 수 있습니다.
*   **시스템 경계에서의 데이터 유효성 검증의 중요성:** DOP에서는 시스템 경계에서 데이터 유효성 검증을 가장 중요하게 생각합니다. 시스템 경계는 클라이언트, 데이터베이스, 웹 서비스 등과 같이 시스템이 데이터를 주고받는 영역을 의미합니다.
*   **시스템 경계와 내부 데이터 유효성 검증의 구분:** 시스템 경계에서의 데이터 유효성 검증은 주로 유효하지 않은 데이터의 유입 및 유출을 막는 것을 목표로 하며, 내부 데이터 유효성 검증은 개발 편의성을 위해 사용됩니다.
*   **데이터 유효성 검증 목적:**
    *   **경계:** 유효하지 않은 데이터의 유입/유출 방지 및 오류 정보 표시
    *   **내부:** 개발 용이성 (코드베이스가 커질 때)

**추가적인 상세 정보 및 새로운 내용:**

1.  **데이터 유효성 검증의 중요성 강조:**
    *   **OOP와의 비교:** OOP에서는 클래스 인스턴스화 시 멤버 필드의 이름과 타입이 보장되지만, DOP에서는 이 보장이 없기 때문에 데이터 유효성 검증이 더욱 중요합니다.
    *   **문제 발생 가능성:** 필드 이름이나 타입의 작은 실수로 인해 데이터 일관성 문제가 발생할 수 있습니다.

2.  **시스템 경계의 정의 및 예시:**
    *   **정의:** 시스템이 데이터를 주고받는 영역
    *   **예시:**
        *   **클라이언트 경계:** 웹 브라우저와 같은 클라이언트
        *   **데이터베이스 경계:** 데이터베이스와의 통신
        *   **웹 서비스 경계:** 웹 서비스와의 통신

3.  **시스템 경계에서의 데이터 유효성 검증의 구체적인 목적:**
    *   **유효하지 않은 데이터의 유입/유출 방지:** 시스템에 들어오거나 나가는 데이터의 무결성을 유지합니다.
    *   **오류 정보 표시:** 유효하지 않은 데이터가 발견될 경우, 사용자에게 정확하고 이해하기 쉬운 오류 메시지를 제공합니다.

4.  **두 가지 종류의 데이터 유효성 검증의 차이점 (Table 7.1):**
    *   **경계:**
        *   **목적:** 유효하지 않은 데이터의 유입/유출 방지 및 오류 정보 표시
        *   **환경:** 프로덕션 환경에서 데이터의 무결성을 유지 (Guardian 역할)
    *   **내부:**
        *   **목적:** 개발 편의성
        *   **환경:** 개발 환경에서 코드의 가독성과 유지 보수성을 향상 (개발 편의성)

5.  **DOP에서의 데이터 유효성 검증의 구현 방식 (암시적):**
    *   DOP에서는 데이터 스키마와 데이터 표현이 분리되어 있기 때문에, JSON Schema와 같은 스키마 정의 언어를 활용하여 데이터 유효성 검증을 구현할 수 있습니다. (7.2 절에서 자세히 다룰 예정)
    *   시스템 경계에서 JSON Schema를 사용하여 데이터의 구조와 타입을 정의하고, 들어오고 나가는 데이터를 이 스키마에 따라 검증합니다.

**결론:**

이 챕터는 DOP에서 데이터 유효성 검증의 필요성을 강조하고, 시스템 경계에서의 검증의 중요성을 설명합니다. 또한, 두 종류의 데이터 유효성 검증의 목적과 환경을 비교하고, 다음 챕터에서 JSON Schema를 활용한 구체적인 구현 방법을 제시할 것을 암시합니다.

## 주요 화제
- **데이터 유효성 검증의 중요성:** DOP에서의 데이터 유효성 검증의 필요성과 중요성을 강조하며, OOP와 비교하여 DOP에서 데이터 유효성 검증이 왜 중요한지 설명합니다.
- **DOP에서의 데이터 유효성 검증 방법:** DOP가 데이터 유효성 검증을 강제하지는 않지만, 데이터를 유효성 검증하는 방법을 제공하며, 데이터 스키마와 데이터 표현의 분리를 언급합니다.
- **시스템 경계에서의 데이터 유효성 검증:** 웹 서버와 같은 시스템의 경계를 정의하고, 시스템 경계에서의 데이터 유효성 검증이 가장 중요함을 강조합니다. 클라이언트, 데이터베이스, 웹 서비스 간의 데이터 교환 경계를 예시로 제시합니다.
- **시스템 경계 및 내부 데이터 유효성 검증의 차이점:** 시스템 경계에서의 유효성 검증과 내부에서의 유효성 검증의 목적, 환경, 중요성을 비교하여 설명합니다. 경계에서의 유효성 검증이 오류를 방지하고, 내부에서의 유효성 검증은 개발 편의성을 높이는 데 중점을 둔다는 점을 강조합니다.
- **데이터 유효성 검증의 목적:** 시스템 경계에서의 데이터 유효성 검증의 주요 목적 (유효하지 않은 데이터 유입/유출 방지, 오류 정보 제공)을 설명합니다.


## 부차 화제
- DOP와 OOP의 차이점: OOP에서 데이터 검증의 용이함과 DOP에서의 어려움 비교.
- 시스템 경계의 정의: 데이터 교환이 일어나는 영역을 시스템 경계로 정의.
- 웹 서버 아키텍처: 클라이언트, 웹 서버, 웹 서비스, 데이터베이스 간의 데이터 흐름과 경계 시각화.
- 시스템 경계에서의 데이터 검증 중요성: 시스템 경계에서 데이터 검증이 왜 중요하고, 내부 데이터 검증과 비교하여 어떤 이점을 가지는지 설명.
- 데이터 검증의 종류: 시스템 경계에서의 데이터 검증(Guardian, Production)과 내부 데이터 검증(Ease of development, Dev)의 목적과 환경 비교.
- 데이터 검증 목적: 시스템 경계에서의 데이터 검증의 주요 목적 (유효하지 않은 데이터 유입/유출 방지, 정보 오류 표시)
