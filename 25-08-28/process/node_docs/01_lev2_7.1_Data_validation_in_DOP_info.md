## 핵심 내용
DOP에서 데이터 유효성 검사는 시스템 경계(클라이언트, 데이터베이스, 웹 서비스)에서 가장 중요하며, 시스템 안의 유효성 검사보다 우선순위가 높습니다. 경계에서의 유효성 검사는 시스템 내/외부로 오가는 데이터의 무결성을 보장하고 오류를 방지하는 데 목적이 있습니다.


## 상세 핵심 내용
## 7.1 Data Validation in DOP: 상세 분석

### 도입부: DOP에서의 데이터 검증의 중요성

*   **문제 제기:** OOP(객체 지향 프로그래밍)에서 데이터 검증이 보장되는 것과 달리, DOP(데이터 지향 프로그래밍)에서는 필드 이름 및 타입의 작은 실수로 인해 데이터 일관성 문제가 발생할 수 있다는 점이 제기됩니다.
*   **해결책 제시:** DOP에서도 데이터 검증이 가능하며, 시스템 경계에서 데이터를 검증하는 것이 중요합니다.

### DOP에서의 데이터 검증 원리

*   **DOP의 특징:** DOP는 데이터 스키마와 데이터 표현이 분리되어 있습니다. 이는 데이터 검증을 수행하는 데 있어서 중요한 기반이 됩니다.
*   **데이터 검증의 초점:** DOP에서 가장 중요한 데이터 검증은 시스템 경계를 넘나드는 데이터에 집중합니다.

### 시스템 경계의 정의 및 예시

*   **시스템 경계:** 시스템이 데이터를 교환하는 영역을 의미합니다.
*   **예시 (웹 서버):**
    *   클라이언트 경계 (웹 브라우저 등)
    *   데이터베이스 경계
    *   웹 서비스 경계

### 데이터 검증의 종류 및 중요성

*   **두 가지 종류의 데이터 검증:**
    *   **경계에서의 검증:** 시스템의 입출력 데이터를 검증합니다. (Guardian, Production 환경)
    *   **내부에서의 검증:** 코드 개발의 용이성을 위해 내부 데이터를 검증합니다. (Dev 환경)
*   **경계에서의 검증의 중요성:** 시스템의 경계에서 데이터가 유효한지 확인하면, 시스템 내부에서 예상치 못한 데이터가 발생할 확률을 줄일 수 있습니다.
*   **내부 검증의 목적:** 코드베이스가 커짐에 따라 개발 편의성을 높입니다.

### 데이터 검증의 목적

*   **경계에서의 검증 목적:**
    *   유효하지 않은 데이터의 시스템 유입 및 유출 방지.
    *   유효하지 않은 데이터를 발견했을 때, 유용한 오류 메시지 제공.

### 데이터 검증 요약 표 (Table 7.1)

| 종류                     | 목적                                     | 환경   |
| :----------------------- | :---------------------------------------- | :----- |
| 경계에서의 데이터 검증 | 시스템 입출력 데이터의 유효성 검증          | Production |
| 내부에서의 데이터 검증  | 개발 편의성                                 | Dev      |

*   **세부 정보:** 시스템 경계에서의 데이터 유효성 검증이 우선적으로 중요합니다. 경계에서 데이터의 유효성을 확보하면 시스템 내부에서 예상치 못한 데이터가 발생할 가능성이 줄어듭니다.

## 주요 화제
- **DOP에서의 데이터 검증 필요성:** OOP와 달리 DOP에서 데이터 검증이 왜 필요한지, Theo의 경험을 통해 DOP에서의 데이터 검증의 중요성을 강조합니다.
- **DOP에서의 데이터 검증 방법:** DOP가 데이터 검증을 강제하지 않지만, 데이터 검증을 수행할 수 있는 방법을 제시하며, 데이터 스키마와 데이터 표현의 분리를 언급합니다.
- **시스템 경계:** 시스템 경계의 정의와 중요성, 웹 서버 아키텍처 다이어그램을 통해 클라이언트, 데이터베이스, 웹 서비스 간의 경계를 설명합니다.
- **데이터 검증의 두 가지 종류:** 시스템 경계에서의 데이터 검증과 시스템 내부에서의 데이터 검증을 구분하고, 각각의 목적과 환경을 설명합니다.
- **시스템 경계에서의 데이터 검증의 중요성:** 시스템 경계에서의 데이터 검증이 왜 더 중요한지, 그리고 그 목적에 대해 설명합니다.
- **시스템 내부에서의 데이터 검증의 필요성:** 시스템 내부에서의 데이터 검증이 코드 개발의 용이성을 위해 필요하다는 것을 언급합니다.


## 부차 화제
- OOP와 DOP의 데이터 유효성 검사 비교: OOP에서 클래스 인스턴스화 시 멤버 필드의 이름과 유형이 보장되는 반면, DOP에서는 필드 이름 및 유형의 작은 실수 가능성이 높다는 점을 비교하며 DOP에서의 데이터 유효성 검사의 필요성을 제기합니다.
- 웹 서버 아키텍처와 시스템 경계: 웹 서버와 클라이언트, 데이터 소스, 웹 서비스, 데이터베이스 간의 데이터 교환을 보여주는 웹 서버의 아키텍처 다이어그램을 제시하고, 데이터 교환이 일어나는 경계를 정의합니다.
- 시스템 경계의 종류: 클라이언트 경계, 데이터베이스 경계, 웹 서비스 경계, 총 3가지 시스템 경계를 제시하고, 각 경계에서 데이터 유효성 검사의 중요성을 강조합니다.
- 경계에서의 데이터 유효성 검사의 중요성: 시스템 경계에서 데이터 유효성 검사를 먼저 수행하면 시스템 내부에서 예상치 못한 데이터 발생 확률을 낮출 수 있다는 점을 강조하며, 시스템 내부에서의 유효성 검사는 개발 편의성을 위해 필요하다고 설명합니다.
- 데이터 유효성 검사의 목적과 환경: 경계에서의 데이터 유효성 검사의 목적은 유효하지 않은 데이터의 출입을 방지하고 오류 발생 시 정보를 제공하는 것이며, 생산 환경(production)에서 주로 사용됩니다. 시스템 내부의 데이터 유효성 검사는 개발 환경(dev)에서 개발 편의성을 위해 사용됩니다.
