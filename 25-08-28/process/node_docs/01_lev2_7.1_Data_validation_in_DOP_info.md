## 핵심 내용
DOP에서 데이터 유효성 검사는 시스템 경계를 넘어 데이터가 오갈 때 가장 중요하며, 외부에서 유효하지 않은 데이터 유입을 막고 오류를 적절하게 표시하는 것을 목표로 합니다. 시스템 내부의 데이터 유효성 검사는 코드베이스 확장을 용이하게 하는 데 목적이 있습니다.


## 상세 핵심 내용
## 7.1 Data validation in DOP: 상세 내용 정리

### 1. 도입: DOP에서의 데이터 검증 필요성

*   Theo는 DOP에서 데이터 검증의 부재에 대한 우려를 표명. OOP에서는 클래스 인스턴스화 시 멤버 필드의 이름과 타입이 보장되지만, DOP에서는 오류 발생 가능성이 높음.
*   Joe는 DOP에서도 데이터 검증이 가능하다고 설명. DOP는 데이터 검증을 강제하지 않지만, 이를 방해하지도 않음.

### 2. DOP와 데이터 스키마의 분리

*   DOP에서 데이터 스키마는 데이터 표현과 분리되어 있음. 이로 인해 데이터 일관성 문제가 발생할 수 있다는 Theo의 우려에 Joe는 데이터 검증을 통해 해결 가능하다고 설명.

### 3. 시스템 경계에서의 데이터 검증

*   **핵심 개념**: DOP에서 가장 중요한 데이터 검증은 시스템 경계를 넘나드는 데이터에 대한 검증.
*   **시스템 경계**: 시스템이 데이터를 교환하는 영역. (예: 웹 서버 - 클라이언트, 웹 서버 - 데이터베이스, 웹 서버 - 웹 서비스)
*   **예시**: 웹 서버의 경우, 클라이언트, 데이터베이스, 웹 서비스와의 경계.
*   **중요성**: 시스템 경계에서 데이터 유효성을 확보하면 내부에서 예상치 못한 데이터가 발생할 가능성이 낮아짐.

### 4. 데이터 검증의 두 가지 종류

*   **경계에서의 검증**: 시스템의 입출력 데이터 검증.
    *   **목적**: 유효하지 않은 데이터의 유입 및 유출 방지, 오류 발생 시 정보 제공.
    *   **환경**: 프로덕션 환경 (Guardian)
*   **내부 검증**: 개발 용이성을 위한 코드 내 검증.
    *   **목적**: 개발 편의성 증진.
    *   **환경**: 개발 환경 (Dev)

### 5. 결론

*   시스템 경계에서의 데이터 검증이 가장 중요하며, 내부 검증은 코드베이스가 커짐에 따라 개발 편의성을 위해 필요.
*   본 챕터에서는 시스템 경계에서의 데이터 검증에 집중.

## 7.1 Data Validation in DOP - 추가 상세 정보 및 새로운 내용 분석

이 챕터는 DOP(Data-Oriented Programming)에서 데이터 유효성 검사의 중요성을 강조하며, 특히 시스템 경계에서의 유효성 검사에 초점을 맞춥니다. 기존 내용 외에 다음과 같은 새로운 정보와 세부 사항을 식별할 수 있습니다.

**1. Theo의 OOP 경험과 DOP의 차이점 (페이지 170):**

*   **세부 사항:** OOP에서는 클래스 인스턴스 생성 시 멤버 필드의 이름과 타입이 보장되는 반면, DOP에서는 필드 이름 및 타입의 작은 실수로 인해 오류가 발생하기 쉽다는 점을 지적합니다.
*   **새로운 내용:** Theo의 경험을 통해 OOP 개발자가 DOP로 전환할 때 겪을 수 있는 어려움을 구체적으로 제시하며, 데이터 유효성 검사의 부재가 주요 문제점임을 강조합니다.

**2. 시스템 경계 (Boundaries)의 정의 및 중요성 (페이지 170-171):**

*   **세부 사항:** 시스템 경계는 시스템이 데이터를 교환하는 영역으로 정의됩니다. 웹 서버의 경우 클라이언트, 데이터베이스, 웹 서비스가 시스템 경계에 해당합니다.
*   **예시:** 웹 서버 아키텍처 다이어그램(Figure 7.1)을 통해 시스템 경계를 시각적으로 표현합니다.
*   **새로운 내용:** 시스템 경계를 명확히 정의하고, 경계에서 발생하는 데이터 유효성 검사의 중요성을 강조합니다. 시스템 경계에서 데이터 유효성 검사를 수행하면, 내부에서의 데이터 유효성 검사 필요성이 줄어든다는 점을 시사합니다.

**3. 데이터 유효성 검사의 두 가지 종류 (페이지 171):**

*   **세부 사항:**
    *   **경계에서의 유효성 검사:** 시스템의 입력과 출력 데이터를 보호하는 'Guardian' 역할. 프로덕션 환경에서 중요.
    *   **내부에서의 유효성 검사:** 개발 편의성을 높이기 위한 역할. 개발 환경에서 중요.
*   **새로운 내용:** 두 가지 유형의 유효성 검사를 명확히 구분하고, 각 유형의 목적과 환경을 Table 7.1을 통해 시각적으로 제시합니다. 내부 유효성 검사의 목적이 개발 편의성에 있음을 명확히 합니다.

**4. 시스템 경계에서의 데이터 유효성 검사의 주요 목적 (페이지 171):**

*   **세부 사항:**
    *   유효하지 않은 데이터의 시스템 유입 및 유출 방지.
    *   유효하지 않은 데이터를 발견했을 때, 유용한 오류 메시지 표시.
*   **새로운 내용:** 경계에서의 유효성 검사가 시스템의 보안과 안정성을 확보하는 데 중요한 역할을 함을 명시합니다. 오류 메시지 표시를 언급하며, 사용자 경험 개선의 측면도 강조합니다.

**5. 추가적인 팁 (페이지 171):**

*   **세부 사항:** 시스템 경계에서 데이터 유효성 검사가 이루어지면, 내부에서 동일한 검사를 반복할 필요가 없다는 점을 강조합니다.
*   **새로운 내용:** 데이터 유효성 검사의 효율성을 높이는 방법을 제시하며, 중복 검사의 불필요성을 언급합니다.

**요약:**

이 챕터는 DOP에서 데이터 유효성 검사의 필요성을 강조하고, 특히 시스템 경계에서의 유효성 검사의 중요성을 설명합니다. 새로운 내용은 다음과 같습니다:

*   OOP와 DOP의 차이점, 특히 데이터 유효성 검사 측면에서의 차이점.
*   시스템 경계의 정의와 예시.
*   두 가지 유형의 데이터 유효성 검사 (경계, 내부)와 각 유형의 목적.
*   경계에서의 데이터 유효성 검사의 주요 목적 (데이터 보호, 오류 메시지).
*   경계 유효성 검사 후 내부 중복 검사의 불필요성.

이러한 상세 정보들은 DOP에서 데이터 유효성 검사를 어떻게 구현하고, 시스템의 안정성을 확보할 수 있는지에 대한 기본적인 이해를 제공합니다.


## 주요 화제
- **DOP에서의 데이터 유효성 검증의 필요성:** OOP와 달리 DOP에서는 데이터 유효성 검증이 강제되지 않지만, 이를 수행할 수 있으며, 데이터 유효성 검증이 중요한 이유가 설명됩니다.
- **DOP에서의 데이터 스키마와 데이터 표현의 분리:** DOP에서 데이터 스키마와 데이터 표현이 분리되어 데이터 유효성 검증을 가능하게 한다는 점을 언급합니다.
- **시스템 경계에서의 데이터 유효성 검증의 중요성:** 웹 서버와 같은 시스템에서 데이터 유효성 검증은 시스템 경계(클라이언트, 데이터베이스, 웹 서비스)에서 가장 중요하며, 시스템 안에서의 데이터 유효성 검증보다 우선시되어야 한다는 점을 강조합니다.
- **시스템 경계의 정의:** 시스템 경계를 시스템이 데이터를 교환하는 영역으로 정의하며, 클라이언트, 데이터베이스, 웹 서비스를 예시로 제시합니다.
- **데이터 유효성 검증의 두 가지 종류:** 시스템 경계에서의 데이터 유효성 검증과 시스템 내부에서의 데이터 유효성 검증을 구분하고, 목적과 환경을 비교합니다.
- **시스템 경계 데이터 유효성 검증의 목적:** 시스템 경계에서 유효하지 않은 데이터의 유입/유출을 막고, 오류 발생 시 정보를 제공하는 것을 주요 목적으로 설명합니다.
- **시스템 내부 데이터 유효성 검증의 목적:** 코드베이스가 커짐에 따라 개발 편의성을 높이는 것을 목표로 함을 언급합니다.


## 부차 화제
- OOP와 DOP의 비교: OOP에서의 데이터 유효성 검증과 DOP에서의 데이터 유효성 검증의 차이점. OOP에서는 클래스 인스턴스화 시 멤버 필드의 이름과 유형이 보장되지만, DOP에서는 데이터 유효성 검증이 선택 사항이라는 점.
- 웹 서버 아키텍처 및 시스템 경계: 웹 서버의 주요 구성 요소(클라이언트, 웹 서비스, 데이터베이스)와 데이터 교환 지점 (경계)에 대한 이해. 시스템 경계의 중요성.
- 데이터 유효성 검증의 종류: 시스템 경계에서의 데이터 유효성 검증과 내부에서의 데이터 유효성 검증의 차이점, 목적, 환경.
- 데이터 유효성 검증의 중요성: 시스템 경계에서 데이터 유효성 검증의 우선순위와 중요성.
- 데이터 유효성 검증의 목적: 시스템으로 들어오고 나가는 유효하지 않은 데이터를 방지하고, 유효하지 않은 데이터 발생 시 유용한 오류를 표시하는 것.
- 데이터 유효성 검증의 환경: 경계에서의 데이터 유효성 검증은 프로덕션 환경에서, 내부에서의 데이터 유효성 검증은 개발 환경에서 주로 수행됨.
