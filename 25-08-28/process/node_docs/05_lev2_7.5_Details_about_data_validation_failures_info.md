## 핵심 내용
데이터 유효성 검사 실패 시, 오류의 구체적인 이유를 알 수 있으며, 누락된 필드나 잘못된 데이터 유형에 대한 정보를 얻을 수 있습니다. Ajv와 같은 라이브러리는 오류를 배열 형태로 반환하며, `errorsText` 함수를 사용하여 사람이 읽기 쉬운 형태로 변환할 수 있습니다. 여러 오류를 감지하려면 `allErrors: true` 옵션을 사용하여 검사해야 합니다.


## 상세 핵심 내용
### 데이터 유효성 검사 실패 정보 상세 내용

이 절에서는 JSON Schema를 사용한 데이터 유효성 검사 실패 시 얻을 수 있는 상세 정보에 대해 설명합니다. 이전까지는 데이터 유효성 검사가 성공 또는 실패(binary)로만 처리되었지만, 실제로는 실패 이유에 대한 자세한 정보를 얻을 수 있습니다.

#### 1. 실패 정보의 필요성

*   유효하지 않은 데이터의 구체적인 문제점을 파악하여 수정하는 데 도움을 줍니다.
*   예: 필수 필드 누락 시 누락된 필드의 이름을, 데이터 타입이 예상과 다를 경우 해당 타입 정보를 제공합니다.

#### 2. 실패 정보 접근 방법

*   **다양한 라이브러리:** 각 데이터 유효성 검사 라이브러리는 자체적인 방식으로 실패 정보를 제공합니다.
*   **Ajv (JavaScript 예시):** Ajv는 유효성 검사 실패 정보를 validator instance 내의 `errors` 배열에 저장합니다.

#### 3. Ajv의 `errors` 배열 구조

*   **배열:** 여러 개의 실패가 발생할 수 있으므로 오류 정보는 배열 형태로 저장됩니다.
*   **개별 오류 객체:** 각 배열 요소는 다음과 같은 정보를 포함하는 객체입니다.
    *   `instancePath`: 오류가 발생한 데이터 내의 위치 (예: `"data/fields/0"`).
    *   `schemaPath`: 오류를 발생시킨 스키마의 위치 (예: `"#required"`).
    *   `keyword`: 오류의 종류 (예: `"required"`, `"type"`).
    *   `params`: 오류와 관련된 추가 정보 (예: 누락된 필드 이름: `"missingProperty": "title"`).
    *   `message`: 사람이 읽을 수 있는 오류 메시지.

#### 4. 오류 정보의 가독성 향상

*   **`errorsText` 유틸리티 함수:** Ajv는 `errors` 배열을 사람이 읽기 쉬운 형식의 문자열로 변환하는 `errorsText` 함수를 제공합니다.

#### 5. 여러 실패 정보 수집

*   **기본 설정:** Ajv는 기본적으로 첫 번째 유효성 검사 실패만 감지합니다.
*   **`allErrors: true` 옵션:** `Ajv` 생성자에 `allErrors: true` 옵션을 전달하면 모든 유효성 검사 실패를 수집할 수 있습니다.
*   **성능 고려:** 첫 번째 오류 발생 시 검사를 중단하는 것은 성능 향상을 위한 전략일 수 있습니다.

#### 6. 예시: 다중 실패 상황

*   스키마 정의, 유효하지 않은 데이터, `allErrors: true` 옵션을 사용한 `Ajv` 인스턴스 생성 및 오류 처리 과정을 보여주는 코드 예시가 제공됩니다.
*   결과로 여러 개의 오류 메시지가 출력되어, 다수의 유효성 검사 실패를 확인할 수 있음을 보여줍니다.

## 7.5 Details about data validation failures - 추가 정보 및 상세 내용 정리

이 챕터는 JSON Schema validation 실패 시, 단순한 "유효하지 않음" 이상의 정보를 얻을 수 있음을 보여줍니다. 특히 Ajv 라이브러리를 예시로 사용하여, 실패 이유에 대한 상세 정보를 어떻게 접근하고 활용하는지를 설명합니다.

**1. 데이터 유효성 검사 실패의 상세 정보 접근:**

*   **일반적인 상황:** 유효성 검사 실패 시, 실패 이유에 대한 세부 정보를 얻을 수 있습니다. 예를 들어, 필수 필드가 누락되었는지, 데이터 타입이 예상과 다른지 등을 확인할 수 있습니다.
*   **Ajv의 오류 정보:** Ajv는 validation 실패 시 오류 정보를 배열 형태로 제공합니다 (예: `ajv.errors`).
    *   각 오류는 `instancePath`, `schemaPath`, `keyword`, `params`, `message` 등의 속성을 포함하는 객체입니다.
    *   `instancePath`: 오류가 발생한 데이터 내의 위치 (예: `data/fields/0`).
    *   `schemaPath`: 오류가 발생한 스키마 내의 위치.
    *   `keyword`: 발생한 오류의 키워드 (예: `required`, `type`).
    *   `params`: 오류에 대한 추가 정보 (예: `missingProperty`).
    *   `message`: 오류에 대한 설명.

**2. Ajv 오류 정보의 활용:**

*   **`errorsText` 유틸리티 함수:** Ajv는 오류 배열을 사람이 읽기 쉬운 형식으로 변환해주는 `errorsText` 함수를 제공합니다.
*   **여러 오류 처리:** Ajv는 기본적으로 첫 번째 오류만 감지합니다. `allErrors: true` 옵션을 Ajv 생성자에 전달하면 모든 오류를 감지할 수 있습니다. 이는 여러 개의 유효성 검사 실패를 한 번에 처리해야 할 때 유용합니다.

**3. 예시 및 구현 상세:**

*   **누락된 필드 오류:**
    *   스키마에서 `title` 필드가 필수 (`required: ["title", "fields"]`)로 지정되었지만, 입력 데이터에 `title`이 없을 경우, `ajv.errors` 배열은 다음 형태의 오류 객체를 포함합니다.
        ```json
        [
          {
            "instancePath": "",
            "schemaPath": "#/required",
            "keyword": "required",
            "params": {
              "missingProperty": "title"
            },
            "message": "must have required property 'title'"
          }
        ]
        ```
    *   `ajv.errorsText(ajv.errors)`를 사용하면 "data must have required property 'title'"와 같은 인간 친화적인 오류 메시지를 얻을 수 있습니다.
*   **데이터 타입 오류:**
    *   `fields` 배열의 요소가 문자열이 아닌 경우 (예: 숫자), `ajv.errors` 배열은 각 오류에 대한 객체를 포함합니다.
    *   `ajv.errorsText(ajv.errors)`는 "data/fields/0 must be string", "data/fields/1 must be string"과 같은 메시지를 반환합니다.
*   **`allErrors` 옵션 사용 예시:**
    ```javascript
    var ajv = new Ajv({allErrors: true});
    // ... 스키마 및 잘못된 데이터 정의 ...
    ajv.validate(searchBooksRequestSchema, invalidSearchBooksRequest);
    console.log(ajv.errorsText(ajv.errors)); // 여러 오류 메시지 출력
    ```

**4. 추가 정보 (새로운 내용):**

*   **오류 정보의 활용:** 오류 정보 (특히 `instancePath`와 `params`)를 활용하여, 프론트엔드에서 사용자에게 더 구체적인 에러 메시지를 제공하거나, 백엔드에서 오류를 처리하는 로직을 세분화할 수 있습니다.
*   **라이브러리별 차이:** 각 JSON Schema validation 라이브러리 (예: Ajv, tv4 등)는 오류 정보를 제공하는 방식이 다를 수 있습니다. 특정 라이브러리에 의존하지 않고, 오류 정보의 구조를 파악하여, 유연하게 대응할 수 있도록 설계하는 것이 중요합니다. (이 챕터에서는 Ajv에 초점을 맞추고 있지만, 다른 라이브러리의 문서도 참조하여 학습할 필요가 있습니다.)
*   **실제 사용 시나리오:** 웹 서버의 API 요청/응답 유효성 검사, 데이터베이스 입력 유효성 검사, 설정 파일 유효성 검사 등 다양한 상황에서 활용될 수 있습니다.

**5. Cheat Sheet (예시):**

*   제공된 JSON Schema cheat sheet는 다음과 같은 기본적인 JSON Schema 구조를 보여줍니다.
    *   `type`: 데이터의 기본 유형 (예: "array", "object", "string", "number", "boolean").
    *   `properties`: 객체의 속성 정의.
    *   `required`: 필수 속성 목록.
    *   `enum`: 열거형 값.
    *   `additionalProperties`: 추가 속성 허용 여부. (false일 경우, 스키마에 명시된 속성만 허용)

**6. 유효한 데이터 예시:**

*   제공된 유효한 데이터 예시는 JSON Schema를 기반으로 작성되었으며, 각 필드의 유효성을 보여줍니다. (예: `"myNumber": 42`, `"myString": "Hello"`, `"myEnum": "myVal"`)

**결론:**

이 챕터는 JSON Schema validation 실패 시, 단순한 "유효하지 않음" 이상의 상세 정보를 얻어, 더 효과적으로 오류를 처리하고 사용자 경험을 향상시킬 수 있음을 보여줍니다. Ajv 라이브러리를 예시로 들어, 구체적인 구현 방법과 오류 정보 활용법을 설명합니다. 또한, JSON Schema cheat sheet와 유효한 데이터 예시를 통해 JSON Schema의 기본 구조와 유효성 검사 개념을 보강합니다.
