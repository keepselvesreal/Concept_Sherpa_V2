## 상세 핵심 내용

## 상세 핵심 내용
OOP에서는 객체의 가변성 때문에 멀티 스레드 환경에서 객체의 상태가 예기치 않게 변경될 수 있어 코드의 예측 가능성이 떨어진다. 싱글 스레드 환경에서도 비동기 코드를 통해 데이터가 수정될 때 동일한 문제가 발생할 수 있다. 뮤텍스와 같은 동시성 안전 메커니즘을 사용하여 이러한 문제를 해결할 수 있지만, 성능 저하 및 데드락 위험이 따른다. DOP는 데이터 불변성을 통해 이러한 문제를 해결하고 개발자가 애플리케이션의 핵심 로직에 집중할 수 있도록 돕는다. DOP는 개발자의 인지 부담을 줄여주고 시스템을 더 간단하게 만들어준다.

## 상세 정보

## 상세 정보
*   **예측 불가능한 코드 동작**: OOP에서 가변 객체 멤버에 접근할 때 발생하는 문제점을 설명하고 데이터 변경으로 인한 예기치 않은 결과를 강조한다.
*   **멀티 스레드 환경**: 멀티 스레드 환경에서 context switch로 인해 객체의 상태가 변경되어 예측 불가능한 결과가 발생할 수 있음을 지적한다.
*   **싱글 스레드 환경**: 싱글 스레드 환경에서도 비동기 코드를 통해 데이터가 수정될 때 예측 불가능성이 발생할 수 있음을 설명한다.
*   **해결 방법**: OOP에서는 뮤텍스와 같은 동시성 안전 메커니즘을 사용할 수 있지만, 성능 저하 및 데드락 위험이 따른다는 점을 언급한다.
*   **DOP (Data-Oriented Programming)**: 데이터 불변성을 통해 가변 객체로 인한 문제를 해결하고 개발자에게 안정감을 제공하는 DOP의 장점을 강조한다.
*   **데이터 불변성**: DOP는 모든 데이터를 immutable 값으로 취급하여 예측 가능성을 높이고 개발자의 인지 부담을 줄인다.
*   **코드 예시**: mutable 데이터와 immutable 데이터의 차이점을 보여주는 코드 스니펫을 제공하여 데이터 불변성의 중요성을 강조한다.

Complexity of object-oriented programming
This unpredictable behavior of the second listing is one of the annoying conse-
quences of OOP. Unlike primitive types, which are usually immutable, object mem-
bers are mutable. One way to solve this problem in OOP is to protect sensitive code
with concurrency safety mechanisms like mutexes, but that introduces issues like a
performance hit and a risk of deadlocks.
 We will see later in the book that DOP treats every piece of data in the same way:
both primitive types and collection types are immutable values. This value treatment for
all citizens brings serenity to DOP developers' minds, and more brain cells are avail-
able to handle the interesting pieces of the applications they build.
TIP
Data immutability brings serenity to DOP developers' minds.
