## 핵심 내용
이 문서는 객체 지향 프로그래밍(OOP) 설계의 복잡성을 설명하며, 도서관 관리 시스템의 UML 클래스 다이어그램을 예시로 들어 클래스 간의 관계(composition, association, inheritance, usage)를 설명한다. Theo와 Dave의 대화를 통해 UML 다이어그램의 각 요소를 이해하고 시스템 설계를 구현하는 과정을 보여준다.

## 상세 핵심 내용
Theo는 새로운 프로젝트를 위해 도서관 관리 시스템의 UML 클래스 다이어그램을 설계하고, 주니어 개발자 Dave에게 이를 설명한다. 이 설계는 Library, Member, Librarian, User, Catalog, Book, BookItem, Author, BookLending 클래스를 포함하며, 각 클래스 간의 관계는 composition, association, inheritance, usage 네 가지 유형으로 표현된다. Theo는 UML 다이어그램을 통해 코딩 시간을 절약할 수 있다고 믿으며, Dave는 UML 다이어그램에 대한 이해를 높인다. 이 문서는 OOP 설계의 중요성과 UML 다이어그램을 활용한 시스템 설계 방법을 강조한다.

## 상세 정보
이 문서는 소프트웨어 컨설팅 회사 Albatross의 시니어 기술 리드 Theo가 새로운 고객을 위해 도서관 관리 시스템의 UML 클래스 다이어그램을 설계하는 과정을 설명한다. Theo는 주니어 개발자 Dave에게 다이어그램을 보여주며 UML의 기본 개념과 클래스 간의 관계를 설명한다.

*   **클래스 다이어그램 구성 요소:** Library, Book, BookItem, BookLending, Member, Librarian, User, Catalog, Author 클래스들이 존재한다.
*   **클래스 간의 관계:**
    *   **Composition:** Library와 Catalog (1:1), Library와 Members (1:N)
    *   **Association:** Book과 Author (N:N)
    *   **Inheritance:** Librarian과 User, Member와 User
    *   **Usage:** Librarian이 Member의 메서드를 사용하는 경우 등
*   **각 클래스의 역할:**
    *   **Library:** 시스템의 루트 클래스, 다른 객체에 동작을 위임.
    *   **User:** id, email, password를 가지며, login 기능을 제공.
    *   **Member:** User를 상속받아 책을 빌리고 반납하는 기능 제공. BookLending 객체를 소유.
    *   **Librarian:** User를 상속받아 회원을 관리하고 도서 아이템을 추가하는 기능 제공.
    *   **Catalog:** 도서 검색 및 도서 아이템 추가 기능 제공. Book 객체를 소유.
    *   **Book:** id, title을 가지며, Author와 BookItem 객체와 연관.
    *   **BookItem:** 책의 사본을 나타내며, BookLending 객체를 소유.
*   **UML 다이어그램의 중요성:** Theo는 상세한 설계가 코딩 시간을 절약해 준다고 믿는다.
