이 문서는 객체 지향 프로그래밍(OOP)에서 가변 객체로 인해 발생하는 예측 불가능한 코드 동작 문제를 설명하고, 데이터 불변성을 강조하는 데이터 중심 프로그래밍(DOP)이 이러한 문제를 해결하고 개발자에게 안정적인 개발 환경을 제공하는 대안임을 제시한다.

## 상세 핵심 내용

## 상세 핵심 내용
OOP에서 객체 멤버는 mutable하기 때문에, 멀티스레드 환경에서는 두 번의 접근 사이에 객체의 상태가 변경될 수 있어 예측 불가능한 결과가 발생할 수 있다. 싱글 스레드 환경에서도 비동기 코드에 의해 데이터가 변경될 경우 동일한 문제가 발생할 수 있다. 이러한 문제는 mutex와 같은 동시성 안전 메커니즘으로 해결할 수 있지만, 성능 저하나 데드락 위험과 같은 새로운 문제를 야기한다. DOP는 모든 데이터를 immutable하게 취급하여 이러한 문제점을 해결하고 개발자에게 안정적인 개발 환경을 제공한다. 데이터 불변성은 코드의 예측 가능성을 높이고, 개발자가 애플리케이션의 핵심 로직에 집중할 수 있도록 돕는다. 객체의 가변성은 OOP의 주요 복잡성 원인 중 하나이며, DOP는 이를 효과적으로 완화할 수 있다.

## 상세 정보

## 상세 정보
*   **예측 불가능한 코드 동작:** OOP에서 mutable한 객체 멤버에 접근할 때 발생하는 문제점.
*   **멀티 스레드 환경:** 객체 멤버의 상태가 변경될 수 있어 예측 불가능성이 증가한다.
*   **싱글 스레드 환경:** 비동기 코드에 의한 데이터 변경으로 예측 불가능성이 발생할 수 있다.
*   **해결 방법:**
*   Mutex와 같은 동시성 안전 메커니즘 사용 (단점: 성능 저하, 데드락 위험)
*   DOP에서 데이터 불변성(immutability) 적용
*   **데이터 불변성:** DOP에서 모든 데이터를 immutable하게 취급하여 예측 불가능성을 제거하고 개발자에게 안정감을 제공한다.
*   **코드 예시:** Boolean 값을 두 번 접근하는 경우(listing 1.1)와 객체 멤버를 두 번 접근하는 경우(listing 1.2)를 비교하여 mutable 데이터의 위험성을 설명한다.
*   **결론:** mutable한 데이터는 예측 불가능한 코드 동작을 야기하며, 데이터 불변성은 이러한 문제를 해결한다.

Complexity of object-oriented programming
This unpredictable behavior of the second listing is one of the annoying conse-
quences of OOP. Unlike primitive types, which are usually immutable, object mem-
bers are mutable. One way to solve this problem in OOP is to protect sensitive code
with concurrency safety mechanisms like mutexes, but that introduces issues like a
performance hit and a risk of deadlocks.
 We will see later in the book that DOP treats every piece of data in the same way:
both primitive types and collection types are immutable values. This value treatment for
all citizens brings serenity to DOP developers' minds, and more brain cells are avail-
able to handle the interesting pieces of the applications they build.
TIP
Data immutability brings serenity to DOP developers' minds.
